# 実身・仮身モデル設計書（Issue #46）

状態: **設計と V1a（登録簿）・V1b（実身の操作）・V2（続柄）・V3（接続と虚身）・V4a（アプリケーション管理）・V4b-0（登録簿の共有）・V4b-1（起動と実行プロトコル）・V4b-2（実行機能付箋の固有データ）・V5（漢殻の命令）の実装**。BTRON3 の実身／仮身マネージャ（OS 仕様編 第3章 3.8）を、現在の録層・篇藏・漢殻の上にどう載せるかを決める。
原文: <https://www.chokanji.com/developer/doc/btron3/os_spec/shell/omgr.html>（3.8.1〜3.8.6、全 60 関数）。関連: [compat/btron3-file-design.md](compat/btron3-file-design.md)、[design-pianfs.md](design-pianfs.md)、[compat/btron3-api-inventory.md](compat/btron3-api-inventory.md)。

## 1. 原文の要点

| 概念 | 原文 |
|---|---|
| 実身 | 意味のあるデータの集まり。**実際のファイルに一対一に対応する**。常に仮身を通して参照され、直接は表示されない |
| 仮身 | 実身を参照するタグ。1 つの実身を 1 つ以上の仮身が参照できる。**内部的にはファイル管理の「リンク」で表現**する |
| 仮身リンク `VLINK` | `LINK`（52 B）と同じ配置で、欄の意味だけが違う: `fs_name[20]`・`f_id`（対象ファイル）と、仮身固有の `attr`（属性・状態）・`rel`（続柄の索引）・`appl[3]`（既定のアプリ ID） |
| 仮身セグメント `VOBJSEG` | `VLINK` と対になる表示情報（表示領域・開いた高さ・文字サイズ・色 4 色・固有データ）。文書（TAD）の中に埋め込む |
| 分類 | 通常仮身・内部仮身（開いた仮身の中の静的表示）・隠蔽仮身 |
| 間接参照 | 仮身の所属元のデバイスと別のデバイスの実身を指す仮身（リンクファイルを参照）。参照は保証されない |
| 虚身 | 切断状態のデバイスの実身を指す間接参照仮身。開こうとすると接続を求める |
| 続柄 | 仮身に付ける名前（16 文字）。**ファイルシステム単位**で「続柄管理ファイル」（ルート直下）に `VOBJREL{name[16], col}` の表で持ち、仮身には索引だけを入れる。索引 0 は名なし |
| 実身のタイプ | ファイルのアプリケーションタイプ（`atype`）。上位バイトは実身／仮身マネージャが使う属性、下位はピクトグラム番号 |
| マネージャの位置づけ | **外殻（アプリ層）**。アプリは `o*` 関数で仮身を登録・表示・操作し、アプリの登録・起動もここを通る |
| 仮身 ID `vid` | 仮身を**ウィンドウ／パネル上のパーツとして登録**したときに割り当てる正の整数。関数の大半は `vid` を取る |

## 2. 現状の部品との対応

実身・仮身の土台は、録層（BTRON3 の 1.6 ファイル管理）にすでにある。

| BTRON3 の概念 | 今ある実装 | 状態 |
|---|---|---|
| 実身（ファイル） | 録層のファイル（FS 番号＋ファイル ID、見出し 256 B、本体は連続した頁）。`cre_fil`・`opn_fil`・`del_fil`・`fil_sts` ほか | 済（B1〜B5）。`atype`（見出し `+80`）も保持 |
| 仮身リンク `VLINK` | 録層の `LINK`（52 B。`fs_name[20]`・`f_id`・`atr1..5`）。`cre_lnk`・`get_lnk`・`fnd_lnk`・`lnk_sts`・`syn_lnk` | 済。`attr`＝`atr1`、`rel`＝`atr2`、`appl[3]`＝`atr3..5` に対応づけられる |
| 間接参照（リンクファイル） | リンクファイル（種別 0）。`cre_lnk`・`gen_fil` | 済（M3） |
| 切断／接続・虚身 | `att_fls`・`det_fls`・`chg_fls`・`fls_sts`（FS の接続状態）。SYS は接続しない | 済（1.6 の接続管理）。仮身側の「虚身状態」の判定は未 |
| 参照数 | 見出し `+72`（同一 FS の固定リンクの数） | 済 |
| 続柄管理ファイル | 無い | 未 |
| 仮身セグメント・TAD | 無い（TAD は未着手） | 未 |
| 仮身の登録（`vid`）・ウィンドウ／パネル | 無い（表示装置が無い） | 未 |
| アプリ登録・起動（`appl` ID、実行機能付箋） | `cre_prc` が像ファイルの `LINK` から起動する。アプリ ID の表は無い | 一部 |

つまり**データモデルは録層で足りている**。足りないのは、その上の (a) 仮身の登録簿（`vid`）、(b) 続柄、(c) アプリ登録、(d) 表示（F7 の領域）である。

## 4. 方針

1. **実身＝録層のファイル、仮身＝録層の `LINK`**。新しい保存形式は作らない。`VLINK` は `LINK` の欄に `attr`・`rel`・`appl` を入れる規約を決めるだけ。
2. **識別子は BTRON3 のまま（FS 名＋ファイル ID）**。Issue #46 の「安定した識別子」は、これで満たす（`f_id` は 16 ビットで、録層は「次の ID」から空いている番号を探して割り当てる。削除したファイルの ID は一周するまで再利用されず、次の ID は永続化でも戻る。ただし回り込めば再利用される＝完全に再利用されない保証ではない）。篇ID との対応は、録層の本文を篇（型 `録`）へ移す段階（roadmap F5）で表を作る。ここでは決めない。
3. **実身／仮身マネージャは EL0 のライブラリとして作る**（`user/btron/omgr.mkn`。原文でも外殻＝アプリ層）。核に追加する漢令は要らない見込み（既存の 1.6 の漢令の上に載せる）。登録簿（`vid` → `VLINK`・`VOBJSEG`・状態）は行程内の表。
4. **実身と仮身の操作を分ける**（Issue #46 の原則どおり）: 仮身の複製・移動・削除は `LINK` の操作（実身は変わらない）、実身の複製（`ocre_obj` の `copy`）・新版（`onew_obj`）・削除（`odel_obj`）はファイルの操作。`odel_obj` は「参照数 0 かつ登録済みの仮身が無い」ときだけ削除し、中にあるリンクが指す先もネストして削除する（原文どおり）。
5. **漢殻の操作は後段**。命令名と構文は言語仕様と整合してから決める（Issue #46 の「仮案」のまま）。第一歩は、ライブラリの関数を呼ぶ外部命令（試験用）で挙動を固める。

## 5. 決定事項（V1a の実装で決めたもの）

1. **擬似ウィンドウは作らない（§5 の初案を変更）**。原文は `oreg_vob` の `wid < 0` を「−（描画環境 ID）」とし、描画環境が存在しなくても登録はでき、表示のときに `EG_GID` になる、としている。表示装置が無い間は、**`wid < 0` かつ `V_NODISP` で登録**し、`wid >= 0`（ウィンドウ）は `EX_WID` にする。`odel_vob(vid < 0)`・`ochg_sts(vid < 0)` は原文どおり `wid < 0` の登録を対象にしない（常に 0）。
2. **`EX_*` の値**: 原文のこの章に定義が無い。`ER_*` と取り違えないよう別の eclass（0xFFFE）の通し番号にする（`user/btron/er.mkn` の「選択の記録」）。原文は核のエラーがそのまま戻りうるとし、`oreg_vob` は `ER_NOFS` も返すので、値の重なりは許されない。`EG_GID` は表示の段階で決める。
3. **仮身の属性ビット**: 原文の図 123（画像）と図 124 を読み、`V_*` の定義（3.8.4）と突き合わせて確認した（`attr` は 16 ビット: bit0 `V_NONAME`〜bit9 `V_NOEXPND`、bit8 `V_OPENED`、bit11 `V_LINKFL`、bit12 `V_DETACH`、bit13 `V_INPROC`、bit14 `V_AUTEXE`、bit15 `V_HIDDEN`。`atype` は bit15 実行可能ファイル・bit14 デバイス実身・bit13 取外し可能デバイス実身、下位がピクトグラム番号）。登録のとき `V_LINKFL`・`V_DETACH`・`V_INPROC` は意味を持たないので消し、`ochg_sts` が返す値では `V_HIDDEN` を常に 0 にする。
4. **`VOBJSEG` の配置**: C の構造体のとおり自然な境界に置いた **32 B**（`RECT` 8 B・`H` 2 B・`CHSIZE` 2 B・`COLOR` 4 B × 4・`UH dlen` 2 B・余白 2 B）。固有データは +32 から。`COLOR` を 4 B とするのは仮定で、共有データ編 `data_type.html` で要確認。固有データは **64 B まで**で、超えると `EX_NOSPC`（登録簿の項の大きさによる制限）。
5. **登録簿**: 行程ごとの表を民の窓のデータ域の固定番地 `0x407E0000`〜に置く（192 B × 64 項。同じ窓の試験・核の用途と重ならない番地。頁はデマンドページングでゼロ埋め）。`vid` は 1 から単調増加で再利用しない。機械漢文のユーザー像は変更可能な大域変数を持てないので、固定番地を使う。
6. **登録簿の範囲**: まず行程内だけ。別行程が同じ実身を削除しようとしたときの `odel_obj` の判定（登録済みの仮身が無いこと）は、共有が要る段階（サービス行程化）で扱う。

### V1b で決めたこと

- **`ocre_obj` は `gen_fil` を `F_FLOAT` で呼ぶ**: 親のリンクを持たない参照数 0 のファイル（実身）ができる。仮身（リンクレコード）が格納されて初めて参照数が増える。`del_fil` の親は NULL（参照数 0 のときだけ消せる）。
- **生成先の FS**: 所属デバイスは持たないので、作業ファイル（`TC_FOWN`）の FS、未定義なら仮身の指す FS。`nvid` を渡すと新しい実身の仮身（属性 0、`wid` と `disp` は元の仮身と同じ）を登録する。
- **`copy ≠ 0`**: 全レコードをレコードの型・サブタイプごと複写する（リンクレコードも LINK のまま。参照数は増える）。1 レコードは 4096 B まで（超えると `EX_NOSPC`）。
- **`odel_obj`**: 登録簿に仮身がある・参照数 > 0 のものは消さず 0 を返す。消せたら含まれるリンクの先を入れ子に（深さ 3 まで、1 つの実身あたりリンク 16 個まで）同じ条件で消す。戻り値は消した数。`mode` のエラーパネルは出さない。
- **`oopn_obj`**: パスワードが違うとき、原文は入力パネルだが、パネルは出せないので `EX_PWD`。
- **`ochg_nam`**: 名前が `NULL`（変更パネル）は `EX_PAR`。同じ実身を指す他の仮身への仮身要求イベントとデバイス仮身の改名は未対応。
- **`oupd_fil`**: 実行メニュー・小物メニューが無いので、`vid`・`lnk` の検査だけ行って 0。

### V2 で決めたこと

- **続柄管理ファイル**: 原文はファイルの名前とレコードの形を規定しない（「ルート直下」「`VOBJREL` の表」「索引 0 は名なし」とだけ書く）。実装依存として、FS のルート直下の通常ファイル「続柄」（TC 2 文字）に、`VOBJREL`（名前 32 B ＋ 色 4 B = 36 B）を 1 レコードずつ、レコード番号＝索引で並べる。索引 0（全て 0）は最初に作る。追加だけで消さない。索引は 256 個まで（超えると `EX_LIMIT`）。
- 仮身の続柄は、**参照する実身（間接参照ならリンクファイル）の FS**の表を引く（原文）。
- `ochg_rel`: 索引が無ければ `EX_PAR`、`index < 0`（続柄変更パネル）は出せないので `EX_PAR`。
- `ocnv_vob`: 同じ FS なら 0 を返し何もしない。別の FS なら、元の FS に**リンクファイルを `F_FLOAT` で作り**（参照先の名前・生成日時・アプリタイプは `fil_sts` から。**参照先の FS が接続されている必要がある**＝SYS なら `att_fls` で接続してから）、仮身をそのリンクファイルを指すものに置き換え、`V_LINKFL` を立てる。続柄は、元の FS の表から名前を引いて新しい FS の表へ登録し、索引を付け替える（表が読めなければ 0）。この続柄の付け替えは、書き込める FS が RAM だけなので、FS をまたいだ端から端までの試験はしていない（`続柄登録`・`続柄取得` は単体で試験した）。
- `odel_obj` はリンクファイルを `lnk_sts` の参照数で判定し、リンクファイルそのものを消す（`fil_sts` は参照先を引くので使えない）。

### V3 で決めたこと

- **`o*` の接続・切断は登録簿の虚身状態を更新する**: `oatt_fls`・`oatt_vob` で接続すると、その FS の登録済みの仮身の `V_DETACH` を外し、`odet_fls`・`odet_vob` で切断すると立てる（原文: アプリは `att_fls`・`det_fls` でなく `o*` を使う。カーネルを直接呼ぶと登録簿は更新されない）。
- **`oreg_vob` の虚身**: 仮身の FS が接続されていなければ、同じ FS を指す虚身が既に登録されている場合だけ虚身（`V_DETACH`）として登録し、無ければ `ER_NOFS`（原文の接続パネルは出せない）。以前の「FS の接続の検査は V3」を実装した。
- **`oatt_vob` の接続先**: FS 名から装置を引く表が無いので、組み込みの FS だけ（SYS = 装置 `rom`・接続名 `SYS`、RAM = 装置 `mem`・接続名 `RAM`）。ほかは `ER_NOFS`。
- **`odet_vob`**: `vid > 0` は `vid` の FS、`vid <= 0` は `dev` の装置（空文字列はシステムデバイス = FS 名が SYS の接続）。切断済みなら 0、切断したら 1 で、`dev` が NULL でなければ論理デバイス名（TC 8 文字 + 終端）を戻す。
- **`ofat_fls`・`ofdt_fls`** は他のシステムコール実行中でも待たない点だけが違うが、行程内のライブラリなので待つものが無く、`oatt_fls`・`odet_fls` と同じ処理にした。
- 仮身要求イベント（虚身移行・解除）、小物メニュー・検索対象 FS の更新、接続・切断のパネルは未対応。

### V5（漢殻の命令）で決めたこと

- **外部命令として実装し、`kernel/kernel.mkn` の殻には手を入れない**（組み込み命令は増やさない。殻の組み込みとの取り違えと、`def_exc` を進めている作業との衝突を避ける）。1 つの漢像 `user/obj.mkn` を `実作`・`仮置`・`実削`・`実目`・`実名` の 5 つの名前で登録し、`argv[0]` で分ける。
- **操作文脈は RAM のルート**（作業ファイルは起動した行程に引き継がれないので使わない）。
- `実作 名`: `ocre_obj` で実身を作り、文脈のルートに仮身（リンクレコード）を置く（参照数 1。以後 `RAM/名` のパスで引け、同名は `名#1`）。`仮置 名 先`: 実身 `名` の仮身を実身 `先` の中に置く（参照数が増える）。`実削 名`: 文脈から `名` の仮身を 1 つ外し、`odel_obj` で実身を消す（他の仮身が参照していれば実身は残り、消した数は 0。仮身の削除と実身の削除を分ける）。`実目`: 文脈のファイルを `ID`・参照数・名前で一覧する。`実名 旧 新`: `ochg_nam`。
- **名前は ASCII のみ（20 文字まで、`/`・`#` を含まない）**。ファイル名の TC は **JIS X 0208 の 2 バイト符号**（`tools/gen-images.sh` は EUC-JP から 0x80 を引く）で、UTF-8 の引数を変える表を漢像に持たせていない。日本語の名前は、変換表（約 7000 字）の置き場を決めてから対応する。続柄管理ファイルの名前「続柄」も、これに合わせて JIS の符号（0x4233・0x4A41）にした。
- 出力は 1 行ごとに固定の形（`実作 完 ID=… 参照=…`、`仮置 完 参照=…`、`実削 完 外=… 消=…`、`実目 ID=… 参照=… 名=…`、`実名 完=…`、失敗は `実誤 命令 番号`）。終了コードは常に 0（漢殻が失敗を `殻碼` として出さないため）。
- 像の数が 18 から 24 に増え（V4b-1 の `objapp` を含む）、T1 の `時元試` と T3 の `時` を加えて現在は 26。**像の数は永続化の互換性の照合に使う**ので、これ以前の `同` の保存（`make run` のディスク）は読まれず、初期化した状態で起動する。

### V4a で決めたこと

- **システム全体の状態は RAM のルート直下のファイル `omgrst` に持つ**: 実行環境ファイルのスタック・検索対象 FS・小物入れは「システム全体で 1 つ」（原文）なので、行程の間で共有するためファイルにした。3 つの固定長レコード（0 = 実行環境: 個数 + 8 × {LINK, ウィンドウ ID}、1 = 検索対象: 個数 + 8 × LINK、2 = 小物入れ）を書き換える。永続化（`同`）されると再起動後も残る。
- **アプリケーション登録ファイルは各 FS のルート直下のファイル `appreg`**: 1 登録 = 1 レコード（型 1）: LINK（`atr3`〜`atr5` = アプリケーション ID）+ データタイプ名 TC[16] = 84 B。
- **レコードタイプの数値は原文に無い**（3.8.4 にも定義が無い）ので実装依存として、実行プログラムレコード = 29、機能付箋 = 30、実行機能付箋 = 31 とした（レコードタイプは 0〜31 の 5 ビット。0 はリンクレコード）。実行可能ファイルは `atype` の最上位ビット（図 124）。`FUSENSEG` は C の自然な境界で 96 B（固有データは +96 から）。
- `oreg_apg`: 実行可能でない・先頭が実行プログラムレコードでない・機能付箋が無い・データタイプ ID が (0, 0) は `EX_PAR`、同じファイルの再登録は `EX_EXS`（新しい `EX_*`）。`odel_apg`: 登録が無ければ `EX_NOEXS`（アプリ自体は消さない）。
- `ofnd_apg`: `fs_name` 指定ならその FS だけ（未接続は `ER_NOFS`）、空なら実行環境の FS → 検索対象 FS（未接続は除く）。複数見つかれば全部返し、選択パネルは出さない。
- `ochg_env`: 8 段まで（9 つ目は `EX_LIMIT`）。同じファイルを設定し直すと古い定義が消える。`lnk = NULL` で直前に戻る。`oset_tmf`: 小物入れを記録するだけ（小物メニューは無い）。
- 未対応: 同じアプリを異なるものと見分ける判定（総バイト数・レコード数・ファイル名）、アプリ選択パネル、ウィンドウ削除に連動した実行環境の自動切り替え。

## V4b 設計（起動と実行プロトコル）

状態: **V4b-0（登録簿の共有）・V4b-1（起動と実行プロトコル）・V4b-2（`oget_fsn`・`oput_fsn`）は実装済み**。決定: 登録簿は案 B（共有塊 + グローバル名 + セマフォ）、アプリの実行プログラムレコードの本体は「起動する漢像の名前」、試験用アプリの漢像を 1 つ足す。

対象: `oexe_apg`（起動）、`osta_prc`・`oend_prc`・`oend_req`（起動されたアプリの通知）、`oget_fsn`・`oput_fsn`（実行機能付箋の固有データ）。`oreq_prc`・`orsp_prc`（仮身要求イベント）、`oput_dat`（貼り込み）、開いた仮身の表示起動・TAD 作成起動・付箋の起動・小物アプリは、ウィンドウ・描画環境・トレーが要るので V6。

### 問題: 仮身 ID が行程の外で解決できない

原文では、アプリは起動メッセージ `M_EXECREQ` の中の仮身 ID（`vid`）を `osta_prc(vid, wid)`・`oget_fsn(vid, …)`・`oend_prc(vid, …)` に渡す。`vid` は起動した側が登録したもの（実身／仮身マネージャが**システム全体**で持つ）で、起動された行程（別の行程）から引ける必要がある。V1a〜V4a の登録簿は**行程ごとの表**（民の窓の固定番地）なので、起動されたアプリは親の `vid` を引けず、`EX_VID` になる。したがって V4b の前提は、**登録簿をシステム全体で共有すること**。

### 案

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 管理行程 | 登録簿を持つ常駐行程を作り、`o*` を要求・応答（ランデブー口 `cal_por`・`acp_por`）にする | 原文の構造（マネージャが 1 つ）に近い。競合が無い | ライブラリの全関数を RPC に書き換える。常駐行程の起動・終了の管理が要る |
| **B. 共有メモリの登録簿（推奨）** | 登録簿を**共有塊**（`Smalloc`）に置き、最初に使った行程がグローバル名（`cre_nam`）で公開、以後は `get_nam` で見つける。競合はセマフォ（`cre_sem`・`wai_sem`・`sig_sem`）で防ぐ | 既存の関数の中身（登録簿の添字の引き方）を置き換えるだけで、挙動は変わらない。専用行程が要らない | EL0 のプリエンプションで競合するのでセマフォが要る。持ち主の行程が終了したときの項の掃除が要る |
| C. ファイル | `omgrst` と同じく RAM のファイルに持つ | 既に使っている手法 | 項の読み書きがレコード単位で遅く、登録簿の操作ごとにファイルを開く |

**推奨は B**。共有塊の領域は窓の頁 248〜255（32 KiB、全行程で同じ仮想アドレス）で、登録簿（64 項 × 192 B + ヘッダ = 約 12 KiB）は収まる。行程ごとの作業領域（`0x407E4000`〜）は今のまま行程ごとに持つ。

B の細部:

1. **公開**: 初回に `cre_nam`（グローバル名）が成功した行程が共有塊を作って初期化する。失敗（既にある）なら `get_nam` で取得する。共有塊は `DELEXIT` なしで作る（行程が終了しても残る）。
2. **競合**: 登録簿の更新はセマフォ 1 つで囲む（グローバル名で見つける）。取得に失敗する（ほかの行程が持ったまま終了した）場合の復旧は、セマフォが排他セマフォ（`TA_...`）として行程の終了で自動的に渡される（`同終了`）ことに頼る。
3. **持ち主と掃除**: 各項に持ち主の行程 ID を持たせ、項を引くとき（`登探`・`登空`）に持ち主が存在しなければ（`prc_sts`）その項を空にする。
4. **処理中状態**: `V_INPROC` は項に持つ。起動した側が `oexe_apg` で立て（または `osta_prc` で）、`oend_prc` で外す。
5. 登録簿の移行（段階 V4b-0）は**挙動を変えない**。既存の `実試` 49 項目と `実作` などの漢殻の試験がそのまま通ることを確認する。

### 起動（`oexe_apg`）

- `vid > 0` で `item` の下位バイトが 0 ならデフォルトアプリ（仮身の `appl` で `ofnd_apg`）、0 でなければ「実行メニューの項目番号」（対象の実身の中の n 番目の**実行機能付箋レコード**（型 31）の `appl`）。`vid <= 0`（小物メニュー）は V6。付箋（`vlnk = NULL`）で `item` が 0 でなければ `EX_PAR`。
- **アプリの実行プログラム**: 現在の核が起動できるのは SYS の像ファイル（`cre_prc` の `LINK` 版）だけなので、アプリのファイルの**実行プログラムレコード（型 29）の本体を、起動する漢像の名前（NUL 終端の ASCII）**と決める。`oexe_apg` はその名前の SYS の像の `LINK` を引き、`cre_prc` に起動メッセージを渡して起動する（`oreg_apg` が登録するアプリは、このレコードを持つ）。これは実装依存の選択で、原文の「標準オブジェクト形式」とは別。
- **起動メッセージ** `M_EXECREQ`（`type = 0x10`、`size`、`self`（アプリのファイルの `LINK`、`atr3`〜`atr5` = アプリ ID）、`lnk`（対象の実身）、`vid`、`pwid`、`info`、`r`、`bgcol`、`mode`）は原文どおりの配置（自然な境界）で、`cre_prc` の `MESSAGE` に載せる。`info` は、デフォルト起動は付箋の固有データへのポインタ、そうでなければ実行機能付箋のレコード番号（`mode` の R ビット）。初期起動は V6。
- 戻り値は起動した行程 ID（既に処理中なら 0）。虚身は `EX_VOBJ`（接続パネルが出せない。`oatt_vob` を先に呼ぶ）、登録が無ければ `EX_NOEXS`、複数あれば最後に登録されたものを起動し選択パネルは出さない。

### 通知と固有データ

- `osta_prc(vid, wid)`: 仮身を処理中にし、`wid` を記録する。`wid <= 0` は `EX_PAR`（小物以外）、付箋は `EX_VOBJ`、無い `vid` は `EX_VID`。
- `oend_prc(vid, dat, update)`: 処理中を外し、`dat`（先頭の UH が長さ）を仮身に付随する固有データとして共有登録簿に保存する。開いた仮身の表示用の描画環境 ID は、表示が無いので常に 0。
- `oend_req(vid, stat)`: 表示起動・貼り込み起動の終了通知。起動が V6 なので、V4b では `vid` と付箋の検査だけ。
- `oget_fsn(vid, fd, dat, size)`・`oput_fsn(vid, fd, dat)`: 処理中でない・虚身は `EX_VOBJ`。対象の実身（`fd` は呼び出し側が開く）の中の、起動の対象になった実行機能付箋レコード（型 31）の固有データ（`FUSENSEG` の `dlen` と +96 以降）を取り出す・更新する。`oexe_apg` が登録簿の項 `+126` に「起動した型 31 のレコード番号 + 1」を残す（0 = 実行機能付箋以外からの起動）。`oput_fsn` は `see_rec`・`wri_rec` でレコード内だけを書き換え、`wri_rec` が更新するファイルの更新日時を `chg_ftm` で元に戻す。

### 試験

試験用のアプリの漢像 `user/obj_app.mkn`（像名 `objapp`。起動メッセージを受け取り、`osta_prc`→固有データの更新→`oend_prc` を行って終わる）を 1 つ足し、**2 つの行程にまたがる**試験にする: 起動側の `oexe_apg` → アプリが `vid` を引ける（`osta_prc` が 0）→ 起動側から見て `V_INPROC` → `oend_prc` のあと `V_INPROC` が外れ、固有データが保存される。像の数は 23 から 24 に増える（永続化の互換性の照合に使う数が変わる）。T1 の `時元試` と T3 の `時` を加えて現在は 26。V4b-2 の `oget_fsn`・`oput_fsn` は、アプリの起動中に起動側が対象ファイルを開いて取得・更新し、再取得・更新日時不変・処理終了後の `EX_VOBJ` を確かめる（像は増やさない）。

### V4b-0（実装済み）で決めたこと

- 登録簿は**共有塊**（`get_mbk` の `M_COMMON`、4 頁 = 16 KiB）。最初に使った行程が公開名 `omgrreg`（`cre_nam`）に番地を入れ、以後の行程は `get_nam` で取る。公開を先に別の行程がしていたら、自分の塊とセマフォを返して公開されたものを使う。共有塊が取れなければ、局所の登録簿（V4a までと同じ）に落ちる。
- ヘッダ: `+0` 次の仮身 ID、`+16` セマフォ ID。項は `+64` から（配置は変えない）。項の `+16` の上位 32 ビットに**持ち主の行程 ID**を入れる。
- **排他**: 登録簿の確保・解放（`oreg_vob`・`b_odup_vob`・`odel_vob`）をセマフォで囲む（待ちは 2 秒で諦める）。
- **持ち主のいない項の掃除**: 仮身の登録は行程のもので、行程の終了で無くなる。登録簿が一杯になったとき、`odel_obj`・`V_CHKREF`/`V_CHKDUP`・`oreg_vob` の虚身の判定のとき、持ち主の行程が存在しない（`prc_sts`）項を空ける（自分の項は空けない）。
- 試験: `実試` に、子行程（`実試 c <仮身 ID>`）が親の登録した仮身を引け・自分でも登録でき、子の終了後に子の項が `V_CHKREF` に数えられないことを確かめる項目を足した（49 項目）。掃除を外す・局所の登録簿に固定する変異で落ちる。

### V4b-1（実装済み）で決めたこと

- **`M_EXECREQ`**: `type = 0x10`、`size = 132`、全体 140 B。`self`（+8）はアプリのファイルの `LINK`（`atr3`〜`atr5` = アプリ ID）、`lnk`（+60）は対象の実身、`vid`（+112）、`pwid`（+116）、`info`（+120）、`r`（+124）、`bgcol`（+132）、`mode`（+136）を持つ。`mode` の R ビットは 0 = 既定起動（`info` = 実行環境ファイルの固有データの写しの番地。共有でないときは 0）、1 = 実行メニュー起動（`info` = 実行機能付箋のレコード番号）。
- **アプリの像名**: 実行プログラムレコード（型 29）の本体を NUL 終端の ASCII の像名とし、`/SYS/<像名>` を TC で引いて `cre_prc` に渡す。像名は 20 文字まで。`BTRONリンク取` の負のカーネルエラーは `錯換` で `ER_*` に直す（SYS 未接続は `ER_NOFS`）。
- **既定起動**: 対象の VLINK の `appl`（+46〜+50）が `(0,0,0)` でなければ、`appreg` の登録のうち `appl` が一致するものを探し、複数あれば最後に登録されたものを起動する。`appl` が `(0,0,0)` なら全部の登録から選ぶ（選択パネルは出さない）。
- **実行メニュー起動**: `item` の下位バイトが n（1 以上）なら、対象の実身（仮身の指すファイル）の n 番目の型 31 レコードの `appl` と、`info` = そのレコード番号を使う。見つからなければ `EX_NOEXS`。
- **状態**: `oexe_apg` は登録簿の排他を取って `V_INPROC` を先に立て、失敗時は `起印消` で戻す。既に `V_INPROC` なら 0。`vid <= 0` は `EX_PAR`、虚身（`V_DETACH`）は `EX_VOBJ`、無い `vid` は `EX_VID`。
- **通知**: `osta_prc(vid, wid)` は `wid <= 0` を `EX_PAR`、虚身を `EX_VOBJ`、無い `vid` を `EX_VID` とし、`V_INPROC` と `wid` を記録する。`oend_prc(vid, dat, update)` は `V_INPROC` を外し、`dat` が NULL でなければ先頭の UH を長さとして最大 64 B を共有登録簿の固有データ（項の `+128`、`vseg` の `+96` 以降）に写し、`dlen` と `size` を更新する。`oend_req` は `vid` と虚身だけを検査する（表示起動は V6）。
- **起動メッセージの配送**: 核の行程ごとの起動メッセージ欄（`0x403E7000`、8 項 × 272 B = 2176 B。`+0` 型、`+8` 長、`+16` 本体 256 B）に `cre_prc` が置き、子が最初の `rcv_msg` で受け取る。行程の生成時に消し、配送後に消す。型 1〜31、本体 256 B まで。型 0 は従来の argv。
- **試験**: `実試` の 6 項目（起動一・処理終了・起動二・誤り・虚身・未接続）で、既定起動・`V_INPROC`・固有データ・実行メニュー起動（`info = 2`）・エラー・虚身・SYS 未接続を確かめる。V4b-1 の時点で 55 項目、V4b-2 の 5 項目を加えて現在は 60 項目。像の数は 24。T1 の `時元試` と T3 の `時` を加えて現在は 26。
- **実装上の注意**: `M_EXECREQ` の `mode` は 4 B だが、8 B の書込みで隣の作業域（`起像鎖`）を壊さないよう 1 B ずつ書く。

### V4b-2（実装済み）で決めたこと

- **対象レコードの記録**: 登録簿の項の `+126`（`VOBJSEG` の末尾の 2 B の余白）に、`oexe_apg` が起動した型 31 のレコード番号 + 1 を残す。0 は「実行機能付箋以外からの起動」。`oget_fsn`・`oput_fsn` はこの値から対象レコードを引く。レコード 0 の型 31 と「なし」を区別するため +1 する。`起印消` と既定起動では 0 に戻す。
- **前提**: 対象の仮身が `V_INPROC` で処理中であること。処理中でない仮身と `V_DETACH` の虚身は `EX_VOBJ`、無い `vid` は `EX_VID`、型 31 以外・対象レコードなしは `EX_NOEXS`。
- **`oget_fsn(vid, fd, dat, size)`**: `fd` で開いた実身の型 31 レコードを読み、`FUSENSEG`（96 B の見出し + 固有データ）を `dat` に写す。`size` がレコードより小さければ切り詰める。`dat` が NULL で `size > 0`、窓外は `EX_ADR`。
- **`oput_fsn(vid, fd, dat)`**: `dat` の `dlen`（+94）が 64 を超えれば `EX_NOSPC`。対象レコードの見出し（表示情報・appl・name・dtype・subtype）は変えず、`dlen` と +96 以降だけを更新する。`wri_rec` はファイルの更新日時を現在時刻にするので、書込み前に `fil_sts` で控えた更新日時を `chg_ftm` で戻す。更新日時が 0 のときは `chg_ftm` が「変えない」と解釈するため触らない（時計が 0 の起動では `wri_rec` も 0 のまま）。
- **試験**: `実試` に 5 項目を足した（既定起動は `EX_NOEXS`、型 31 の取得、dlen=4 の更新と再取得・更新日時不変、`EX_VID`/`EX_ADR`/`EX_NOSPC`、処理終了後の `EX_VOBJ`）。虚身の `EX_VOBJ` は既存の虚身の項目に足した。`実試` は 60 項目。

### 未決・未対応（V1a 時点）

- 付箋（`vlnk = NULL`）は `EX_PAR`（付箋は TAD の付箋セグメントに依存するので後）。
- ファイルシステムの接続の検査（`ER_NOFS`・虚身状態 `V_DETACH`）、`V_LINKFL`（間接参照）の判定は V3。
- `view` の補正（最も近い正しい領域）とデフォールトの大きさは、表示装置が無いので行わない。
- `V_CHKREF`/`V_CHKDUP` は、リンクファイルを辿らず、登録簿の同じ（FS 名, ファイル ID）だけを数える。
- アプリ ID の表（`oreg_apg`・`ofnd_apg`）と `cre_prc` の統合、続柄管理ファイルの置き場は V2・V4 で決める。
