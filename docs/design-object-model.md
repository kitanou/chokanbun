# 実身・仮身モデル設計書（Issue #46）

状態: **設計と V1a（登録簿）・V1b（実身の操作）・V2（続柄）・V3（接続と虚身）・V5（漢殻の命令）の実装**。BTRON3 の実身／仮身マネージャ（OS 仕様編 第3章 3.8）を、現在の録層・篇藏・漢殻の上にどう載せるかを決める。
原文: <https://www.chokanji.com/developer/doc/btron3/os_spec/shell/omgr.html>（3.8.1〜3.8.6、全 60 関数）。関連: [compat/btron3-file-design.md](compat/btron3-file-design.md)、[design-pianfs.md](design-pianfs.md)、[compat/btron3-api-inventory.md](compat/btron3-api-inventory.md)。

## 1. 原文の要点

| 概念 | 原文 |
|---|---|
| 実身 | 意味のあるデータの集まり。**実際のファイルに一対一に対応する**。常に仮身を通して参照され、直接は表示されない |
| 仮身 | 実身を参照するタグ。1 つの実身を 1 つ以上の仮身が参照できる。**内部的にはファイル管理の「リンク」で表現**する |
| 仮身リンク `VLINK` | `LINK`（52 B）と同じ配置で、欄の意味だけが違う: `fs_name[20]`・`f_id`（対象ファイル）と、仮身固有の `attr`（属性・状態）・`rel`（続柄の索引）・`appl[3]`（既定のアプリ ID） |
| 仮身セグメント `VOBJSEG` | `VLINK` と対になる表示情報（表示領域・開いた高さ・文字サイズ・色 4 色・固有データ）。文書（TAD）の中に埋め込む |
| 分類 | 通常仮身・内部仮身（開いた仮身の中の静的表示）・隠蔽仮身 |
| 間接参照 | 仮身の所属元のデバイスと別のデバイスの実身を指す仮身（リンクファイルを参照）。参照は保証されない |
| 虚身 | 切断状態のデバイスの実身を指す間接参照仮身。開こうとすると接続を求める |
| 続柄 | 仮身に付ける名前（16 文字）。**ファイルシステム単位**で「続柄管理ファイル」（ルート直下）に `VOBJREL{name[16], col}` の表で持ち、仮身には索引だけを入れる。索引 0 は名なし |
| 実身のタイプ | ファイルのアプリケーションタイプ（`atype`）。上位バイトは実身／仮身マネージャが使う属性、下位はピクトグラム番号 |
| マネージャの位置づけ | **外殻（アプリ層）**。アプリは `o*` 関数で仮身を登録・表示・操作し、アプリの登録・起動もここを通る |
| 仮身 ID `vid` | 仮身を**ウィンドウ／パネル上のパーツとして登録**したときに割り当てる正の整数。関数の大半は `vid` を取る |

## 2. 現状の部品との対応

実身・仮身の土台は、録層（BTRON3 の 1.6 ファイル管理）にすでにある。

| BTRON3 の概念 | 今ある実装 | 状態 |
|---|---|---|
| 実身（ファイル） | 録層のファイル（FS 番号＋ファイル ID、見出し 256 B、本体は連続した頁）。`cre_fil`・`opn_fil`・`del_fil`・`fil_sts` ほか | 済（B1〜B5）。`atype`（見出し `+80`）も保持 |
| 仮身リンク `VLINK` | 録層の `LINK`（52 B。`fs_name[20]`・`f_id`・`atr1..5`）。`cre_lnk`・`get_lnk`・`fnd_lnk`・`lnk_sts`・`syn_lnk` | 済。`attr`＝`atr1`、`rel`＝`atr2`、`appl[3]`＝`atr3..5` に対応づけられる |
| 間接参照（リンクファイル） | リンクファイル（種別 0）。`cre_lnk`・`gen_fil` | 済（M3） |
| 切断／接続・虚身 | `att_fls`・`det_fls`・`chg_fls`・`fls_sts`（FS の接続状態）。SYS は接続しない | 済（1.6 の接続管理）。仮身側の「虚身状態」の判定は未 |
| 参照数 | 見出し `+72`（同一 FS の固定リンクの数） | 済 |
| 続柄管理ファイル | 無い | 未 |
| 仮身セグメント・TAD | 無い（TAD は未着手） | 未 |
| 仮身の登録（`vid`）・ウィンドウ／パネル | 無い（表示装置が無い） | 未 |
| アプリ登録・起動（`appl` ID、実行機能付箋） | `cre_prc` が像ファイルの `LINK` から起動する。アプリ ID の表は無い | 一部 |

つまり**データモデルは録層で足りている**。足りないのは、その上の (a) 仮身の登録簿（`vid`）、(b) 続柄、(c) アプリ登録、(d) 表示（F7 の領域）である。

## 4. 方針

1. **実身＝録層のファイル、仮身＝録層の `LINK`**。新しい保存形式は作らない。`VLINK` は `LINK` の欄に `attr`・`rel`・`appl` を入れる規約を決めるだけ。
2. **識別子は BTRON3 のまま（FS 名＋ファイル ID）**。Issue #46 の「安定した識別子」は、これで満たす（`f_id` は 16 ビットで、録層は「次の ID」から空いている番号を探して割り当てる。削除したファイルの ID は一周するまで再利用されず、次の ID は永続化でも戻る。ただし回り込めば再利用される＝完全に再利用されない保証ではない）。篇ID との対応は、録層の本文を篇（型 `録`）へ移す段階（roadmap F5）で表を作る。ここでは決めない。
3. **実身／仮身マネージャは EL0 のライブラリとして作る**（`user/btron/omgr.mkn`。原文でも外殻＝アプリ層）。核に追加する漢令は要らない見込み（既存の 1.6 の漢令の上に載せる）。登録簿（`vid` → `VLINK`・`VOBJSEG`・状態）は行程内の表。
4. **実身と仮身の操作を分ける**（Issue #46 の原則どおり）: 仮身の複製・移動・削除は `LINK` の操作（実身は変わらない）、実身の複製（`ocre_obj` の `copy`）・新版（`onew_obj`）・削除（`odel_obj`）はファイルの操作。`odel_obj` は「参照数 0 かつ登録済みの仮身が無い」ときだけ削除し、中にあるリンクが指す先もネストして削除する（原文どおり）。
5. **漢殻の操作は後段**。命令名と構文は言語仕様と整合してから決める（Issue #46 の「仮案」のまま）。第一歩は、ライブラリの関数を呼ぶ外部命令（試験用）で挙動を固める。

## 5. 決定事項（V1a の実装で決めたもの）

1. **擬似ウィンドウは作らない（§5 の初案を変更）**。原文は `oreg_vob` の `wid < 0` を「−（描画環境 ID）」とし、描画環境が存在しなくても登録はでき、表示のときに `EG_GID` になる、としている。表示装置が無い間は、**`wid < 0` かつ `V_NODISP` で登録**し、`wid >= 0`（ウィンドウ）は `EX_WID` にする。`odel_vob(vid < 0)`・`ochg_sts(vid < 0)` は原文どおり `wid < 0` の登録を対象にしない（常に 0）。
2. **`EX_*` の値**: 原文のこの章に定義が無い。`ER_*` と取り違えないよう別の eclass（0xFFFE）の通し番号にする（`user/btron/er.mkn` の「選択の記録」）。原文は核のエラーがそのまま戻りうるとし、`oreg_vob` は `ER_NOFS` も返すので、値の重なりは許されない。`EG_GID` は表示の段階で決める。
3. **仮身の属性ビット**: 原文の図 123（画像）と図 124 を読み、`V_*` の定義（3.8.4）と突き合わせて確認した（`attr` は 16 ビット: bit0 `V_NONAME`〜bit9 `V_NOEXPND`、bit8 `V_OPENED`、bit11 `V_LINKFL`、bit12 `V_DETACH`、bit13 `V_INPROC`、bit14 `V_AUTEXE`、bit15 `V_HIDDEN`。`atype` は bit15 実行可能ファイル・bit14 デバイス実身・bit13 取外し可能デバイス実身、下位がピクトグラム番号）。登録のとき `V_LINKFL`・`V_DETACH`・`V_INPROC` は意味を持たないので消し、`ochg_sts` が返す値では `V_HIDDEN` を常に 0 にする。
4. **`VOBJSEG` の配置**: C の構造体のとおり自然な境界に置いた **32 B**（`RECT` 8 B・`H` 2 B・`CHSIZE` 2 B・`COLOR` 4 B × 4・`UH dlen` 2 B・余白 2 B）。固有データは +32 から。`COLOR` を 4 B とするのは仮定で、共有データ編 `data_type.html` で要確認。固有データは **64 B まで**で、超えると `EX_NOSPC`（登録簿の項の大きさによる制限）。
5. **登録簿**: 行程ごとの表を民の窓のデータ域の固定番地 `0x407E0000`〜に置く（192 B × 64 項。同じ窓の試験・核の用途と重ならない番地。頁はデマンドページングでゼロ埋め）。`vid` は 1 から単調増加で再利用しない。機械漢文のユーザー像は変更可能な大域変数を持てないので、固定番地を使う。
6. **登録簿の範囲**: まず行程内だけ。別行程が同じ実身を削除しようとしたときの `odel_obj` の判定（登録済みの仮身が無いこと）は、共有が要る段階（サービス行程化）で扱う。

### V1b で決めたこと

- **`ocre_obj` は `gen_fil` を `F_FLOAT` で呼ぶ**: 親のリンクを持たない参照数 0 のファイル（実身）ができる。仮身（リンクレコード）が格納されて初めて参照数が増える。`del_fil` の親は NULL（参照数 0 のときだけ消せる）。
- **生成先の FS**: 所属デバイスは持たないので、作業ファイル（`TC_FOWN`）の FS、未定義なら仮身の指す FS。`nvid` を渡すと新しい実身の仮身（属性 0、`wid` と `disp` は元の仮身と同じ）を登録する。
- **`copy ≠ 0`**: 全レコードをレコードの型・サブタイプごと複写する（リンクレコードも LINK のまま。参照数は増える）。1 レコードは 4096 B まで（超えると `EX_NOSPC`）。
- **`odel_obj`**: 登録簿に仮身がある・参照数 > 0 のものは消さず 0 を返す。消せたら含まれるリンクの先を入れ子に（深さ 3 まで、1 つの実身あたりリンク 16 個まで）同じ条件で消す。戻り値は消した数。`mode` のエラーパネルは出さない。
- **`oopn_obj`**: パスワードが違うとき、原文は入力パネルだが、パネルは出せないので `EX_PWD`。
- **`ochg_nam`**: 名前が `NULL`（変更パネル）は `EX_PAR`。同じ実身を指す他の仮身への仮身要求イベントとデバイス仮身の改名は未対応。
- **`oupd_fil`**: 実行メニュー・小物メニューが無いので、`vid`・`lnk` の検査だけ行って 0。

### V2 で決めたこと

- **続柄管理ファイル**: 原文はファイルの名前とレコードの形を規定しない（「ルート直下」「`VOBJREL` の表」「索引 0 は名なし」とだけ書く）。実装依存として、FS のルート直下の通常ファイル「続柄」（TC 2 文字）に、`VOBJREL`（名前 32 B ＋ 色 4 B = 36 B）を 1 レコードずつ、レコード番号＝索引で並べる。索引 0（全て 0）は最初に作る。追加だけで消さない。索引は 256 個まで（超えると `EX_LIMIT`）。
- 仮身の続柄は、**参照する実身（間接参照ならリンクファイル）の FS**の表を引く（原文）。
- `ochg_rel`: 索引が無ければ `EX_PAR`、`index < 0`（続柄変更パネル）は出せないので `EX_PAR`。
- `ocnv_vob`: 同じ FS なら 0 を返し何もしない。別の FS なら、元の FS に**リンクファイルを `F_FLOAT` で作り**（参照先の名前・生成日時・アプリタイプは `fil_sts` から。**参照先の FS が接続されている必要がある**＝SYS なら `att_fls` で接続してから）、仮身をそのリンクファイルを指すものに置き換え、`V_LINKFL` を立てる。続柄は、元の FS の表から名前を引いて新しい FS の表へ登録し、索引を付け替える（表が読めなければ 0）。この続柄の付け替えは、書き込める FS が RAM だけなので、FS をまたいだ端から端までの試験はしていない（`続柄登録`・`続柄取得` は単体で試験した）。
- `odel_obj` はリンクファイルを `lnk_sts` の参照数で判定し、リンクファイルそのものを消す（`fil_sts` は参照先を引くので使えない）。

### V3 で決めたこと

- **`o*` の接続・切断は登録簿の虚身状態を更新する**: `oatt_fls`・`oatt_vob` で接続すると、その FS の登録済みの仮身の `V_DETACH` を外し、`odet_fls`・`odet_vob` で切断すると立てる（原文: アプリは `att_fls`・`det_fls` でなく `o*` を使う。カーネルを直接呼ぶと登録簿は更新されない）。
- **`oreg_vob` の虚身**: 仮身の FS が接続されていなければ、同じ FS を指す虚身が既に登録されている場合だけ虚身（`V_DETACH`）として登録し、無ければ `ER_NOFS`（原文の接続パネルは出せない）。以前の「FS の接続の検査は V3」を実装した。
- **`oatt_vob` の接続先**: FS 名から装置を引く表が無いので、組み込みの FS だけ（SYS = 装置 `rom`・接続名 `SYS`、RAM = 装置 `mem`・接続名 `RAM`）。ほかは `ER_NOFS`。
- **`odet_vob`**: `vid > 0` は `vid` の FS、`vid <= 0` は `dev` の装置（空文字列はシステムデバイス = FS 名が SYS の接続）。切断済みなら 0、切断したら 1 で、`dev` が NULL でなければ論理デバイス名（TC 8 文字 + 終端）を戻す。
- **`ofat_fls`・`ofdt_fls`** は他のシステムコール実行中でも待たない点だけが違うが、行程内のライブラリなので待つものが無く、`oatt_fls`・`odet_fls` と同じ処理にした。
- 仮身要求イベント（虚身移行・解除）、小物メニュー・検索対象 FS の更新、接続・切断のパネルは未対応。

### V5（漢殻の命令）で決めたこと

- **外部命令として実装し、`kernel/kernel.mkn` の殻には手を入れない**（組み込み命令は増やさない。殻の組み込みとの取り違えと、`def_exc` を進めている作業との衝突を避ける）。1 つの漢像 `user/obj.mkn` を `実作`・`仮置`・`実削`・`実目`・`実名` の 5 つの名前で登録し、`argv[0]` で分ける。
- **操作文脈は RAM のルート**（作業ファイルは起動した行程に引き継がれないので使わない）。
- `実作 名`: `ocre_obj` で実身を作り、文脈のルートに仮身（リンクレコード）を置く（参照数 1。以後 `RAM/名` のパスで引け、同名は `名#1`）。`仮置 名 先`: 実身 `名` の仮身を実身 `先` の中に置く（参照数が増える）。`実削 名`: 文脈から `名` の仮身を 1 つ外し、`odel_obj` で実身を消す（他の仮身が参照していれば実身は残り、消した数は 0。仮身の削除と実身の削除を分ける）。`実目`: 文脈のファイルを `ID`・参照数・名前で一覧する。`実名 旧 新`: `ochg_nam`。
- **名前は ASCII のみ（20 文字まで、`/`・`#` を含まない）**。ファイル名の TC は **JIS X 0208 の 2 バイト符号**（`tools/gen-images.sh` は EUC-JP から 0x80 を引く）で、UTF-8 の引数を変える表を漢像に持たせていない。日本語の名前は、変換表（約 7000 字）の置き場を決めてから対応する。続柄管理ファイルの名前「続柄」も、これに合わせて JIS の符号（0x4233・0x4A41）にした。
- 出力は 1 行ごとに固定の形（`実作 完 ID=… 参照=…`、`仮置 完 参照=…`、`実削 完 外=… 消=…`、`実目 ID=… 参照=… 名=…`、`実名 完=…`、失敗は `実誤 命令 番号`）。終了コードは常に 0（漢殻が失敗を `殻碼` として出さないため）。
- 像の数が 18 から 23 に増え、**像の数は永続化の互換性の照合に使う**ので、これ以前の `同` の保存（`make run` のディスク）は読まれず、初期化した状態で起動する。

### 未決・未対応（V1a 時点）

- 付箋（`vlnk = NULL`）は `EX_PAR`（付箋は TAD の付箋セグメントに依存するので後）。
- ファイルシステムの接続の検査（`ER_NOFS`・虚身状態 `V_DETACH`）、`V_LINKFL`（間接参照）の判定は V3。
- `view` の補正（最も近い正しい領域）とデフォールトの大きさは、表示装置が無いので行わない。
- `V_CHKREF`/`V_CHKDUP` は、リンクファイルを辿らず、登録簿の同じ（FS 名, ファイル ID）だけを数える。
- アプリ ID の表（`oreg_apg`・`ofnd_apg`）と `cre_prc` の統合、続柄管理ファイルの置き場は V2・V4 で決める。
