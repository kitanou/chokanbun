# 超漢文OS アーキテクチャ v0.1（草案）

## 原則
1. カーネル内部・ドライバ・ユーザーランドを機械漢文で記述する。
2. コンパイラは独立実装し、機械漢文AST → 型付きIR → LLVM IR → AArch64 と変換する。
3. 実行時の構造体やページテーブルはバイナリ表現とし、漢文テキストとして保持しない。
4. 初期ブートと例外入口に必要な最小限のアセンブリは暫定許容する。
5. QEMU virtで検証後、実機移植を検討する。

## 層
- userland: 漢文シェル、基本コマンド
- runtime: syscallラッパー、標準入出力、メモリAPI
- kernel: 起動、物理/仮想メモリ、例外、行程、スケジューラ、VFS、ドライバ
- arch/aarch64: EL1/EL0、MMU、例外ベクタ、GIC、汎用タイマー、PL011 UART
- hardware: QEMU virt (AArch64)

## 境界
- EL1: カーネル、EL0: ユーザー空間
- システムコール: SVCを介する。番号・引数・エラー規約はABI文書で固定
- デバイス: MMIOを型付きvolatile操作として表現
- 互換性: POSIXは独立レイヤーで段階的に実装

## 実装状況（M3）
- `kernel/`: 漢極本体。`kernel.mkn`（機械漢文）が PL011 出力・例外診断・
  物理ページ割当・変換表構築・GIC 設定・割込処理・漢令処理・民行程本体を担い、
  `boot.mkn`/`entry.mkn`（`組譯` によるインライン asm）と `proc/sysreg.mkn`（型付き機械命令）がスタック・ベクタ表・
  システムレジスタ操作・EL0 遷移と SVC 境界を担う。
- 例外: 同期例外を捕捉し ESR_EL1 を復号、`eret` で継続する。
- コンソール: PL011 UART を機械漢文の volatile MMIO で操作する。出力は
  `核外字元`（`UART_FR` の TXFF を待って `UART_DR` へ書く）、入力は
  `核外有空`/`核外受`（`UART_FR` の RXFE を見て `UART_DR` から読む）。
  漢令 `読込`（番10）が受信分を検証済みの民の窓バッファへ写し、殻の入力経路になる。
- MMU: 4KiB グラニュール、レベル1 表 + レベル2 表 + レベル3 表を**行程ごとに**
  持ち、核の写像は 2MiB ブロック単位、民の窓は 4KiB ページ単位で属性を与える。
  核の写像（コード EL1 RO+EL0 RO、data/核棧・頁池/頁表は EL1 RW）は全行程で
  共通で、要素3 の「民の窓」は全行程共通でその行程のレベル3 表を指す（仮想
  `0x40600000`）。民の窓の物理ページは触れた時に与えられるため、行程間で互いの
  書き込みは見えない。EL0 から書き込めるブロックは EL1 で実行できないという
  段1規則のため、実行イメージと窓を別ブロックに置く。
- 割込: GICv2（QEMU `virt`, `gic-version=2`）のディストリビュータ
  0x08000000 と CPU インタフェース 0x08010000 を機械漢文の volatile MMIO で
  設定する。EL1 物理タイマー（PPI 30）を `CNTP_TVAL_EL0`/`CNTP_CTL_EL0` で
  起動し、IRQ はベクタ表（Current EL with SPx, +0x280）から `irq_handler`
  （暫定アセンブリでレジスタと NZCV を保存）を経て機械漢文の
  `公開 記號「irq_dispatch」 術曰「割込處理」` に届く。ハンドラは `GICC_IAR`
  で要因番号を取得し、タイマーを再装填して `GICC_EOIR` で完了、`eret` で
  中断した計算へ戻る。EL0 実行中のタイマー割込は下位EL IRQ ベクタ（+0x480）へ
   入り、`公開 記號「irq_switch」 術曰「割込切替」` が横取り切替を行う（下記
   「プリエンプション」）。
- 行程: `入民籍`（`enter_el0`）で EL0 へ遷移し、EL0 の `svc #0` は下位EL同期
  ベクタ（+0x400）の `lower_sync_handler` を経て機械漢文の漢令處理
  （`svc_dispatch`）で処理する。漢令番号は `x8`、引数 `x0`–`x5`、戻り値 `x0`
  （漢令 ABI v0.1、`docs/abi-aarch64.md`）。`lower_sync_handler` は**行程ごとの
  核棧**（64 KiB、`核棧基` 0x40320000 から）上に 288 バイトの保存フレーム
  （`x0`–`x30`・NZCV・`ELR_EL1`・`SPSR_EL1`・`SP_EL0`）を作り、`svc_dispatch` が
  返すフレーム（別行程のこともある）へ `SP_EL1` を切り替えて復歸する。これにより
  コンテキスト切替が成立する。
- スケジューラ: 行程表（`程表址` 0x40300000。192 B × `程限`=8 項、項の配置は `偏識`〜`偏柄`）に各行程の保存フレームへの**ポインタ**を置き、
  `譲渡`（番5）と `終行程`（番2）で次の実行可能な行程へ協調的に切り替える。
  `次程` は優先度に従い、群 A（0〜127）は厳密な優先順、群 B（128〜191）・群 C（192〜255）は
  仮想時刻による配分比で選ぶ（`docs/design-subtask.md` §10）。`立程` が行程の核棧上に初期フレーム（`x0`=行程番号、
  `ELR`=民務、`SPSR`=EL0t、`SP_EL0`=民の棧の頭 `0x40608000`（32 KiB。需要で頁を張る））を作り、その
  アドレスを行程表の `偏框` に記録する。行程の状態（`偏状`）は 0=空（終了）・1=実行可能・
  2=待機で、`次程` は状=1 の行程のみ選ぶ。
- プリエンプション: 民行程が `開先取`（番7）を発行すると、自分の保存フレームの
  `SPSR_EL1` の I ビットを落とし（`0x340`）、タイマーを起動する。
  以降に EL0 で受けたタイマー割込は下位EL IRQ ベクタ（+0x480）の
  `lower_irq_handler`（288 バイトの保存フレーム）を経て機械漢文の
  `公開 記號「irq_switch」 術曰「割込切替」` に届く。ハンドラは `GICC_IAR` で
  要因番号（PPI 30）を取得し、刻数を進めてタイマーを再装填し `GICC_EOIR` で
  完了してから `排程` を呼ぶ。`排程` は SVC と同じ枠組みでコンテキスト（と
  `TTBR0_EL1`）を切り替え、ハンドラは返されたフレームへ `SP_EL1` を切り替えて
  `eret` する。
- 待機・起床: `待機`（番8）は呼出側の起床予定刻（`偏覚` = 現在刻 + 指定刻）を
  記録して状を 2（待機）にし、`排程` で他の行程へ切り替える。`割込切替` は刻を
  進めた後に `覚醒` を呼び、`偏覚` の時刻に達した待機行程を状=1 へ戻す。
  `排程` は生存する行程（状 ≠ 0）のフレームへのポインタを保存するため、待機行程は
  起床後に自分の核棧上でそこから再開する。QEMU で 甲 が `待機` で眠り、乙 が
  回転中に 甲 が起床することを確認。実行可能な行程が尽きた場合は核が EL1 で
  待機する（制限）。
- アドレス空間: 行程ごとに変換表を持ち、`排程` が行程を切り替えるときに
  `設台`（`set_ttbr0`）で `TTBR0_EL1` を次の行程の表へ向けて TLB を無効化する。
  民の窓は仮想 `0x40600000` が行程ごとの物理ページに写るため、同一の仮想
  アドレスへの書き込みが行程間で見えない（QEMU で 甲/乙 が同じ仮想アドレスに
  それぞれ 0xa/0xb を書き、切替後に各自の値を読むことを確認）。
- デマンドページング: 民の窓はレベル3 表で 4KiB ページ単位に管理し、起動時に
  張るのは民の棧の先頭 2 ページだけ。EL0 が未写像ページに触れると下位EL
  データアボート（EC=36）が発生し、`漢令處理` が `頁取`（動的頁域 `頁元`
  0x40800000 のビットマップ割当）で物理ページを与え、`無效台` で TLB を無効化して
  同じ命令を再試行する。QEMU で 甲/乙 が未写像の `0x40701000` に書き込み、
  頁が供給されて各自の値（0x1000/0x1001）を読み戻すことを確認。
- 境界検査: 漢令のポインタ引数は `漢令處理` が EL0 可読範囲（コード/rodata 域と
  自分の窓）に収まるか、かつ長さが `令長限`（4 KiB）以内かを確認し、窓外・核専用
  ブロック・長過は `-EFAULT` で拒否する。`書出`（読取系）と `読込`（書込系）の
  両方に適用する。未知の漢令番号は `-ENOSYS`、窓外の不正アクセスなど他の
  下位EL同期例外は `民異常` を出して待機する。
- 典籍（VFS/RAMFS）: 目録と本文を核の EL1 専用域（0x403A0000/0x403B0000）に置く
  メモリ内ファイルシステム。起動時に数件を登録し、`開`/`閉`/`讀入`/`柄書` の各漢令が
  名前照合と現在位置つきの読み書きを行う。柄 `0` はコンソール入力、`1`/`2` は
  コンソール出力で、殻は装置とファイルを同じ柄で扱える。核が EL1 から民の頁へ書く
  `讀入` は `備宛`（窓内・`令長限` 以内を確認し `給頁` で先に張る）を通す。
- 未実装: VFS のモジュール分割（`kernel/vfs/`）、漢文シェル、構造体を渡す漢令の複製検査。

## 非目標（初期）

- GUI・ネットワーク・SMP
- 実機Apple Siliconでの直接ブート
