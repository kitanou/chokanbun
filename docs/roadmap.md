# 開発ロードマップ

> 目標: **ブートローダー、カーネル、ドライバ、ユーザー空間、コンパイラまで、最終的に人が保守するソースコードをすべて機械漢文に統一する独立ARM64 OS。**
>
> 全体追跡: [Issue #10 — 完全機械漢文OS化](https://github.com/kitanou/chokanbun/issues/10)

## 原則
- 対象は AArch64、初期実行環境は QEMU `virt`。
- 初期のコンパイラや起動スタブに既存言語・AArch64アセンブリを暫定利用できる。ただし置換計画と依存境界を記録する。
- 最終的にブートローダー、カーネル、ドライバ、ユーザーランド、コンパイラ自身を機械漢文で記述する。生成される機械語、外部ファームウェア等は対象外。
- POSIX互換は段階的に検証する。
- 各マイルストーンでビルド、テスト、QEMU実行ログ、再現手順を残す。
- 以下は**目標・計画**であり、完了済みを意味しない。実装状況は検証後に更新する。

## M0: 言語最小仕様・既存成果の保全
- [ ] 既存の `docs/`、`src/` とGit追跡状況を確認し、成果を保全
- [ ] 整数、ポインタ、関数、文字列、MMIO、無標準ライブラリの仕様を確定
- [x] 字句解析・構文解析・型検査のビルドとテスト
- [x] LLVM IR出力とAArch64 ABIの検証


## M1: 世界安寧 — 初回ベアメタル起動
- [ ] QEMU `virt` / AArch64の起動方式、EL、メモリ配置、DTB、PL011 UARTを定義
- [ ] 必要に応じ暫定起動スタブでスタック・BSS・例外レベルを初期化
- [x] **機械漢文ソースから生成したコードでUARTに「世界安寧」を表示**
- [ ] GDBで再現可能な起動テスト、ビルド手順、ログ

## M2: 機械漢文カーネル基盤
- [ ] 低レベル言語機能（volatile MMIO、メモリバリア、システムレジスタ、セクション、例外ハンドラ等）
- [ ] UART・カーネル起動部分を機械漢文で記述し、「超漢文起動」を出力
- [ ] 例外ベクタ、タイマー、物理メモリ管理、MMU
- [ ] 暫定アセンブリ依存を洗い出し、機械漢文生成コードへ段階的に移行

## M3: 行程 — プロセス基盤
- [ ] スケジューラ、コンテキスト切替、EL0実行、SVC、アドレス空間
- [ ] ユーザー・カーネル境界の検証

## M4: 文件とシェル
- [ ] VFS、簡易RAMファイルシステム
- [ ] 機械漢文製init、漢文シェル、基本ドライバ

## M5: POSIX互換サブセット
- [ ] read/write/open/close、exec/wait/pipe、forkなどを段階的に検証
- [ ] 対応範囲・非対応範囲を明文化

## M6: 機械漢文ブートローダー
- [ ] QEMU直接起動・UEFI等との責務境界を明確化
- [ ] カーネルロード、メモリ情報・DTB受け渡し、制御移譲を機械漢文で実装
- [ ] 暫定起動スタブを撤去し、コールドブートを検証

## M7: セルフホスティングと全ソース機械漢文化
- [ ] コンパイラ、標準ライブラリ、必要なビルドツールを機械漢文へ移植
- [ ] 機械漢文コンパイラで自身を再ビルド
- [ ] 手書きC/Rust/Assemblyの残存依存を監査し、外部境界を明記

## 品質ゲート
各マイルストーンに自動ビルド、単体・統合テスト、QEMUテスト、再現手順、ログを付ける。M1は「世界安寧」、M2は機械漢文カーネルによる「超漢文起動」を区別して検証する。
