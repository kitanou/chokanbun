# 開発ロードマップ

> 目標: **ブートローダー、カーネル、ドライバ、ユーザー空間、コンパイラまで、最終的に人が保守するソースコードをすべて機械漢文に統一する独立ARM64 OS。**
>
> 全体追跡: [Issue #10 — 完全機械漢文OS化](https://github.com/kitanou/chokanbun/issues/10)
>
> 殻の命令と漢令の一覧: [shell-commands.md](shell-commands.md)

## 原則
- 対象は AArch64、初期実行環境は QEMU `virt`。
- 初期のコンパイラや起動スタブに既存言語・AArch64アセンブリを暫定利用できる。ただし置換計画と依存境界を記録する。
- 最終的にブートローダー、カーネル、ドライバ、ユーザーランド、コンパイラ自身を機械漢文で記述する。生成される機械語、外部ファームウェア等は対象外。
- POSIX互換は段階的に検証する。
- 各マイルストーンでビルド、テスト、QEMU実行ログ、再現手順を残す。
- 以下は**目標・計画**であり、完了済みを意味しない。実装状況は検証後に更新する。

- UART ドライバ `boot/uart.c` は C の暫定実装。M2 の機械漢文 MMIO 記述
  （`kernel/kernel.txt`、`tests/uart_mmio.txt`）へ移植済みで、C 版は
  `外術曰` 連携の参照用に残している。
- 漢極の低水準入口は暫定アセンブリに限定する:
  `kernel/boot.S`（スタック・BSS 零化・`VBAR_EL1` 設定）、
  `kernel/vectors.S`（例外ベクタ表・レジスタ保存）、
  `kernel/sysreg.S`（`enable_mmu`/`read_sctlr`・汎用タイマー・`daif`/`wfi` 制御）、
  `kernel/el0.S`（EL0 遷移・SVC 境界・下位EL IRQ 入口・`svc_call`）。
  例外診断・ページ割当・変換表構築・GIC 設定・割込処理・漢令処理・民行程本体は
  機械漢文（`kernel/kernel.txt`）で実装している。
- アドレス空間は行程ごとの変換表を持つが、配置は当面 QEMU `virt` の固定前提
  （Devicetree 未解析）。民の窓は行程ごとのレベル3 表で 4KiB ページ単位に
  デマンドページングする（物理頁は `頁元` 0x40800000 からのビットマップ割当（16 MiB）。`頁放` で返せる）。窓の
  サイズ（2MiB）と細かい 4KiB 保護（W^X など）は今後。
- EL0 行程は既定でプレエンプション無効（`SPSR_EL1` の DAIF マスク）で走り、
  切替は協調的（`譲渡` 番5・`終行程` 番2）に行う。民行程が `開先取`（番7）を
  発行すると自分の `SPSR_EL1` の I ビットを落とし、タイマーを起動して
  非協調切替を有効にする。その後のタイマー割込は下位EL IRQ ベクタ（+0x480）の
  `lower_irq_handler` を経て機械漢文の `割込切替`（`irq_switch`）が処理し、
  `排程` を呼んで SVC と同じ枠組みでコンテキストを切り替える。行程ごとに核棧
  （64 KiB、`核棧基` 0x40320000 から）を持ち、保存フレームはその核棧上に置く。
  行程表の `偏框` はフレームへのポインタを保持し、`排程` は次行程のポインタを返す。
  `el0.S` は返されたアドレスへ `SP_EL1`（EL1h の `sp`）を切り替えてから復歸する。
- 待機・起床: 行程の状態（行程表の `偏状`）は 0=空（終了）・1=実行可能・2=待機・3=終了済み未回収（僵）・4=子待ち・5=メッセージ待ち・6=送信の空き待ち・7=同期物待ち（セマフォ・フラグ・バッファ・ランデブ）。`待機`（番8）は
  呼出側の起床予定刻（`偏覚`、現在刻 + 指定刻）を記録して状を 2 にし、`排程` で他の
  行程へ切り替える。`割込切替` は刻を進めた後に `覚醒` を呼び、起床予定刻に達した
  待機行程を実行可能へ戻す。`排程` は生存する行程（状 ≠ 0）のフレームへのポインタを
  保存するため、待機行程も起床後にそこから再開する。全行程が待機して実行可能な
  行程が無い場合、核は EL1 で IRQ を禁止したまま `wfi` し、起きるたびに `閑巡`（`el0_park` から呼ぶ）が GIC の
  タイマー割込を直接確認して刻を進め、時間切れ・起床予定刻に達した行程へ切り替える。漢令の入口でも、呼出側が IRQ を禁止している（`開先取` していない）ときだけ同じ確認
  （`刻巡`）をする（IRQ を許している行程の割込を横取りすると先取りが起きなくなるため）。ただし、**漢令を呼ばずに走り続ける行程**がいる間は、その行程が `開先取` していない限り
  時間が進まない（既知の制限）。
- 割込は QEMU `virt`（`gic-version=2`）を前提とする。EL1 物理タイマー（PPI 30）を
  GICv2 経由で受け、`GICC_CTLR.AckCtl` を設定してセキュア状態でも `GICC_IAR` で
  要因番号を取得する。ごく短い周期で数回発火させて検証する。
- 篇藏（VFS）: 篇のメタデータ表を 0x403EC000（64 B × 128）に、本文と章の表を頁池の頁に置く。根 `天地` の下に
  予約章（家・典・法・器・術・志）を起動時に作り、典籍の 2 件は `天地/典` に登録する。`開`（番11）・`創`（番16）・
  `削`（番24）は名前をパスとして現在章（起動時は `天地/典`）から解決し、`讀入`/`柄書` は開表の位置から読み書きする。
  柄 `0`/`1`/`2` は `天地/器/盤`（コンソール）を開いたものとして扱う。詳細は [design-pianfs.md](design-pianfs.md) §13。
- BTRON3 互換層の核側は `kernel/proc/`（gname・clk・msg・user・term・sync・sync2）と `kernel/file/btron.txt` に置き、
  表は核専用ブロックの 0x403E0000〜0x403EAFFF に固定配置している（配置の一覧は各ファイルの冒頭の定数）。
  互換層の EL0 ライブラリは `user/btron/`。漢令の番号は `abi-aarch64.md` の表を正とする。
- 殻は外部命令の名前を厳密比較せず、組み込み命令の先頭と重なる名前（例: `終試`）を組み込みとして扱ってしまう。
  外部命令名は組み込み命令（響・讀・書・削・目・終・助 など）の先頭と重ならないようにする（殻の修正は別課題）。
- 機械漢文の字句の制約: 式の中で参照する名前に ASCII やカタカナを混ぜられない（`「…」` で囲めば宣言・呼出しは可）。
  予約語で始まる名前（`受…`・`呼…`・`返…`、単独の `項`・`無`・`空`・`負`・`真` など）は識別子に使えない。
- VFS は `kernel/vfs/`（`const.txt`・`pian.txt`・`handle.txt`）に分割済み。コンパイラに取込が無いため、ビルド時に
  `tools/kernel-expand.sh` が `kernel/kernel.txt` の `註 @取込 パス` 行を展開する（案A）。
