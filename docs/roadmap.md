> 目標：BTRON3仕様書 Ver. 3.20.00 への完全準拠を目指し、AArch64上で動作する独立OS「超漢文」を構築する。OSの保守対象ソースは段階的に機械漢文へ移し、最終的にブートローダー・カーネル・ドライバ・ユーザー空間・コンパイラを機械漢文で記述する。
>
> - 全体方針：[#10 完全機械漢文OS化](https://github.com/kitanou/chokanbun/issues/10)
> - BTRON3適合性：[#42 BTRON3仕様書 Ver. 3.20.00 への完全準拠](https://github.com/kitanou/chokanbun/issues/42)
> - 漢殻と実身・仮身：[#46](https://github.com/kitanou/chokanbun/issues/46)
> - 黄帝紀元：[#47](https://github.com/kitanou/chokanbun/issues/47)
> - 独自機械漢文CPU：[#26](https://github.com/kitanou/chokanbun/issues/26)
> - 組譯の型付き化：[#102](https://github.com/kitanou/chokanbun/issues/102)
> - Devicetree と固定配置の解消：[#103](https://github.com/kitanou/chokanbun/issues/103)
> - POSIX サブセット：[#104](https://github.com/kitanou/chokanbun/issues/104)

この文書は、実装済み機能、進行中の作業、将来計画を区別して追跡する。チェック項目はテストや仕様照合で確認できた場合のみ完了にする。

## 開発原則

1. **BTRON3適合性を外部仕様の基準とする。** 規範仕様、内部実装、超漢文独自拡張を区別する。「完全準拠」は適合性マトリクスの全対象項目を検証してから宣言する。
2. **漢殻は必須UIである。** GUIを導入しても漢殻を廃止しない。診断・保守・基本操作・GUI起動に利用できるようにする。
3. **実身・仮身を第一級オブジェクトにする。** 実身の内容と仮身の参照・配置・操作を混同せず、漢殻とGUIで共通の意味モデルを使う。
4. **機械漢文を段階的に拡大する。** 暫定アセンブリや既存言語を許す場合は、依存箇所と置換計画を記録する。
5. **基本OS機能はLLMに依存させない。** 漢殻の命令実行、ファイル操作、権限検査、時刻処理は明示的構文と決定的なコードで行う。篇藏はLLM非依存とする。
6. **各段階を再現可能に検証する。** ビルド、単体・統合テスト、QEMU実行、ログ、仕様根拠を残す。
7. **初期実行基盤はAArch64/QEMU virtとする。** 独自機械漢文CPUは別系統の研究計画とし、現行OSの完成を妨げない。

- [x] 行程表・頁表・核棧の動的管理を堅牢化し、資源枯渇時の動作を検証
  - 行程表の枯渇は検証済み: 待たずに子を起動し続けると空き枠（6 個）を使い切って `-EAGAIN`、全員を回収でき、回収後にまた起動できる（`民生試`）。頁池の枯渇は割当器の水準で検証済み（全頁を取り切ると 0 が返り、全部放すと空き数が戻る）。頁不足時の `生行程` は、試験専用の漢令 230（核の中で頁池を絞って `生行程像` を呼ぶ）で、空き 0〜3 頁のとき `-ENOMEM` で失敗し、失敗後に頁が漏れないことを検証した。デマンドページング（`給頁号`）は頁池が空のとき頁を張らない（以前は `頁取` の 0 に属性を足して物理アドレス 0 を EL0 RW で張っていた不具合を直した。核が書き込む前の `備宛`・`備宛広` も、頁が張れなければ 0 を返す。漢令 230 の 0x20 で検証。共有塊の取得〈0x40〉と篇の本文の拡張〈0x80〉も、頁池が空のとき -ENOMEM で失敗し何も消費しないことを検証）。長時間実行は、起動・回収 200 回が全て成功し頁が漏れないことを検証した（`民生試`）。`頁取`・`塊頁連取` の呼び出し側は全件を確認した（頁表と核棧は行程枠ごとの固定領域で、動的に尽きるのは頁池と行程表だけ）。異常終了とメモリ保護は下の項目で検証した
- [x] メモリ保護、競合、異常終了、長時間実行の回帰試験を追加（核専用域・読み取り専用コードへの書込、実行不可のデータ域への飛び込み、BRK は子だけを強制終了し〈164・160・188〉、親は走り続け、頁が漏れない。`異常試`。写像済みの頁での欠陥を「解決した」と見なして無限に再試行する不具合を直した。競合は、タイマー横取り・セマフォ/イベントフラグ・メッセージの既存試験に加え、`競試`（5 行程が同時に篇の作成・書込・標・索・読戻・削除を 40 回ずつ、2 巡。食い違い 0・2 巡目の前後で頁が漏れない）で見ている。核の中は割込みを受けないので、競合が起こるのは民の側の共有状態と行程の切替である）

## 用語の注意

- この文書の **F0〜F9 は全体フェーズ**。篇藏の設計書（[design-pianfs.md](design-pianfs.md)）の段階 F0〜F5、BTRON3 ファイル管理の段階 B0〜B6、互換層の段階 G0〜G7 とは別物で、文書では「篇藏 F2」のように必ず前置きして区別する。
- 時刻: BTRON3 の API は STIME（1985-01-01 GMT 起点の秒）を外部仕様として保つ（`get_tim` ほか）。黄帝紀元（F6）は表示・利用者向けの暦として、その上に換算層を置く形で決める（API の値を置き換えない）。

## 既知の制約（抜粋）

- 時間待ち: 全行程が眠ると空き待ち（`閑巡`）が GIC を直接確認して刻を進める。漢令を呼ばずに走り続ける行程がいる間は、その行程が先取りを有効にしていない限り時間切れが進まない。
- 漢殻は組み込み命令を先頭の漢字 1 字で選ぶため、外部命令の名がその字で始まると取り違える。
- 核の表は QEMU `virt` 前提の固定番地（BTRON3 互換層と篇藏は核専用域 0x403E0000〜0x403EFFFF）。DTB から取るのは RAM と主な周辺の基底までで、核の内部表・`設頁表` の Device 塊・virtio の複数枠は固定のまま（Issue #103）。
- セルフホストの既知の不具合: 自作バックエンドで作った核の上で、自作ツールチェーンで作った `機譯` を動かすとコード頁が壊れることがある（どちらか片方が LLVM 製なら通る）。原因は未特定で、`TOOLCHAIN=kanbun` ではこの組み合わせの OS 上のコンパイル試験 3 件を省く（[selfhost-plan.md](selfhost-plan.md) §3e）。
- POSIX 互換は未提供。方針のみ [posix-compat.md](posix-compat.md) に記録している（Issue #104）。
- 機械漢文の字句の制約（式中の名に ASCII・カタカナを混ぜられない、予約語で始まる名を使えない。`空`・`負`・`返`・`項`・`終` などで始まる変数名も該当）は [compat/btron3-compat-layer.md](compat/btron3-compat-layer.md) の付記を参照。
- 録層（1.6）の本文は頁池の連続した頁（1 頁から始まり、足りなくなると倍に取り直して移す。最大 16 頁＝64 KiB、1 レコードは約 64 KiB まで。`rea_rec` の書き先は 1 回 64 KiB まで）。ファイルは FS あたり 32 まで。取り直しには連続した空き頁が要り（最大 64 頁の連続を 1 語の中で探す）、頁池が断片化すると 64 KiB に届かないことがある。写像されているファイルは本体が動くので伸ばせない（`ER_BUSY`）。ロックは記述子ごとに 1 件で `F_LOCK` は待たない（[compat/btron3-file-design.md](compat/btron3-file-design.md)）。
