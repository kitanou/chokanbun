## 2. 表示装置の第 1 段階（実装済）

- **装置**: `virtio-gpu-device`。QEMU には `-global virtio-mmio.force-legacy=false` と `-device virtio-gpu-device` を付ける。**主な試験の起動には付けない**（頁の総数を固定した試験があるため。専用の短い起動だけで使う）。
- **初期化は遅延**: 最初の `画面出` で、機器表（Devicetree）が教える virtio-mmio の枠から DeviceID 16 を探して初期化する。起動時には何も探さず頁も取らない。装置が無ければ `画面出` は `-ENOENT`。
- **提示の手順**（呼ぶたびに）: （資源が無い・大きさが違えば）2D 資源の作成 → 背面の割り当て → （新しい資源なら）走査出力の設定 → ホストへ転送 → 表示の更新 → 背面の取り外し。**走査出力は背面が付いた資源にしか設定できない**（QEMU が `ERR_UNSPEC` を返す）ので、割り当てが先。取り外しまで行うので、行程が終わって塊が頁池へ戻っても、装置があとでその頁を読むことはない（2D 資源はホスト側に画面の写しを持つので、取り外したあとも表示は残る。screendump で確認済み）。
- **背面**: 共有画面（§6）の 2 MiB 塊 1 つ（物理は連続）。幅 × 高 × 4 ≤ 2 MiB。
- **画素の形式**: virtio-gpu の `X8R8G8B8_UNORM`（4）。メモリ上のバイトが先頭から X・R・G・B の順で、ディスプレイプリミティブの 32 ビット画素（上位バイトが先、値 `0x00RRGGBB`）と一致する。赤・緑・青の帯を描いて screendump で確かめた。
- **漢令 233 `画面出`**: x0＝広域の 2 MiB 塊の先頭、x1＝幅、x2＝高。戻り値 0、引数不正は `-EINVAL`、塊でない番地は `-EFAULT`、装置が無ければ `-ENOENT`、装置の誤りは `-EIO`。（232 は永続化の試験が使っているので 233 にした。）
- **EL0 の入口**: `dp.mkn` の `gopn_dev("SCREEN")` が広域の最初の塊を 320×240 のビットマップとして描画環境にし、`gfls_dev`（原文に無い、この実装の追加）が提示する。
- **制約**: 画面の大きさは 320×240 固定。

## 3. 試験の方法

QEMU のモニタ（`-monitor unix:<ソケット>`）の `screendump` で PPM を取り、画素を調べる（`tests/run_tests.sh` の `gpu_boot`）。

- 画面の用意: 外部命令 `描試 G` が `SCREEN` を開き、赤・緑・青の帯・黒の縁・白い隅を描いて `gfls_dev`、さらに右上を赤紫にして 2 回目の提示。印（`描試 再提示`）が出たら `screendump` を取る。
- 確かめること: 320×240、帯と隅の画素値、2 回目の提示が反映される（資源を作り直さない経路）、装置を付けない起動では `-ENOENT`。
- 注意: モニタのソケットの経路は 104 バイトまでなので `/tmp` に作る。`screendump` のファイル名に空白があるときは `"` で囲む。
- 主な起動（装置なし）でも、`SCREEN` の環境の生成・仕様の取得・描画・読み戻しは試験できる（`描試` の 5 項目）。

## 4. 次の段階

1. **入力の残り**: キーコード（Linux の `KEY_*`）から TRON のキートップへの対応表と、かな入力、割り込みによる配達（今はポーリング）、`req_evt` のメッセージ配達の起床（今は漢令の入口で吸い上げるので、待っている行程は起きない）。
2. **画面の共有の残り**: `MSGPNL`（メッセージパネル）、描画の排他（今は行程が自由に同じ画素へ描く）、画面の大きさの変更。
3. **文字描画の残り**: 日本語の字形（再配布できるフォントの調査が要る）、フォント指定 `gset_fon`/`gget_fon`、文字間隔と描画方向 `gset_chd`、`gget_str`、`gcop_chr`、3.9 のフォント形式、TRON コードの B〜D ゾーンの割当。
4. **ウィンドウマネージャ（3.1）**: ウィンドウの生成・移動・再描画・イベント配送。漢殻からの起動と、GUI が止まったときの漢殻での診断・復旧（F7 の残りの項目）。
5. **描画関数の残り**: 曲線・円弧・楕円・多角形（画素の決め方は原文の図に頼る）、パターンマスクのビット配置（図 29）、カラー情報つきの環境、クリッピング領域。

## 5. 入力（第 1 段階）の記録

- 実装: `kernel/proc/inp.mkn`。virtio-mmio の DeviceID 18 を全部探し、設定空間（選択 0x11 `EV_BITS`・副選択 3 = `EV_ABS`）で、絶対軸を持てばタブレット、そうでなければキーボードとする。環は 1 頁（8 個の 8 バイトの受け取り枠）、割り込みは使わずに、漢令 192 事取・195 端取・198 鍵状取の入口で `入吸` を呼んで、装置が出したイベントを吸い上げる。装置が無ければ何もしない（頁も取らない）。
- 1.7 との接続: `evt.mkn` の `put_evt` の本体を `事発` に切り出して共有した。系掩（システムイベントマスク）の対象外は捨てる。キー状態・自動リピートの前提・PD ボタン状態は `事発` が更新する。
- 変換: キーボード `EV_KEY` の値 1 → `EV_KEYDWN`、0 → `EV_KEYUP`（値 2 のリピートは捨て、自動キーは 1.7 の仕組みが作る）。情 = キーコード | 文字 << 16（US 配列の ASCII。左右のシフトは Linux 42・54 で、メタキーなのでイベントを出さず `stat` の `ES_LSHFT`・`ES_RSHFT` に反映して、シフト時の文字に変える）。タブレットの `ABS_X/ABS_Y`（最大値は設定空間の `ABS_INFO` から読む。読めなければ 32767）は画面 320 × 240 に縮めて PD 位置にする。`BTN_LEFT` は `EV_BUTDWN`/`EV_BUTUP`。
- 試験: `件試 I` を virtio-keyboard-device・virtio-tablet-device つきで起動し、QMP `input-send-event`（絶対位置。HMP の `mouse_move` は相対）・HMP `sendkey`・`mouse_button` で注入する。
- 未解決: キートップの対応表（共有データ編・OS 仕様編には割り当てが無い。`gif/keymap.gif` は get_kmp のビット配置の図だった。キーボード固有の仕様が要る）、かな、割り込み。

## 6. 画面の共有（第 1 段階）

- **仕組み**: 核が 2 MiB の塊を 1 つ持つ（最初の `画面共有取` で頁池から取り、返さない。物理の番地は核の語 0x403FF020）。漢令 234 `画面共有取` は、呼んだ行程の広域の最後の枠（0x63E00000、枠 31）に EL0 RW で張って、その仮想アドレスを返す（2 回目以降は同じ値）。全ての行程が同じ物理の塊を見るので、画素は行程をまたいで共有される。
- **後始末**: 行程の終了（`広域清`）は、共有画面の枠を空にするだけで塊は頁池へ返さない。塊は核が動いている間は残る。広域取は枠 31 を使うので 31 個までにした（以前は 32 個まで）。
- **DP との関係**: `gopn_dev("SCREEN")` は共有画面を 320×240 のビットマップにする。`gfls_dev` は共有画面から出す（`画面出` は枠 31 の塊を受け付ける）。同じ起動で複数の行程が、先の行程の画素を残したまま描き足して提示できる。
- **試験**: `描試 G` のあとに `描試 H` を続け、screendump で、G の帯が残ったまま H の黄色の四角が出ることを確かめる。主な起動（装置なし）でも `SCREEN` の環境は作れるので、共有の塊は他の試験の頁の総数に影響しなかった（頁池の試験は通っている）。
- **未解決**: 描画の排他・合成（ウィンドウマネージャの仕事）、`MSGPNL`、複数の画面の大きさ。
