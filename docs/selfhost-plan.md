# セルフホスト計画（機械漢文コンパイラを機械漢文で書き直す）

[roadmap.md](roadmap.md) F9。今のコンパイラは C++17 の約 5900 行（`src/`）で、字句解析 → 構文解析 → 型検査 → LLVM IR 生成の 4 段。これを機械漢文へ段階的に移し、最後に「機械漢文で書いたコンパイラが、自分自身のソースから自分と同じ IR を作る」ことを目標にする。

## 1. 段階と現状

| 段 | 内容 | C++ の元 | 検証（出力の一致） | 状態 |
|---|---|---|---|---|
| 1 | 字句解析器 | `src/lexer.cpp`（714 行） | `-tokens` の出力が全ての `.mkn` で一致 | **完了**（`selfhost/lexer.mkn`） |
| 2 | 構文解析器と AST | `src/parser.cpp` 1346 行・`ast.*`・`astdump.cpp` | `-ast` の出力が一致 | **完了**（`selfhost/parser.mkn`） |
| 3 | 型検査 | `src/typecheck.cpp`（1193 行） | 診断（錯 E00xx）が一致（型は式の `式解` へ記録） | **完了**（`selfhost/typecheck.mkn`） |
| 4 | LLVM IR 生成 | `src/llvmir.cpp`（1282 行） | `-ir` の出力が一致 | **完了**（`selfhost/irgen.mkn`） |
| 5 | 駆動部と自己再構築 | `src/main.cpp` | 機械漢文のコンパイラで自分自身の IR を作り、C++ 版の IR と一致 | **完了**（ホストで不動点。OS 上の命令 `機譯` は小さな源のみ） |

各段は、C++ 版と**同じ出力**を出すことで検証する（出力形式をそのまま仕様にする）。段 1〜4 を終えれば、段 5 は C++ 版と機械漢文版の IR を比べるだけになる。

## 2. 段 1 の実装と検証

- `selfhost/lexer.mkn`: 入出力を持たない純粋な関数 `字句解析(状, 源址, 源長, 出址, 出容)`。源（UTF-8）を受け取り、`-tokens` と同じ形式の行 `行:桁 種 本文` を出力領域へ書く。状は 128 バイトの作業域。予約語 100 語は `src/lexer.cpp` の `allKeywords` と同じ（最長一致）。桁の数え方（`advance` 相当は 1 バイトごと、語・識別子・文字列は符号点ごと）も C++ 版と同じ。
- **ホストでの検証**（`tests/run_tests.sh`「selfhost」）: 機械漢文のコンパイラで IR にし、ホストの clang で実行ファイルにして（入出力だけの `selfhost/host_main.c` を付ける）、リポジトリの全ての `.mkn`（168 個）で C++ 版 `-tokens` と一致を確かめる。字句の誤りは両方が失敗すればよい。
- **OS 上での検証**: 外部命令 `字句`（`user/lex_cmd.mkn`。`selfhost/lexer.mkn` を取り込む）が、篇の内容を読んでトークン列を出す。QEMU 上の漢殻で `書 源 …` → `字句 源` を実行し、出力が C++ 版と一致することを確かめる。**機械漢文のコンパイラの一部が、機械漢文の OS の上で動いた**最初の段である。

## 3. 段 2 の実装と検証

- `selfhost/parser.mkn`: `構文解析(源址, 源長, 作業域, 作業容, 出址, 出容)`。字句解析器の**トークン表モード**（1 件 40 B: 種・本文・長さ・行・桁。予約語の種は 16 + 予約語の表の順、記号は 201〜205）でトークンを作り、再帰下降で AST を**領域（アリーナ）**へ固定長のノードとして詰め、`-ast` と同じ形式で出力する。作業域は呼び出し側が用意する（トークン表・文字列・ノードを詰める）。
- 誤りは C++ 版と同じ条件で数え、1 つでもあれば失敗にする（構文の誤り、比較演算子の連鎖、`stoull` 相当の桁溢れ、機械命令の文字列の検査など）。
- **ホストでの検証**（`tests/run_tests.sh`「selfhost」）: 全ての `.mkn`（173 個）で C++ 版 `-ast` と一致。構文の誤りがあるファイルは両方が失敗すればよい。
- **OS 上での検証**: 外部命令 `構文`（`user/ast_cmd.mkn`）が篇を読んで AST を出し、QEMU 上で C++ 版と同じ 11 行を出す（漢殻の 1 行は 200 バイト弱までなので、短い関数 1 つ）。
- 試験の中でコンパイラの不具合を 1 つ見つけて直した: LLVM IR の文字列定数で `"` と `\` を `\"`・`\\` と書いていた（正しくは `\22`・`\5C`）。文字列に引用符を含む機械漢文は IR にならなかった。

## 3b. 段 3 の実装と検証

- `selfhost/typecheck.mkn`: `型検査(源址, 源長, 作業域, 作業容, 出址, 出容)`。構文解析器の `構文構築` で AST を作り（段 2 の入口を「構文木を作る部分」と「AST を出す部分」に分けた）、`src/typecheck.cpp` と同じ順序で検査して、`錯 E00xx: 行:桁: 本文` の形式の診断を出力へ書く。長さ 0 は誤り無し。
- 状態は検査器の構造体（`検`）に持つ。局所変数は領域上の表（名・型・入れ子の深さ）で、入れ子を出るときに深さが同じ項を捨てる。関数・定数・構造体の探索は宣言の並びの線形探索（C++ 版と同じ）。型は段 2 の型ノードを共有し、指標型と文字列型だけ検査中に作る。式ごとに型を `式解` へ書く（`coerceLiteral` が決めた型も含む。次の段の IR 生成が読む）。
- 再現した C++ 版の挙動: 定数は使うたびに初期値を検査し直す（範囲外などの診断が使用ごとに重なる）、呼出しの引数は仮引数の個数までしか検査しない、本体の無い関数は個数の不一致を報告しない、`取址(術名)` は `無符六四`。
- **ホストでの検証**（`tests/run_tests.sh`「selfhost」）: C++ 版に診断だけを出す `-check` を足し、リポジトリの全ての `.mkn`（取込の断片を含む）と、取込を展開した全プログラム（核・行程・ローダー・セルフホスト自身）で診断の文字列・位置・順序が一致することを確かめる。展開後の全プログラムは誤り無し、`tests/lang/err/` と断片の診断あり（115 個）は一致。誤りの各メッセージを網羅するため `tests/lang/err/` に試験を足した。
- **OS 上での検証**: 外部命令 `型検`（`user/tc_cmd.mkn`）が篇を読んで診断を出し、QEMU 上で C++ 版 `-check` と同じ診断を出す。

## 3c. 段 4 の実装と検証

- `selfhost/irgen.mkn`: `IR生成(源址, 源長, 作業域, 作業容, 出址, 出容, 結址)`。型検査器の `検実行` で AST と式ごとの型（`式解`）を得て、`src/llvmir.cpp` と同じ順序で IR を出力する。型検査か IR 生成の診断があれば IR の代わりに診断を出し（`結址` に 1）、C++ 版の `main` と同じ振る舞いにする。
- 式の値は「型 値」の文字列（`i64 %v3` など）で受け渡す。文字列は領域に置く「長さ + 本体」で、一行は作業用の領域（築）で組んでから出力へ書く。名前の連番（`%v12`・`%r5` など）は C++ 版と同じ順に振る（カウンタは全関数で共通）。関数の先頭へ差し込む `alloca` は別の領域に溜め、関数の終わりで出力へ割り込ませる。
- C++ 版の癖も再現した: `define` の引数は次の行に出す、`二項演算` の `且`・`或` は短絡せずビット演算、`置` の左辺が識別子でなければ `; TODO: assign to`、`取址` は局所・引数以外は関数か文字列だけ、定数は畳み込める整数・真偽・空だけ。
- **ホストでの検証**（`tests/run_tests.sh`「selfhost」）: 型検査を通る全てのプログラム（核・行程・ローダー・セルフホスト自身を取込展開したもの）で、IR が C++ 版と 1 バイトも違わない。診断で失敗するものは診断が一致する。
- **自己再構築の予行**: 機械漢文の IR 生成器（ホストで動く）が自分自身のソース（字句・構文・型検査・IR 生成の全部）から作る IR が、C++ 版の作る IR と一致する。段 5 は、この IR を `llc` にかけて OS 上で動かすことと、駆動部（取込の展開・ファイル入出力）を機械漢文で書くことが残る。

## 3d. 段 5 の実装と検証（駆動部・自己再構築）

- `selfhost/driver.mkn`: `駆動(根址, 根長, 作業域, 作業容, 出址, 出容, 結址)`。`tools/kernel-expand.sh` と同じ規則（行頭の「註 @取込 相対路」を、**根の置き場**からの相対路のファイルで置き換える。同じファイルを何度取り込んでも毎回展開）で 1 つのソースに展開し、`IR生成` にかける。C++ 版の `main` に当たる。ファイルの読み込みだけは呼び出し側の術「ファイル読」に任せる（ホスト用の根 `selfhost/cc_host.mkn` は C の `file_read` を外術で呼び、OS 上では漢令で書いた術を与える）。
- **ホストでの検証**: 根のソースだけを渡して、核・ローダー・行程・セルフホスト自身で、展開 + C++ 版 `-ir` と IR が一致する。
- **不動点**: C++ 版が作ったコンパイラ（第 1 世代）が自分自身から作る IR → それをビルドした第 2 世代が作る IR → 第 3 世代が作る IR が、全て同じ（27,000 行余り）。**機械漢文のコンパイラが、機械漢文のコンパイラを再構築できる**。
- **OS 上のコンパイラ**: 外部命令 `機譯`（`user/cc_cmd.mkn`）が駆動部を載せ、篇のソースから、C++ 版 `-ir` と同じ IR を作る（QEMU で 27 行）。`@取込` の取込先も篇から読める。
- 制約・残り: 民の窓は 1 MiB 弱で、命令のバイナリ・源・作業域（704 KiB）・出力（128 KiB）が全部収まる必要があり、核のような大きな源は OS 上ではまだ通らない（大きな源のための連続頁の記憶域が要る）。IR → 機械語（`llc`）と結合（`ld.lld`）は LLVM に依存したままで、これを機械漢文で置き換える範囲は[roadmap](roadmap.md)の別項目。

## 4. 次の段に要るもの

段 3 以降は記号表と型を作るので、さらに動的な記憶域が要る。段 2 のアリーナ（作業域の bump 割り当て）を引き続き使う。

- **記憶域**: 民の窓（1 MiB 弱）では足りない。BTRON3 互換層のメモリ管理（`get_mbk`／`malloc`。連続した頁を取れる）を使い、AST のノードを領域（アリーナ）に詰める。ノードは固定長の構造体（機械漢文の `構`）か、型タグ付きの語の並びにする。
- **文字列・並び**: 識別子の表（文字列を一意にする）、ノードの子の並びは、アリーナ上の並びで持つ。標準ライブラリとして `selfhost/` に小さな文字列・並びの関数をまとめる（段 2 の最初の作業）。
- **入出力**: 篇（文）の読み書き（漢令）。大きな源のために、読み込みは 2 KiB ずつ繰り返す（`字句` と同じ）。

## 5. 残る外部依存（監査）と境界

セルフホスト後も、次は機械漢文の外にある。ここを「外部境界」と決める。

| 依存 | 役割 | 方針 |
|---|---|---|
| LLVM（`llc`・`ld.lld`・`llvm-objcopy`・`clang`） | IR → オブジェクト → ELF／漢像。`clang` は `tools/gen-images.sh` が作る `.S`（`.incbin` で漢像を埋め込むだけ）のアセンブルにも使う | IR を出力する所までを機械漢文で行い、その先は LLVM に任せる（当面） |
| QEMU | 実行環境 | 外部境界（試験環境） |
| `src/*.cpp`（C++ 版コンパイラ） | 段 5 の比較の基準、ブートストラップ | セルフホストが成立した後も、比較用に残す |
| `boot/uart.c`、`selfhost/host_main.c` | 前者は `uart` 試験の参照用 C、後者はホストでの字句解析器の試験用の入出力 | 試験の足場。核・民のどちらにも入らない |
| `tools/*.sh`・`tools/mkkernelimg.py`・`tests/run_tests.sh` | ビルドと試験の手順 | ホスト側のスクリプト。機械漢文化の対象外 |

核・民ライブラリ・ブートローダー（`kernel/`・`user/`・`boot/loader.mkn`）に手書きの C やアセンブリは無い（試験専用の `user/fault.mkn` の 1 か所を除く、[asm-inventory.md](asm-inventory.md)）。
