# 実装メモ

README から切り出した、各マイルストーンの実装の中身。仕様の正本は
[abi-aarch64.md](abi-aarch64.md)、進捗は [roadmap.md](roadmap.md)。

## M0〜M1: コンパイラと「世界安寧」

- 機械漢文コンパイラ（`src/`）がビルド・テスト可能。字句解析 → 構文解析 → 型検査 → LLVM IR 出力。
- QEMU `virt` / AArch64 上で、機械漢文ソース由来のコードが UART に「世界安寧」を出力する。
- PL011 UART ドライバを機械漢文の volatile MMIO・生ポインタ添字で記述できる（`tests/uart_mmio.mkn`）。

## M2: カーネル基盤（`kernel/`）

漢極本体（`kernel/kernel.mkn`）は機械漢文で記述している。

- PL011 出力。
- 例外ハンドラ: `brk #0` を捕捉して ESR を復号し、`eret` で継続する。
- 物理ページ割当。
- MMU: レベル1/レベル2 変換表を構築し、恒等写像で有効化する。
- GICv2 の設定と EL1 物理タイマー割込: `GICC_IAR` で要因番号を取得し、`GICC_EOIR` で完了して `eret` で復帰する。

## M3: 行程

- **EL0 行程と漢令:** 民行程（`民務`）が `svc #0` で漢令を発行し、`漢令處理` が処理して復歸する。
  漢令は番号 `x8`・引数 `x0`–`x5`・戻り値 `x0`（[abi-aarch64.md](abi-aarch64.md)）。
- **協調スケジューラ:** 保存フレーム（`x0`–`x30`・NZCV・`ELR_EL1`・`SPSR_EL1`・`SP_EL0`）を行程表に持ち、
  `譲渡`（番5）と `終行程`（番2）で次の行程へラウンドロビンで切り替える。
- **行程ごとのアドレス空間:** 行程ごとにレベル1/2/3 表を持つ。核の写像は 2 MiB ブロック単位で全行程共通、
  民の窓（仮想 `0x40600000`）は行程ごとのレベル3 表（4 KiB ページ）を指す。物理ページが行程ごとに異なるため、
  同じ仮想アドレスへの書き込みが行程間で見えない。切替時に `設台`（`set_ttbr0`）で `TTBR0_EL1` を切り替える。
- **デマンドページング:** 起動時に張るのは民の棧の先頭 2 ページだけ。EL0 が未写像ページに触れると下位EL
  データアボートになり、`漢令處理` が `頁取`（動的頁域 `頁元` 0x40800000 のビットマップ割当）で物理ページを与え、
  `無效台` で TLB を無効化して同じ命令を再試行する。
- **境界検査:** 漢令のポインタ引数は EL0 可読範囲と長さ（`令長限` 4 KiB）を検査する。
  核専用ブロックや長過は `-EFAULT`、未知の漢令番号は `-ENOSYS` で拒否する。
- **UART 受信:** PL011 の受信も機械漢文 MMIO で扱う。書込系漢令 `読込`（番10）が受信分を検証済みの窓バッファへ写す
  （殻の入力経路）。
- **プリエンプション:** 民行程は既定で割込をマスクして走る。`開先取`（番7）で自分の割込を解禁しタイマーを起動すると、
  EL0 で受けたタイマー割込が下位EL IRQ ベクタから `割込切替`（`irq_switch`）に入り、`排程` を呼んで
  SVC と同じ枠組みで非協調的に切り替える。
- **行程ごとの核棧:** 行程ごとに 64 KiB。保存フレームはその核棧上に置く。`排程` が次行程のフレームへの
  ポインタを返し、`el0.S` が `SP_EL1` を切り替えて復歸する。
- **待機と起床:** 行程の状態は 空/実行可能/待機 の 3 値。`待機`（番8）が起床予定刻を記録して眠り、
  `割込切替` の覚醒が刻の経過で実行可能へ戻す。

## M5 の土台: 物理ページの管理（頁池）

動的頁域（`頁元` 0x40800000〜`頁末` 0x41800000、16 MiB = 4096 ページ）をビットマップ（`0x40421000`、64 語）で管理する。
1 ビット = 1 ページで、1 は使用中。頁数を超える上位ビットがあれば常に 1 にして探索から外す。
動的頁域は EL1 RW の 2 MiB ブロック 8 個として、全行程の変換表（レベル2 の要素 4〜11）に恒等写像する。

- `頁取`: 最も若い空きページをゼロ埋めして返す（決定的）。空きが無ければ 0。
- `頁放`: ページを返す。範囲外・頁境界でない・使用中でない（二重解放）は 0。成功は 1。
- `頁残`: 空きページ数。
- ゼロ埋めは、解放したページの古い内容が次の行程に見えないようにするため。
- 起動時の自己テスト（`頁池 …` の行）が、割当・解放・二重解放・範囲外・境界外・再利用・ゼロ埋め・空き数の復元を確認する。
- 空きが無いときの扱いは未整備（`給頁` は 0 を受けて民異常を出す）。行程の生成・終了（P1 以降）で整える。

## M5 P1: 行程の生成・待機・終了（`kernel/proc/`）

外部命令（行程として起動する機械漢文のプログラム）を、漢像（`KBN1`）から子行程として作る。

- **漢像のビルドと埋め込み:** `tools/mkimage.sh user/hello.mkn` が漢像にし、`tools/gen-images.sh` がカーネルイメージへ
  `.incbin` で埋め込む（像表）。詳細は [design-process-exec.md](design-process-exec.md) §5.1。
- **`生行程`（番17）** → `生行程処理`: 像表で名前を探し（`像検`）、形式を確かめ（`像検査`）、空き枠（状 0 かつ 識 0）を選ぶ。
  枠の窓を空にして（`窓清`）、民の棧 2 ページとコード（16 ページ目 = `0x40610000` から、読み取り専用）を頁池から張って複写し、
  引数を最後のページ（`0x407FF000`）へ写す。コードを書いたあと `clean_dcache_range`・`sync_icache`（`kernel/sysreg.S`）で
  命令フェッチから見えるようにする。保存フレームに `x0`=引数のアドレス、`x1`=長さ、`ELR`=入口、`SPSR`=EL0t を作り、
  柄 0/1/2 を盤に向けて、識を割り当てて実行可能にする。
- **`終行程`（番2）** → `程終了`: 柄をすべて閉じ、子を孤児にし（親を 0 に）、親があれば窓の頁を返して状を僵（3）にし、
  親が待っていれば起こす。親が無い行程（起動時の甲・乙）は従来どおり空にする。
- **`待行程`（番18）** → `待行程処理`: 終わった子（僵）を回収して終了コードを書く。子が無ければ `-ECHILD`。子はいるが
  終わっていなければ状を待子（4）にして眠る。起こす側が親の保存フレームの `ELR` を 4 戻すので、起床後に `svc` が再実行されて
  回収が済む（ブロックする漢令は「状態を変えて切り替える」+「起床時に再試行」）。
- **引数（argc/argv）:** `引構` が最後のページ（`0x407FF000`、読み取り専用）に、`+0` argc、`+8` から argv の各ポインタ（仮想アドレス）、
  0 の終端、NUL 終端の文字列、の順に組み立てる。argv[0] は名前、argv[1..] は引数文字列を ASCII の空白で分けた語。
  子は `x0`=argc、`x1`=argv（`0x407FF008`）で始まる。
- **柄の継承:** 子の柄 0/1/2 は親の柄 0/1/2 と同じ開表項を指し、参照数を増やす（親が空なら盤）。リダイレクトとパイプで差し替える段階（P3）の土台。
- **殻の外部命令（`民殻外`）:** 組み込み（`響`・`讀`・`目`・`書`・`削`・`助`・`終`）に当たらない行の先頭の語を名前、残りを引数として
  `生行程` し、`待行程` で終了を待つ。終了コードが 0 以外なら `殻碼` を出す。像が無ければ `殻不明`、その他の失敗は `殻誤`。
  最初の外部命令は `問安`（`user/hello.mkn`。argv を空白でつないで出力、終了コード 7）と `數`（`user/count.mkn`。argc と引数の長さの合計を出力）。
- 起動時の殻行程（乙）が `民生試` で検証する: 子の起動と引数、終了コード 7 の回収、誤り経路（`-ENOENT`・`-ECHILD`）、
  20 回の起動・回収で頁残が変わらないこと。

## M5 の土台: 行程表（`程限` = 8）

行程ごとの情報を、128 B の 1 項にまとめた行程表（`程表址` 0x40300000、8 項）に持つ。

| 偏 | 項目 | 内容 |
|---|---|---|
| +0 | 識 | 行程番号（`立程` が 号 + 1 を入れる。0 = 未使用） |
| +8 | 状 | 0=空、1=実行可能、2=待機 |
| +16 | 親 | 親の識（0 = なし）。生成（P1）で使う |
| +24 | 碼 | 終了コード。待行程（P1）で使う |
| +32 | 台 | レベル1頁表の物理アドレス（予約。現在は `程台` で算出） |
| +40 | 框 | 保存フレームへのポインタ（核棧上） |
| +48 | 覚 | 起床予定刻 |
| +56 | 待 | 待ち対象（予約） |
| +64 | 柄表 | 8 本 × 8 B |

アクセスは `讀欄`/`置欄`（偏を指定）と、`讀状`・`置状`・`讀覚`・`置覚`・`讀棧`・`置棧`。
起動時は 2 行程（甲・乙）だけ作り、残りの 6 項は 状 = 0（空）。

メモリ配置（核専用ブロック 0x40200000〜0x403FFFFF）:

| 領域 | アドレス | 大きさ |
|---|---|---|
| 行程表 | 0x40300000 | 128 B × 8 |
| 現在の行程番号 | 0x40310800 | 8 B |
| 開表 | 0x40313800 | 32 B × 32 |
| 核棧 | 0x40320000〜 | 64 KiB × 8（0x403A0000 まで） |
| 典籍の目録・件数・本文 | 0x403A0000・0x403A0800・0x403B0000 | 512 B・8 B・256 B × 8 |
| 行程ごとの頁表 | 0x403C0000〜 | 12 KiB × 8 |
| 頁池のビットマップ | 0x40421000 | 512 B（64 語） |
| 動的頁域 | 0x40800000〜0x417FFFFF | 16 MiB |

起動時の自己テスト（`行程表 …`・`頁池 総`）が、8 項の独立（覚・親・柄表が重ならない）、`識` と 状、
8 行程分の頁表と動的頁域のブロック写像、頁池の総ページ数（4096）を確認する。

## M4: 典籍（RAMFS/VFS）と漢文シェル

- **典籍:** 目録（名前・名前長・本文長・現在位置・開状態）と本文を核の EL1 専用域に置く。最大 8 件、
  名前 16 バイト、本文 1 件 256 バイト。起動時に `史記`・`詩経` を登録する。
- **柄（ファイル記述子）:** 行程ごとの柄表（8 本）→ 系統の開表（32 項）→ 実体（盤・典籍）の 3 段（`kernel/vfs/handle.mkn`）。
  `開`（番11）が名前を探して開表項を作り、呼出側の空き柄（3 以上で最小）を返す。同じ典籍を 2 回開くと柄も位置も別々。
  `讀入`（番13）と `柄書`（番14）は開表項の位置から読み書きする。柄 `0` は盤の入力（UART）、`1`/`2` は盤の出力で、
  起動時に各行程へ与える。`閉`（番12）は柄 3 以上だけ閉じられる。`終行程` で行程の柄をすべて閉じる。
  柄表・開表が満杯なら `-EMFILE`。殻は装置とファイルを同じ柄で扱える。
- **一覧と作成:** `目録`（番15）が目録の名前を返し、`創`（番16）が典籍を作る（既存なら内容を空にする）。
- **削除:** `削`（番24）が名前の典籍を削る。枠は名前長 0 の墓標にし、`創` が再利用する。
  `目録` は墓標を数えない。目録の開数（その典籍を指す開表項の数）が 0 でなければ `-EBUSY`。
- **誤り:** 無い名前は `-ENOENT`、閉じた柄は `-EBADF`、窓外・長過は `-EFAULT`、目録が満杯は `-ENOSPC`。
  核が EL1 から民の頁へ書くため、`讀入` の宛先は `備宛`（窓内・`令長限` 以内を確認し `給頁` で先に張る）を通す。
- **漢文シェル（殻）:** 殻行程（乙）が init 兼 殻として動き、UART から一行ずつ読んで命令を実行する。`終` では行程を終了せず、新しい殻を起動する。
  端末の Enter（CR）も LF も受け付け、入力は反響する。命令は [shell-commands.md](shell-commands.md)。

## 暫定アセンブリと C 実装

暫定 AArch64 アセンブリは次に限定する。

| ファイル | 役割 |
|---|---|
| `kernel/boot.S` | スタック設定・BSS 零化・`VBAR_EL1` 設定 |
| `kernel/vectors.S` | 例外ベクタ表とレジスタ保存 |
| `kernel/sysreg.S` | システムレジスタ操作（MMU・タイマー・割込制御） |
| `kernel/el0.S` | EL0 遷移・SVC 境界・下位EL IRQ 入口 |

`boot/uart.c` の C 版ドライバは `外術曰` 連携の後方互換・参照用に残している。旧起動スタブ `boot/boot.S` は
Phase 0 の参照用。VFS は `kernel/vfs/` に分割済み（下記）。

## ソースの分割と展開（`kernel/vfs/`）

コンパイラ（言語 v0.1）にはモジュールや取込が無い。そこで、ビルド時の前処理で複数ファイルを 1 つにつなぐ。

- `kernel/kernel.mkn` の `註 @取込 相対パス` という**コメント行**を、`tools/kernel-expand.sh` が指定ファイルの内容で置き換える（入れ子可）。
  コンパイラはこの行を単なるコメントとして読むので、言語や仕様は変えていない。
- 現在の分割: `kernel/vfs/const.mkn`（篇藏と柄表の定数）、`kernel/vfs/pian.mkn`（篇藏: 篇表・章・パス解決・`籍入`〜`籍目`・名替・屬・權・章移）、`kernel/vfs/handle.mkn`（柄表・開表と読み書き）。
- `make test` は展開結果 `tests/output/kernel_all.mkn` をコンパイルする。**展開前の `kernel/kernel.mkn` を直接コンパイルしても通らない**（関数が足りない）。
- 診断の行番号は展開後のもの。元の位置へ戻すには:

```sh
sh tools/kernel-line.sh tests/output/kernel_all.mkn.map <展開後の行番号>   # 例: kernel/vfs/pian.mkn:195
```

- 展開後のソースは分割前とバイト単位で同一であることを確認した（IR も同じ）。将来、言語に取込構文を入れるときは、この分割をそのまま移せる。
