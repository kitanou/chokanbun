# 超漢文OS 詳細設計 v0.2 — 以前の「機械漢文OS」記事を反映

## 基本理念
- 萬物皆文: ファイル、装置、行程情報を統一名前空間で表現する（全てを通常ファイルと同一視する意味ではない）。
- 百官各司: 官司ごとに責務と境界を明確化する。
- 令出必行: 漢令の意味・型・失敗条件を規範的に定義する。
- 異常必奏: エラーを明示的に返し、診断情報を失わない。

## 用語と実装
| 名称 | 役割 | 配置 |
|---|---|---|
| 漢極 | モノリシックカーネル | kernel/ |
| 漢殻 | シェル | userland/shell/ |
| 漢令 | システムAPIと命令定義 | runtime/abi/ |
| 天道 | スケジューラ | kernel/scheduler/ |
| 戶籍 | 行程管理 | kernel/process/ |
| 度支 | 物理・仮想記憶管理 | kernel/memory/ |
| 典籍 | VFS・ファイル | kernel/vfs/ |
| 驛傳 | IPC・pipe | kernel/ipc/ |
| 刑律 | 権限・エラー体系 | kernel/security/ |
| 百官 | UART、GIC、タイマー、virtio等ドライバ | kernel/drivers/ |

これらはソースコード内のモジュール名にも対応する。実行時のメモリレイアウトは通常のバイナリ形式を使用する。

## 言語とシェルを分離する
- 「機械漢文」: カーネルを記述するコンパイル言語。静的型、ポインタ、構造体、volatile、例外なしのfreestanding実行、ABIを定義。
- 「漢殻文法」: パイプ・リダイレクト・コマンドを扱うシェルDSL。言語構文と混同しない。
- 「漢令」: 両者をつなぐ型付きシステムAPI。ユーザーランドでのコマンド名とカーネル内syscall番号を分離する。

## シェルの文法 v0.1
```ebnf
pipeline    = command, { "傳", command }, [ redirect ] ;
redirect    = "奏入", string ;
command     = verb, { argument } ;
verb        = "讀" | "索" | "列" | identifier ;
argument    = string | identifier ;
string      = "「", { unicode_scalar_except_closing_bracket }, "」" ;
```
例: `讀「史記」 傳 索「項羽」 奏入「結果」`
- `讀`: 入力ファイルを開き内容をstdoutへ転送するユーザーランドコマンド。
- `索`: stdinを受けて一致行をstdoutへ送るユーザーランドコマンド。
- `傳`: pipe生成・接続のシェル構文。
- `奏入`: open/truncate/create + dup2に相当するリダイレクト構文。
- `奏` はstdout、`訴` はstderrへの出力API。
- `列` はディレクトリ一覧コマンド。
- 終了時の `天下太平` はシェル表示案であり、終了ステータス0とは別概念。

## システムコールの設計
- 初期syscall: `開`, `閉`, `讀入`, `書出`, `生行程`, `待行程`, `終行程`, `造管`, `複寫柄`。
- syscall ABI案: x8=番号、x0..x5=引数、x0=戻り値、svc #0。
- エラー: カーネル内部は Result<T, 錯> 型を使用。syscall境界では負のerrno番号を返し、libc互換層で-1とerrnoへ変換する。
- 例: ENOENT → `無此文件`。診断文はローカライズ可能、数値エラーコードは安定させる。
- forkとexecは後期マイルストーン。初期は単純なspawnを優先する。

## カーネル内部データ構造案
```text
構「行程」
    「識別」之無符六四
    「状態」之行程態
    「頁表根」之物理址
    「柄表」之指標〈文件柄表〉
終構
```
これは言語構文の草案であり、まだコンパイルできない。

## QEMU/ARM64
- QEMU virt + 明示的なAArch64 CPU（例: cortex-a57）。
- ベアメタルELF起動を選び、DTBの所在と起動時例外レベルを検証。
- QEMU virtはRAM開始0x40000000を保証するが、UART等のデバイスアドレスはDTBから取得する。
- ブートの最小アセンブリを許容し、kernel main・UART制御は機械漢文で実装。
- 例外/割込のレジスタ保存は低水準機械漢文機能を設計するまでアセンブリを許容。

## 内部IR
- AST → 型付き機械漢文IR → LLVM IR → AArch64。
- NF/SCF/SeCFは自然言語の意味圧縮研究の表現。プログラム意味論・型・副作用・メモリ順序を保証するコンパイラIRと同一視しない。
- 将来、宣言的仕様の正規化にNF/SCF/SeCFの知見を適用する場合も、コード生成前に厳格な型検査を通す。
