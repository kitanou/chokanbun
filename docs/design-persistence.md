# 篇藏の永続化 設計書 (F5 の最初の段階)

状態: **設計と最初の実装**。対象は篇藏（[design-pianfs.md](design-pianfs.md)）と、録層（BTRON3 の RAM ファイルシステム = FS 0）。録層は版 2 から同じスロット・同じ世代・同じチェックサムに載せた（§3、§9）。版 3 で篇の時刻副表（`作時`・`改時`）も同じチェックサムに載せた。
装置は virtio-blk の `vda`（`kernel/proc/blk.mkn`、1.8 のユニット）。

## 1. 方針

- **チェックポイント方式**: 篇藏の状態全体を、ディスクの 2 つのスロットの片方へ書き出す。ジャーナルや差分は使わない。
- **クラッシュ整合性**: データ（表と本文）を先に書き、**最後にヘッダの区画を書く**。ヘッダに世代とチェックサムを持たせる。読み込み時は 2 スロットのヘッダと中身を検証し、**世代が最も大きい正しいスロット**を使う。書き込み中に止まっても、もう片方のスロットが無傷で残る。
- **いつ書くか**: 利用者（行程）が明示的に `篇同` を呼んだときだけ。自動では書かない（シャットダウンの仕組みが無いため）。
- **いつ読むか**: 起動時、篇藏の初期化の直後に、正しいスロットがあればその状態に置き換える。無ければ初期化したまま。

## 2. 何を書くか

篇藏の状態は、次の 4 つである。

| 状態 | 置き場所 | 書き方 |
|---|---|---|
| 篇のメタデータ表 | 核専用域 `0x403EC000`、64 B × 128 = 8 KiB | そのまま。ただし `頁` の欄（物理ページの番地）は読み込み時に取り直すので、書く側は番地そのものに意味を持たせない |
| 篇の時刻副表 | 核専用域 `0x403F4000`、16 B × 128 = 2 KiB（`作時` +0・`改時` +8） | そのまま。スロット末尾の 4 区画（+5153〜+5156）へ書く |
| 本文・章の表の頁 | 型が `文`・`章`・`志` の篇が 1 頁（4 KiB）ずつ持つ | 表の順に 4 KiB ずつ。`章` の頁は子の篇ID を持つだけなので番地に依らない |
| 次の篇ID、予約章の篇ID | `篇次址`（8 B）、`予址`（8 B × 7） | ヘッダの区画に書く |

型が `術`（埋め込みの漢像）・`器`（装置参照）の篇は頁を持たない（`頁` の欄は像番・装置）。そのまま表に書く。
**同じ核でなければ戻せない**（漢像の並びと予約章の篇ID が表に入っているため）。ヘッダに形式の版と、漢像の数を持たせて照合し、合わなければ読み込まない。さらに戻す前に、いまの起動で柄 0〜2 が指す `器/盤` の篇が、保存した表の同じ番号に、同じ篇ID の `器` としてあることを確かめ、違えば戻さない（核を作り直して起動時に作る順が変わると、コンソールを取り違えるため）。

行程ごとの現在章・開いている柄・開表は**書かない**（行程の状態であり、再起動で消える）。篇の表の `開数`（+40）は柄の数なので、**戻すときに全て 0 にし、`器/盤`（柄 0〜2）だけ 3 に戻す**（戻さないと、開いたまま保存した篇が二度と削れなくなる）。表の `改刻`（+48）は前の起動のタイマーの刻数で、今の起動の刻数より大きいことがある（時刻としては使わない）。

## 3. ディスクの配置

区画は 512 B。版 5 から篇の項目が 128 B、篇限が 256 件、本文が連続した複数頁になった。

| 区画 | 内容 |
|---|---|
| 0〜63 | 予約（装置の試験用。永続化は使わない） |
| 64〜8408 | スロット A（8345 区画） |
| 8409〜16753 | スロット B（8345 区画） |

スロットの中身（8345 区画）:

| 位置 | 内容 |
|---|---|
| +0 | ヘッダ（1 区画） |
| +1〜+64 | 篇の表（32 KiB = 64 区画。128 B × 256） |
| +65〜 | 篇の本文・章の表の頁。表の順に、頁を持つ篇だけ **頁数 × 8 区画**ずつ詰める（頁数は項目の +64。章は 1）。型 `録` の篇＝録層 FS 0 のファイルの本体もここに入る。合計 1024 頁（8192 区画）まで。超えると `篇同` は `-ENOSPC` |
| +8257〜 | 録層 FS 0 の件表（16 区画 = 32 件 × 256 B。本体の頁・使用量・頁数は件ではなく写しの篇が持つ） |
| +8273〜+8280 | 篇の時刻副表（4 KiB = 8 区画） |
| +8281〜+8344 | 篇の標の表（32 KiB = 64 区画） |

ヘッダ（512 B）:

| 欄 | 内容 |
|---|---|
| +0 | 識別 `PIAN`（0x4E414950） |
| +4 | 形式の版（3。版 1 = 篇藏のみ、版 2 = 録層まで。版 1・2 は読まれない） |
| +8 | 世代（u64。書くたびに +1。0 は無効） |
| +16 | 次の篇ID（u64） |
| +24 | 本文の頁の数（u32）。表の中の頁を持つ篇の数と一致しなければならない |
| +28 | 漢像の数（u32） |
| +32 | データ（表と頁）のチェックサム（u32） |
| +36 | ヘッダのチェックサム（u32。ヘッダの +0〜+35 と +40〜+127 に対するもの） |
| +40 | 録層 FS 0 の次のファイル ID（u64。FS 表 +40） |
| +48 | 録層の本体の頁の総数（u64。件表の使用中の項の容量の合計と一致しなければならない） |
| +64 | 予約章の篇ID（u64 × 7） |

チェックサムは FNV-1a の 32 ビット。

## 4. 書き込みの手順（`篇同`）

1. 装置が無ければ `-ENODEV`。
2. 書く先のスロット = 現在使っているスロットの反対側（最初は A）。世代 = 直近の世代 + 1。
3. 篇の表を 16 区画で書く。続いて頁を持つ篇それぞれの頁を 8 区画ずつ書く。表の `頁` の欄は、書く時点では 0 に置き換えたコピーのチェックサム対象にする（番地が毎回違うため）。続いて時刻副表 2 KiB を 4 区画で書き、チェックサムに含める。
4. 最後にヘッダの区画を書く。
5. 区画の書込みが 1 つでも失敗したら `-EIO` を返し、**ヘッダは書かない**（その世代は無効のまま）。

データを書き終えたら virtio-blk の FLUSH（type 4、機能ビット 9）を出して装置の記憶域へ届かせてから、ヘッダの区画を書き、もう一度 FLUSH を出す（`盤同`。装置が FLUSH を受け入れなければ何もしない）。ヘッダが先にホストへ届いて、途中で止まったときに壊れたデータの世代が有効に見えることを防ぐ。ヘッダは 1 区画で、チェックサムがあるので、途中までしか書けていなくても検出できる。QEMU がホストのキャッシュをどう扱うかの試験はしていない（FLUSH が出ること自体は、出したときに誤りを返す変異で試験が落ちることを確かめた）。

## 5. 読み込みの手順（起動時）

1. 装置が無ければ何もしない。
2. スロット A・B のヘッダを読む。識別・版・漢像の数・ヘッダのチェックサムが合うものだけを候補にする。
3. 候補をデータまで読み、チェックサムを検証する。表の `頁` の欄は 0 に置き換えて計算する。時刻副表は作業頁へ読み、篇表・頁・録層に続けてチェックサムに入れる。
4. 検証に通った候補のうち世代が大きい方を採る。両方だめなら何もしない（初期化した状態のまま）。
5. 採ったスロットから、表を篇表に写し、頁を持つ篇ごとに頁池から新しい頁を取って中身を写し、`頁` の欄を新しい番地にする。時刻副表も写す。頁が取れなければ、取った頁を全部返して何もしなかったことにする。
6. 次の篇ID と予約章の篇ID を戻す。直近の世代と使用中のスロットを覚える。

## 6. 上限と制約

- 篇 128 件、本文 1 件 4 KiB（design-pianfs.md F0〜F4 のまま）。スロットは最悪の場合に足りる大きさ（篇藏 1041 + 録層 4112 + 時刻副表 4 区画）にした。
- 装置の容量が 16754 区画（永基 64 + スロット 8345 × 2）より小さいと、永続化は使えず `篇同` は `-ENXIO`。定数（`永録起`・`永録表区`・`永録頁区`・`永時起`・`永時区`・`永間`・`永容限`）が篇限・録件数・録件幅・録本頁上と食い違うときも使わない（`永環` が確かめる）。
- 書き込み中の電源断・強制終了には耐える（もう片方のスロットが残る）が、**書き込み中に別の行程が篇藏を変える**ことは防いでいない（単一の CPU で漢令の中は割り込まれない前提）。
- ホスト側の書き込みの永続性（ホストのキャッシュ）は保証しない。QEMU が終了したあとにファイルを読み直せることは、試験で確かめる。
- 柄・行程の状態、録層の開表・ロック・写像、SYS（FS 1）は永続化しない（FS 1 は起動のたびに作り直す）。
- **対話からの使い方**: 殻の命令 `同` が `篇同` を呼ぶ。`make run` は `tests/output/run-disk.img`（12288 区画。`make test` は作り直さず、`make clean` で消える。4096 区画のまま残っていれば `make run` が中身を残して広げる）で起動するので、`同` で保存すると次の `make run` で戻る。装置が無い・容量が足りないとき `同` は `殻誤` を出す。 `make run` を標準入力から流し込む形で 2 回実行し、1 回目の `書 筆記 永続` と `同` で `殻同 保存した`、2 回目の起動で `篇戻 世代=1` と `讀 筆記` が `永続` を返すことを確かめた（人が端末で操作したのではなく、`run_tests.sh` に組み込んでもいない）。

## 7. 受入条件（QEMU で確認する）

- 一回目の起動: 篇を作って `篇同`。QEMU を止める。
- 二回目の起動（同じディスクイメージ）: 作った篇が目録に現れ、中身を読める。
- 破損: 片方のスロットのヘッダを壊しても、ヘッダは無傷でデータの区画だけを壊しても、もう片方から戻る。両方壊すと初期化した状態になる。
- 開いたまま保存した篇が、再起動のあと削れる（`開数` が残らない）。
- 装置が無いとき: 起動が止まらず、`篇同` が `-ENODEV`。

## 9. 録層（FS 0）と時刻副表の永続化（版 2・3）

- **何を書くか**: FS 0（`mem`）のファイル見出し表（`録件表`の 32 件 × 256 B）と、使用中の件ごとの本体（`+56` の頁から、容量 `+232`（0 は 1 頁）の頁数 × 4 KiB。連続した頁）。件の順に並べる。本体が 64 KiB（16 頁）までなので、表と合わせて最大 4112 区画。
- **チェックサム**: 篇藏のデータに続けて、同じ 1 つのチェックサムに入れる（表 → 本体 → 時刻副表の順）。件表の `+56`（本体の頁の番地）は番地そのものでなく「使用中なら 1」に置き換えて計算する（番地は起動ごとに違うため）。`+232`（容量）は値のまま。検証では、使用中の項の FS 番号が 0・容量が 1〜16 であること、頁数の合計がヘッダ `+48` と一致することも確かめる。
- **時刻副表（版 3）**: 篇の `作時`・`改時` の 16 B × 128 を、スロット末尾の 4 区画（+5153〜+5156）へそのまま書く。値は Unix 秒で、RTC 無効時の 0 もそのまま保存する。読み込み時は作業頁へ読んでチェックサムを検証し、頁の確保が全部成功した後に篇表と一緒に写す。
- **見出しに実行時だけの欄は無い**: 開いている状態（開表）・ロック・写像・作業ファイルは別の表にあり、見出しの `+0〜+255` は参照数（`+72`）も含めてすべて保存すべき値である（篇藏の `開数` のような欄は無い。`録件作`・開閉・写像・`xch_fil` の書込み先を確かめた）。
- **戻し方**: 篇藏と録層は、**起動時に 1 回だけ**検証して適用する（`録初期化`のあとで呼ぶ。`録初期化`は篇藏の状態を読まないので順序は問題ない）。篇藏の頁と録層の本体の連続頁を**先にすべて取り**、取れなければ取った分を返して何も変えず `録戻失敗` を出して初期化した状態のまま起動する（黙って失敗にしない）。取れたら、いまの FS 0 の本体を返してから件表を置き換え、本体を読み、`+56` を新しい番地にする。
- **FS 表の欄**: 次のファイル ID（`+40`）だけ戻す（戻さないと、消したファイルの ID が起動直後にまた割り当てられる）。モード（`+16`）・アクセス管理レベル（`+48`）・時刻・接続名・FS 名は起動時の値のまま（設定でなく構成として扱う。`chg_fsm` の変更は保存されない）。
- **版 1・2 のスナップショット**は読まれない（版 3 に上げた。ディスクに版 1・2 しか無ければ初期化した状態で起動する）。
- **試験**（`永試`）: F が 13 バイトと 6000 バイト（2 頁）のファイルと、作って消した一時のファイルを作る → 再起動して G が内容の一致を確かめ、新しいファイルの ID が戻したファイルとも消した一時のファイルとも重ならないことを確かめる → 保存し直して H が新しいファイルの復元を確かめる → 最新のスロットの録層の区画を壊すと世代の古い方から戻る → 全部壊すと録層も初期化した状態（M）。`問安` が戻したあとも起動できる（FS 1 が無傷）。次の ID の復元・本体のチェックサムは、それぞれを外すと試験が落ちることを確かめた。篇「永」の `作時` は F と R と世代 2 からの R で同じ値を照合し、時刻副表が再起動・世代交代をまたいで保たれることを確かめる。
- **試験していない**: 連続頁が取れない状態での `録戻失敗` の経路（コードは巻き戻しを持つが、断片化した頁池は作っていない）。

## 10. 標の表（版 4）

篇ごとの標（4 組 × 鍵 16 B・値 16 B、`kernel/vfs/tag.mkn`）の表 16 KiB を、時刻副表の直後（+5157〜+5188）へそのまま書く。同じ世代のチェックサムに、時刻副表の次に含める。検証は作業頁へ 1 区画ずつ読んでチェックサムに連ね、適用は検証済みのスロットから標の表へ直接読む（読めなければ標だけ空にして、篇と時刻は戻す）。版 3 以前のスナップショットは読まない（版 4 に上げた）。
**試験**（`永試`）: 篇「永」に標 `ptag=kept` を置いて保存（`W`）→ 再起動して標が読め、`索` が標の鍵と値でその篇だけを返す（`S`）。

## 11. 篇の本文が複数頁（版 5）

篇（文・志）の本文は連続した最大 16 頁（64 KiB）になった。項目の +64 が頁数で、足りなくなると倍に取り直して移す（`篇本伸`）。永続化は頁を持つ篇ごとに頁数 × 8 区画を書き、検証は表の頁数の合計（上限 512 頁）と各篇の頁数（上限 16）を確かめる。戻すときは篇ごとに連続した頁を先に全部取り、取れなければ取った分を返して何も変えない。篇の項目は 128 B に広がり（+72〜+127 は予約）、篇限は 256 件になった。表は核の EL1 専用域 0x40440000（篇）・0x40448000（時刻）・0x40450000（標）・0x40458000（索の作業域）へ移した。版 4 以前のスナップショットは読まない。
**試験**: `篇試`（12000 B を 3 回に分けて書き、屬の大きさと読み戻し）、`永試`（`W大` で保存の前に 12000 B を書き、再起動後に `V` で一致を確かめる）。

## 12. 録層の本体は篇の本文（版 6）

録層 FS 0 のファイルの本体は、写しの篇（型 `録`）の本文になった（篇の +24 が頁、+16 が使用量、+64 が頁数。件の +240 に篇ID、+248 に篇の番号 + 1）。このため永続化は録層の本体の区画を別に持たず、篇の本文の区画（§3）に入れる。件表だけを 16 区画で保存し、読み込みでは各件の FS 番号 0・篇の番号が範囲内であることを確かめる。スロットの大きさは変わらない（8345 区画。録層の本体用だった 4096 区画を篇の本文へ回した）。版 5 以前は読まない。

## 13. 差分書き込み

`篇同` は、保存する状態を 4 KiB の塊（篇の表 8・篇の本文の頁・録層の件表 2・時刻副表 1・標の表 8）に分け、塊ごとの 64 ビットのハッシュ（`塊雑`）を、書き込み先のスロットごとに `0x40460000`（スロット 1 は +0x4000）へ覚える。書き込み先のスロットで同じ位置の塊のハッシュが同じなら、その 8 区画を書かない。ヘッダ（世代とチェックサム）は毎回書く。

- **一貫性**: 書き込み先は世代の古い方のスロットで、ヘッダを最後に書くのは従来どおり。途中で止まっても、最新の正しい世代のスロットは無傷（これがジャーナルの代わり）。ハッシュは区画を書いたあとにだけ更新する。
- **起動直後**: ハッシュは「不明」（0）なので、各スロットへの最初の保存は全塊を書く。
- **限界**: 篇の本文の頁は表の順に詰めるので、前の方の篇が大きさを変えたり消えたりすると、後ろの頁の塊の位置がずれて余分に書く。チェックサム（全体）は毎回全部を読んで計算する。
- **統計**: 診断の漢令 232（x0=0 書いた塊の数、1 書かずに済ませた塊の数）。
- **試験**（`永試 Y`・`Z`）: 1 回目と 2 回目は 31 塊すべて、同じ状態の 3 回目は 0 塊、篇「永差」を足した 4 回目は 8 塊。再起動して篇「永差」が読める。
