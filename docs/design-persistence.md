# 篇藏の永続化 設計書 (F5 の最初の段階)

状態: **設計と最初の実装**。対象は篇藏（[design-pianfs.md](design-pianfs.md)）。録層（BTRON3 の RAM ファイルシステム）は対象外で、あとから同じ仕組みに載せる。
装置は virtio-blk の `vda`（`kernel/proc/blk.mkn`、1.8 のユニット）。

## 1. 方針

- **チェックポイント方式**: 篇藏の状態全体を、ディスクの 2 つのスロットの片方へ書き出す。ジャーナルや差分は使わない。
- **クラッシュ整合性**: データ（表と本文）を先に書き、**最後にヘッダの区画を書く**。ヘッダに世代とチェックサムを持たせる。読み込み時は 2 スロットのヘッダと中身を検証し、**世代が最も大きい正しいスロット**を使う。書き込み中に止まっても、もう片方のスロットが無傷で残る。
- **いつ書くか**: 利用者（行程）が明示的に `篇同` を呼んだときだけ。自動では書かない（シャットダウンの仕組みが無いため）。
- **いつ読むか**: 起動時、篇藏の初期化の直後に、正しいスロットがあればその状態に置き換える。無ければ初期化したまま。

## 2. 何を書くか

篇藏の状態は、次の 3 つである。

| 状態 | 置き場所 | 書き方 |
|---|---|---|
| 篇のメタデータ表 | 核専用域 `0x403EC000`、64 B × 128 = 8 KiB | そのまま。ただし `頁` の欄（物理ページの番地）は読み込み時に取り直すので、書く側は番地そのものに意味を持たせない |
| 本文・章の表の頁 | 型が `文`・`章`・`志` の篇が 1 頁（4 KiB）ずつ持つ | 表の順に 4 KiB ずつ。`章` の頁は子の篇ID を持つだけなので番地に依らない |
| 次の篇ID、予約章の篇ID | `篇次址`（8 B）、`予址`（8 B × 7） | ヘッダの区画に書く |

型が `術`（埋め込みの漢像）・`器`（装置参照）の篇は頁を持たない（`頁` の欄は像番・装置）。そのまま表に書く。
**同じ核でなければ戻せない**（漢像の並びと予約章の篇ID が表に入っているため）。ヘッダに形式の版と、漢像の数を持たせて照合し、合わなければ読み込まない。

行程ごとの現在章・開いている柄・開表は**書かない**（行程の状態であり、再起動で消える）。

## 3. ディスクの配置

区画は 512 B。

| 区画 | 内容 |
|---|---|
| 0〜63 | 予約（装置の試験用。永続化は使わない） |
| 64〜 | スロット A（1056 区画） |
| 1120〜 | スロット B（1056 区画） |

スロットの中身（1056 区画）:

| 位置 | 内容 |
|---|---|
| +0 | ヘッダ（1 区画） |
| +1〜+16 | 篇の表（8 KiB = 16 区画） |
| +17〜 | 本文・章の頁。表の順に、頁を持つ篇だけ 8 区画ずつ（最大 128 件 × 8 = 1024 区画） |

ヘッダ（512 B）:

| 欄 | 内容 |
|---|---|
| +0 | 識別 `PIAN`（0x4E414950） |
| +4 | 形式の版（1） |
| +8 | 世代（u64。書くたびに +1。0 は無効） |
| +16 | 次の篇ID（u64） |
| +24 | 本文の頁の数（u32）。表の中の頁を持つ篇の数と一致しなければならない |
| +28 | 漢像の数（u32） |
| +32 | データ（表と頁）のチェックサム（u32） |
| +36 | ヘッダのチェックサム（u32。ヘッダの +0〜+35 と +64〜+127 に対するもの） |
| +64 | 予約章の篇ID（u64 × 7） |

チェックサムは FNV-1a の 32 ビット。

## 4. 書き込みの手順（`篇同`）

1. 装置が無ければ `-ENODEV`。
2. 書く先のスロット = 現在使っているスロットの反対側（最初は A）。世代 = 直近の世代 + 1。
3. 篇の表を 16 区画で書く。続いて頁を持つ篇それぞれの頁を 8 区画ずつ書く。書きながらチェックサムを更新する。表の `頁` の欄は、書く時点では 0 に置き換えたコピーのチェックサム対象にする（番地が毎回違うため）。
4. 最後にヘッダの区画を書く。
5. 区画の書込みが 1 つでも失敗したら `-EIO` を返し、**ヘッダは書かない**（その世代は無効のまま）。

virtio-blk に flush は使わない（ホストのファイルへ順に書かれる）。順序は「データ → ヘッダ」だけに頼る。ヘッダは 1 区画で、チェックサムがあるので、途中までしか書けていなくても検出できる。

## 5. 読み込みの手順（起動時）

1. 装置が無ければ何もしない。
2. スロット A・B のヘッダを読む。識別・版・漢像の数・ヘッダのチェックサムが合うものだけを候補にする。
3. 候補をデータまで読み、チェックサムを検証する。表の `頁` の欄は 0 に置き換えて計算する。
4. 検証に通った候補のうち世代が大きい方を採る。両方だめなら何もしない（初期化した状態のまま）。
5. 採ったスロットから、表を篇表に写し、頁を持つ篇ごとに頁池から新しい頁を取って中身を写し、`頁` の欄を新しい番地にする。頁が取れなければ、取った頁を全部返して何もしなかったことにする。
6. 次の篇ID と予約章の篇ID を戻す。直近の世代と使用中のスロットを覚える。

## 6. 上限と制約

- 篇 128 件、本文 1 件 4 KiB（design-pianfs.md F0〜F4 のまま）。スロットは最悪の場合に足りる大きさ（1056 区画）にした。
- 装置の容量が 2304 区画（64 + 1056 × 2 = 2176 に余裕を足した値）より小さいと、永続化は使えず `篇同` は `-ENODEV`。
- 書き込み中の電源断・強制終了には耐える（もう片方のスロットが残る）が、**書き込み中に別の行程が篇藏を変える**ことは防いでいない（単一の CPU で漢令の中は割り込まれない前提）。
- ホスト側の書き込みの永続性（ホストのキャッシュ）は保証しない。QEMU が終了したあとにファイルを読み直せることは、試験で確かめる。
- 録層・柄・行程の状態は永続化しない。

## 7. 受入条件（QEMU で確認する）

- 一回目の起動: 篇を作って `篇同`。QEMU を止める。
- 二回目の起動（同じディスクイメージ）: 作った篇が目録に現れ、中身を読める。
- 破損: 片方のスロットのヘッダを壊しても、もう片方から戻る。両方壊すと初期化した状態になる。
- 装置が無いとき: 起動が止まらず、`篇同` が `-ENODEV`。

## 8. 将来

- 録層（BTRON3 の RAM ファイルシステム）の永続化。同じスロットに第 2 の領域を足すか、別のスロット組にする。
- 差分書き込み、ジャーナル、書き込み中の保護、フラッシュの発行。
- 複数の装置、装置の選択。
