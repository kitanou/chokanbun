## 1. 位置づけ

篇藏は、既存の VFS/RAMFS（**典籍**）を置き換える別実装ではない。典籍の上に、超漢文固有の
**概念・名前空間・操作の体系**を段階的に載せる設計である。

- 現在の典籍: 平坦な名前（16 バイト以内）、最大 8 件、本文 256 バイト、RAM のみ。
- 篇藏 v0.1 が定義するもの: 篇（ファイル）の識別とメタデータ、章（名前空間）、権限、パス解決、操作の意味、索（検索）。

### LLM 非依存の原則

- LLM 連携・自然言語による FS 操作・埋め込み／意味検索・LLM による操作計画生成は**スコープ外**。
- 作成・読み取り・書き込み・移動・複製・削除・検索・権限検査は、**明示的な構文と決定的なコード**で行う。
- 検索は名前・パス・型・明示タグなど、再現可能な条件だけを使う。
- 篇藏は LLM が使えなくても完全に機能する。LLM を載せる場合も、通常の漢令を呼ぶ一利用者として扱う。

## 2. 概念

| 用語 | 意味 | v0.1 の扱い |
|---|---|---|
| 篇 | ファイル相当のデータ実体 | **実装対象**。篇ID・型・大きさ・所有者・権限を持つ |
| 章 | 篇を分類する名前空間（ディレクトリ相当） | **実装対象**。章も篇の一種（型 `章`）で、子の名前から篇IDへの表を持つ |
| 句 | 文書や構造化データの論理単位 | **定義のみ（§9）**。FS コアは中身の形式を解析しない |
| 索 | 名前・パス・型・タグによる決定的な検索 | **実装対象（最終段）** |

## 3. 篇

### 3.1 篇ID

- 64 ビット整数。篇を作るたびに 1 ずつ増え、**再利用しない**（削除した篇の ID は二度と別の篇に付かない）。
- 0 は無効、1 は根の章 `天地`。

### 3.2 メタデータ

| 項目 | 型 | 意味 |
|---|---|---|
| `識` | u64 | 篇ID |
| `型` | u8 | `文`（バイト列）・`章`（名前空間）・`器`（資源参照）・`術`（実行イメージ、[design-process-exec.md](design-process-exec.md) の漢像）・`志`（追記専用の記録）・`録`（BTRON3 のレコード列ファイル。中身は録層だけが解釈する。[compat/btron3-file-design.md](compat/btron3-file-design.md)） |
| `大` | u64 | 本文の大きさ（バイト） |
| `主` | u32 | 所有者（利用者番号）。v0.1 は単一利用者で常に 0 |
| `權` | u16 | 権限ビット（§6） |
| `標` | 4 組 | 明示タグ。各組は鍵と値（それぞれ 16 バイト以内）。0〜4 個 |
| `創`/`改` | u64 | 作成・最終変更のタイマー刻（時刻ではなく単調な刻数） |

メタデータは**本文と別の表**に置く。これにより一覧・検索で本文を読まずに済む。

### 3.3 本文

v0.1 は「連続したバイト列」とする。上限は段階ごとに引き上げる（§10）。位置と読み書きの意味は現在の `讀入`/`柄書` と同じ。

## 4. 章と名前空間

### 4.1 パス

- 区切りは ASCII の `/`。区切りで分けた各要素を**名**と呼ぶ。
- 名は UTF-8（NFC 正規化済みを前提とし、比較はバイト列の完全一致）。長さは 1〜**32 バイト**。
- 名に使えない: `/`、NUL、制御文字（0x00–0x1F, 0x7F）。`.` と `..` は予約（現在の章・親の章。根の `..` は根）。
- 絶対パスは `天地` から始める（例: `天地/家/筆記`）。`/` で始まる場合は無視する（`/天地/家` = `天地/家`）。
- パス全体の長さは 128 バイト、深さは 8 まで。
- 相対パスは**行程の現在章**から解決する（行程表に `現章` を持つ。初期値は `天地/家`）。

### 4.2 予約された名前空間

根 `天地` の直下に、起動時に核が次の章を作る。利用者は削除・名替できない。

| 章 | 用途 | 型の制約 | 備考 |
|---|---|---|---|
| `家` | 利用者データ | 制約なし | 既定の現在章 |
| `典` | 文書 | `文` `章` | 起動時に登録する資料（現在の `史記`・`詩経` の行き先） |
| `法` | 設定 | `文` `章` | 起動後は特権行程のみ書き込み可（§6） |
| `器` | 装置・資源への参照 | `器` のみ（核だけが作る） | コンソール（`器/盤`）など |
| `術` | 実行プログラム | `術` `章` | 外部命令の置き場。`生行程`/`換行程` はここを探す |
| `志` | 記録 | `志` `章` | 追記専用（§6） |

利用者が新しい予約名を作ることはできない。予約名の追加は仕様の改定で行う。

### 4.3 資源参照の安全性（`器`）

- `器` の篇は**核だけが作る**。利用者は作成・削除できない。
- 本文を持たず、開くと核内の装置オブジェクトへの参照になる。生の物理アドレス・MMIO アドレスは**利用者に見せない**。
- 開くときは通常の権限検査（§6）を受ける。柄 0/1/2 は起動時に `器/盤` を開いたものとして定義する（現在の「柄 0/1/2 はコンソール」と同じ結果になる）。
- 装置の操作は `讀入`/`柄書`、必要なら別の漢令で行い、`器` の篇の型と意味は装置ごとに仕様化する。

## 5. VFS への対応

篇藏の概念は、既存の VFS 層（柄表 → 開表 → 実体）に次のように載せる。

| 篇藏 | VFS・既存の仕組み |
|---|---|
| 篇 | 実体（開表の「籍」の対象）。目録の 1 項目が篇のメタデータになる |
| 章 | 型 `章` の篇。本文が「名 → 篇ID」の表（1 項目 = 名 32 B + 篇ID 8 B） |
| 開く | パス解決 → 篇ID → 権限検査 → 開表に項目を追加 → 柄を返す |
| 柄の位置 | 開表が持つ（現在は目録側。[design-process-exec.md](design-process-exec.md) §6 の移行と同時に行う） |

### 5.1 現在の典籍との互換

- 現在の名前（`史記` など、`/` を含まない）は、**現在章**からの相対パスとして解決する。
- 移行期間の既定の現在章を `天地/典` にすれば、既存の殻・テストの `讀 史記`・`讀 詩経` はそのまま動く。
  利用者が `書` で作る篇は、現在章（`天地/家`）に置くか `典` に置くかを実装時に決める（未決 §11）。
- 既存の漢令（開・閉・讀入・柄書・目録・創）の**番号と引数は変えない**。意味だけを上の規則に沿って拡張する。

### 5.2 解決の手順（決定的）

1. パスを `/` で分け、各名を検査する（長さ・文字）。
2. 先頭が予約名 `天地` なら根から、そうでなければ現在章から始める。
3. 要素ごとに、現在の章の表を**名の完全一致**で引く。無ければ `-ENOENT`。途中の要素が `章` でなければ `-ENOTDIR`。
4. 各章に入る前に「行」権限（探索可否）を検査し、無ければ `-EACCES`。
5. 最後の要素の篇IDを返す。同じパスは同じ篇IDに解決される（曖昧さを持たない）。

## 6. 権限

利用者が 1 人の間は検査を空にするが、**検査の位置と意味**は今から定義しておく。

- 権限ビットは 主・他 の 2 区分 × 3 種（`讀`・`寫`・`行`）の 6 ビット。章に対する `讀` は一覧、`寫` は作成・削除・名替、`行` は経路としての通過。
- `術` の篇を `生行程`/`換行程` で実行するには、その篇に `行` が要る。
- 型ごとの固定規則（権限ビットより優先）:
  - `志`: **追記専用**。`柄書` は常に末尾に付け、位置の指定・切り詰め・削除はできない。
  - `器`: 利用者は作成・削除できない。
  - `法`: 特権行程（初期は init のみ）以外は書き込めない。
- 検査は**核が漢令の入口で 1 回**行う（柄を開く時点）。開いた後は柄が持つ権限（読み／書き／追記）で判断する。
- 失敗は `-EACCES`。

## 7. 操作と漢令（追加案）

[design-process-exec.md](design-process-exec.md) が 17〜23 を使うので、24 以降を割り当てる。

| 番号 | 名 | 引数 | 戻り値 |
|---|---|---|---|
| 24 | 削 | パス | 0 ／ `-ENOENT` `-EACCES` `-ENOTEMPTY` `-EBUSY` |
| 25 | 名替 | 旧パス, 新パス | 0 ／ `-ENOENT` `-EEXIST` `-EACCES` `-EXDEV` |
| 26 | 屬 | パス, 宛 | 0（宛にメタデータを書く）／ `-ENOENT` `-EFAULT` |
| 27 | 權 | パス, 權 | 0 ／ `-ENOENT` `-EACCES` |
| 28 | 章作 | パス | 0 ／ `-EEXIST` `-ENOENT` `-ENOSPC` |
| 29 | 標 | パス, 鍵, 値 | 0（値が空なら標を外す）／ `-ENOSPC` |
| 30 | 索 | 条件, 宛, 長 | 一致した篇の数（§8） |

既存の `開`(11)・`創`(16)・`目録`(15) は、パス解決・メタデータを使う形に拡張する（引数の形は同じ）。
`複`（複製）は殻のコマンドとして `開`+`讀入`+`創`+`柄書` で組み立てられるので、独立の漢令にしない。

### 7.1 各操作の意味

- **削**: 篇を章の表から外す。`章` は空でなければ `-ENOTEMPTY`。開かれている篇は `-EBUSY`（v0.1）。篇IDは再利用しない。
- **名替**: 同じ篇の名と親を変える。同じ篇藏の中だけ（`-EXDEV` は将来の複数の記憶装置用）。新しい名が既にあれば `-EEXIST`（上書きしない）。`天地` 配下の予約章は動かせない。
- **創**: 既にあれば内容を空にする（現在と同じ）。権限と所有者は維持する。
- **目録**: 章の子を、**名のバイト列の昇順**で返す（実装ごとの順序の違いを無くす）。

### 7.2 誤り番号（追加）

`-EACCES`(13)・`-EBUSY`(16)・`-EEXIST`(17)・`-ENOTDIR`(20)・`-EISDIR`(21)・`-ENAMETOOLONG`(36)・`-ENOTEMPTY`(39)・`-EXDEV`(18)。
既存の `-ENOENT`(2)・`-EBADF`(9)・`-EFAULT`(14)・`-ENOSPC`(28)・`-ENOSYS`(38) と合わせ、ABI 表に載せる。

## 8. 索（検索）

検索は**決定的**な条件だけを許す。

- 条件の要素（すべて AND）: 名の前方一致、名の完全一致、型の一致、標（鍵と値の完全一致）、章の範囲（その章の直下／配下）。
- 結果は**パスのバイト列昇順**。同じ状態に同じ条件なら必ず同じ結果になる。
- 本文の内容は検索しない。曖昧一致・意味検索・順位づけは行わない。
- 索引は篇の作成・削除・名替・標の変更のたびに核が同期して更新する（v0.1 は全走査でよい。篇は最大 128 件）。

## 9. 句（定義のみ）

句は「文書や構造化データの論理単位」で、**FS コアは句の中身を解析しない**。

- v0.1 では実装しない。将来の入り口として、篇の本文上の**バイト範囲**（開始・長さ）に名前を付ける「句表」を篇ごとに持てる形を予約する。
- 句の境界の決め方（改行・`。`・利用者の指定など）は利用者側の規約で、FS は範囲を保存して返すだけにする。
- 句を使う操作も、検索と同じく決定的な条件（名・範囲）だけで行う。

## 13. 実装で決めたこと（F0〜F3）

### 13.1 表と上限

| 項目 | 値・置き場所 |
|---|---|
| 篇表 | 核専用域 0x403EC000、64 B × 128 件（識・型・大・頁・權・開数・改刻・親の識） |
| 時刻副表 | 核専用域 0x403F4000、16 B × 128 件（作時 +0・改時 +8。Unix 秒の `有符六四`） |
| 本文・章の表 | 頁池の頁 1 枚（4 KiB）。章の子は 48 B × 32 件（名長・子の識・名 32 B） |
| 現在章 | 行程ごとに篇ID（0x403EE000）。起動時は全行程 `天地/典`、子は親から継ぐ |
| 名・パス・深さ | 名 1〜32 バイト（制御文字不可）、パス 128 バイト、根の下 8 段 |
| 篇ID | 1 から単調増加、再利用しない。根 `天地` は 1 |

### 13.2 漢令

既存の番号と引数は変えず、名前をパスとして解決する（`開` 11・`目録` 15・`創` 16・`削` 24）。追加は次のとおり。§7 の案から、現在章の変更と取得に **32・33** を割り当て、時刻副表の取得に **34** を追加した（29 `標`・30 `索` は F4 のため空けておく）。

| 番号 | 名 | 引数 | 戻り値 |
|---|---|---|---|
| 25 | 名替 | 旧パス, 長, 新パス, 長 | 0 ／ `-ENOENT` `-EEXIST` `-EACCES` `-EINVAL`（章を自分の下へ） `-ENAMETOOLONG` |
| 26 | 屬 | パス, 長, 宛（40 B: 識・型・大・權・開数） | 0 ／ `-ENOENT` `-EFAULT` |
| 27 | 權 | パス, 長, 權（0〜63） | 0 ／ `-ENOENT` `-EINVAL` |
| 28 | 章作 | パス, 長 | 0 ／ `-EEXIST` `-ENOENT` `-EACCES` `-ENAMETOOLONG` `-ENOSPC` |
| 32 | 章移 | パス, 長 | 0 ／ `-ENOENT` `-ENOTDIR` `-EACCES` |
| 33 | 章名 | 宛, 長 | 現在章の絶対パスの長さ（`天地/…`） |
| 34 | 篇時 | パス, 長, 宛（16 B） | 0 ／ `-ENOENT` `-EACCES` `-EFAULT`。宛に `作時`・`改時`（Unix 秒 i64）を書く |

型の値: 1=`文`、2=`章`、3=`器`、4=`術`、5=`志`。權のビット: 主の讀・寫・行 = 0x20・0x10・0x08、他 = 0x04・0x02・0x01。既定は `文`・`志`・`器` が 0x36、`章` が 0x3F、`術` が 0x2D。

### 13.3 規則の具体化

- **権限の検査**: 利用者は 1 人（すべての行程が主）なので、主のビットで判定する。章を通るには `行`、目録には `讀`、作成・削除・名替には親の章の `寫` が要る。開くときに `讀`・`寫` の権利を柄へ写し、`讀入`・`柄書` は柄の権利で判定する（開いた後に權を変えても、その柄には効かない）。
- **予約章**: 根の直下（`家`・`典`・`法`・`器`・`術`・`志`）は削除・名替できず、根の直下に新しい名は作れない（`-EACCES`）。
- **`志`**: `天地/志` の下で `創` すると `志` になる。`柄書` は位置に関わらず末尾へ追記する。既存の `志` を `創` で空にすること、`削` することはできない。
- **`器`**: `天地/器` の下には作れず、`器` の篇は削除・名替できない。起動時に `器/盤` を作り、開表の 0/1/2（柄 0/1/2）の対象を `器/盤` にした。`開 天地/器/盤` は盤の柄（讀は UART 受信、寫は UART 送信）になる。
- **`術`**: 起動時に、埋め込みの漢像を `天地/術` の `術` として登録する（本文は持たず、漢像の番号を持つ）。`生行程` は名前に `/` が無ければ `天地/術` から、あればパスとして探し、`行` が無ければ `-EACCES`。`術` の篇は `開` できない。`天地/術` の下に利用者が作れるのは章だけ。
- **`法`**: 利用者レベル（BTRON3 互換層の `P_USER`）が 0 の行程だけが、`天地/法` の下へ作成・削除・名替・書込できる（起動時は全行程が 0）。
- **削除の条件**: 開かれている篇、空でない章、どれかの行程の現在章になっている章は削れない（`-EBUSY`/`-ENOTEMPTY`）。
- **目録**: 現在章の子を名のバイト列の昇順で返す（序 番目に小さい名）。
- **時刻**: `改刻` は核のタイマー刻（単調）。暦の時刻ではない（§3.2 のとおり）。黄帝紀元の作成・更新時刻は、篇表の直後の時刻副表に `作時`・`改時`（Unix 秒 i64）として別に持つ（[design-time.md](design-time.md) §9.2）。`篇新` が両方を設定し、`籍作` の既存文の消去と `籍書` の書込みが `改時` を更新する。`篇消` は項を 0 に戻す。
- **篇時**: 漢令 34 `篇時` はパスを解決し、`讀` 権を検査して `作時`・`改時` を 16 B で返す。RTC 無効の間の値は 0。`改刻` は残るので、時刻副表を追加しても既存の順序・LRU の意味は変わらない。
- **永続化**: 時刻副表は [design-persistence.md](design-persistence.md) の版 3 でスロット末尾（+5153〜+5156）に保存し、チェックサムに含める。

### 13.4 既存の振る舞いからの変更

- 名の上限が 16 → 32 バイトになり、長すぎる名は `-EFAULT` でなく `-ENAMETOOLONG` を返す（殻の試験を更新）。
- 本文の上限が 256 B → 4 KiB、件数の上限が 8 → 128（篇全体）・32（章ごと）になった。
- `目録` の順が登録順から名のバイト列順になった。
