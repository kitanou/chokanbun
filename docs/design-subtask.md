# サブタスク（cre_tsk / ext_tsk / ter_tsk）設計書

状態: **設計・実装済み（S0〜S5、2026-10-23）**。BTRON3 互換層 1.1 のうち、いま「非適合／未対応」になっている副タスク（[compat/btron3-os.md](compat/btron3-os.md) の `cre_tsk`・`ext_tsk`・`ter_tsk`）を実装するための設計。
原文: <https://www.chokanji.com/developer/doc/btron3/os_spec/kernel/>（1.1 プロセス管理）。関連: [design-process-exec.md](design-process-exec.md)、[compat/btron3-spec-verification.md](compat/btron3-spec-verification.md)。

## 1. 原文が決めていること

| 項目 | 原文（1.1.1・1.1.2・1.1.3 と各システムコール） |
|---|---|
| 構造 | プロセスには 1 つのメインタスクと 0 個以上のサブタスクがある。総称してタスク。タスク ID は正の整数 |
| `cre_tsk(FP entry, W pri, W arg)` | 自プロセス内にサブタスクを作って実行する。成功は生成したタスク ID（正）。`pri` は**自プロセスの優先度グループの範囲内**だけ。エラー: `ER_ADR`（entry 不正）・`ER_PPRI`（優先度がグループ外）・`ER_LIMIT`（数の上限）・`ER_NOMEM` |
| サブタスクの形 | `VOID subtask(W arg)`。**return で終われない**（必ず `ext_tsk()`） |
| `ext_tsk()` | 自タスクを終える。**メインタスクなら、すべてのサブタスクを強制終了してプロセスの終了**。サブタスクの終了はプロセスの終了にならない |
| `ter_tsk(tskid)` | 自プロセス内のサブタスクだけを強制終了。自タスク・メインタスクは指定できない（`ER_ID`） |
| 状態 | サブタスクもメインタスクと同じ状態（Ready／Run／Wait）と遷移を持つ。プロセスの状態＝メインタスクの状態 |
| 優先度 | サブタスクにも生成時に優先度が与えられ、各タスクは優先度でスケジュールされる（A: 0〜127 厳密、B: 128〜191、C: 192〜255。互換層 1.1 の群の扱いはそのまま） |
| `slp_tsk`・`wup_tsk`・`can_wup`・`dly_tsk`・`get_tid` | タスク単位。`wup_tsk` は自プロセス内の他タスクだけ（自タスク・他プロセスは `ER_ID`） |
| メッセージハンドラ | メインタスクの処理に割り込んで実行される。待ちを `ER_MINTR` で中断するのはメインタスク（本設計の対象外。`def_msg` は M7e で実装済み） |

## 2. 現状（実装済みの前提）

- **行程の枠は 8 つ**（`程限`）。`行程表`（`0x40300000`、128 B × 8）の 1 項が行程の全資源の持ち主で、スケジューラ（`次程`・`排程`）は枠を単位に選ぶ。
- **`識`（行程番号）= 枠の番号 + 1**（`立程`）。生成した子には `新識` を付けるが、枠に紐づく。`get_tid` は `識` を返す（原文の「自タスク ID」としては主タスクの ID に当たる）。
- **枠ごとに持つもの**: 核棧（64 KiB、`核棧基 + (番号+1) × 核棧幅`）、保存フレーム、レベル 1〜3 の頁表（`程台`）、窓（`0x40600000`〜`0x407FFFFF`、2 MiB）、柄表、メッセージの信箱（`0x403E0800`）、優先表・統計表・時限表・イベント要求表・名前表……など、`讀現在` で引く表が**カーネル全体で約 70 か所**（kernel.mkn 10、btron.mkn 21、pian.mkn 5、msg.mkn 5、ほか）。
- **民の棧は窓の中の固定位置**（`民棧頭` = `0x40608000`、32 KiB）で、全行程が同じ仮想アドレス。
- 窓の配置: 棧 `0x40600000`〜、コード `0x40610000`〜`0x4062FFFF`（最大 128 KiB。`像最大` = 131072）、共有塊 `0x406F8000`〜`0x40700000`、データ・heap `0x40700000`〜（デマンドページング）。

## 3. 設計の選択肢

### 案 A: サブタスク = 同じ行程表の「従属する枠」（推奨）

サブタスクに行程の枠を 1 つ使い、枠に「**主**」（持ち主のメインタスクの枠番号）を持たせる。

- 実行の単位（保存フレーム・核棧・状態・覚・優先度・起床待ちの数）は**枠ごと**（今のまま `次程`・`排程` が選べる）。
- 資源の持ち主は**主の枠**: 頁表（`程台`）、窓、柄表、信箱、イベント要求、名前、ロック……。サブタスクの枠の `程台` は主と同じ値にして `TTBR0` はそのままで切り替わる。
- 実装の要は、`讀現在` を「実行中の枠」（スケジューラ用）と「資源の持ち主の枠」（`主行程(現在)`）に分け、資源側の約 70 か所を後者に置き換えること。主のいない枠（普通の行程）では `主行程(号) = 号` なので、挙動は変わらない。
- 欠点: 枠の数（8）がそのままタスク数の上限になる。`程限` を上げる（核棧 64 KiB × 枠で `0x40320000`〜の領域が足りるか確かめる）か、サブタスクの総数を絞る必要がある。

### 案 B: タスク表を別に作る

行程表（資源）とタスク表（実行）を分け、スケジューラをタスク単位にする。構造は原文に素直だが、`次程`・`排程`・保存フレーム・核棧・各表の添字がすべて変わり、変更が大きい。**今の規模では見合わない**。

→ **案 A を採る。** 段階 S0（§6）で `主行程` を導入してから機能を足すので、各段階で既存の 173 件が通ることを確かめながら進められる。

## 4. 主な決め事（案 A）

1. **タスク ID**: 主タスク = 行程番号（`識`、今のまま。`get_tid` の試験が変わらない）。サブタスクの ID は**行程番号と同じ単調増加の割り当て**から取る（`新識`）。ID は再利用しない。行程番号とタスク番号が同じ名前空間なので衝突しない。
2. **`cre_tsk`**: 空き枠が無いか、行程内のサブタスク数が上限（案: 4）なら `ER_LIMIT`。`entry` が窓のコード域（`0x40610000`〜`0x4062FFFF`、`像基`〜`像基+像最大`）の外なら `ER_ADR`。`pri` が主の優先度群の範囲外なら `ER_PPRI`（群 A: 0〜127、B: 128〜191、C: 192〜255）。民の棧と核棧が取れなければ `ER_NOMEM`。成功は新しい ID。
3. **サブタスクの民の棧**: 窓の中に**サブタスク用の棧領域**を固定位置で設ける（案: `0x40640000` から 16 KiB × 上限数。コード域 `0x40610000`〜`0x4062FFFF` と共有塊 `0x406F8000` の間で、他の用途に使っていないことを S1 で確かめる）。頁はデマンドページングで与え、終了で返す。
   → 実装では `0x406D8000`（窓内ページ 216〜231、16 KiB × 4）に置いた。`0x40640000` は貯試の窓内作業域と重なるため避けた（§9）。
4. **起動**: 保存フレームを `ELR = entry`、`x0 = arg`、`SP_EL0 = 棧頭`、`SPSR = EL0t` で作る。`LR`（`x30`）は、`ext_tsk` を呼ぶ小さな**戻り先**（コード域の 1 命令: `svc` で `ext_tsk`）にしておく。原文は「return で終われない」とするが、安全のため return されたら `ext_tsk` と同じ扱いにする（適合を損なわない緩め）。
5. **`ext_tsk`**: サブタスクなら、その枠の頁（民の棧）と核棧を返し、枠を空にする。メインタスクなら、**先に同じ主の全サブタスクを終了**してから行程を終了（今の `終行程` の経路）。
6. **`ter_tsk(tskid)`**: 同じ主のサブタスクだけ。自分・主・他行程・存在しない ID は `ER_ID`。対象が待ち状態なら待ちを外して終了（時限表・待ちの登録を解除する）。ロック・セマフォを持ったままの終了は、原文に規定が無いので、持ち主情報を残さず単に解放しない（既存の行程終了と同じ扱い）。
7. **`slp_tsk`・`wup_tsk`・`can_wup`・`dly_tsk`・`get_tid`**: 枠単位の状態に対して今の実装がそのまま使える。`wup_tsk`・`can_wup` の対象の判定を「同じ主の枠か」に直す（今は行程番号）。`wup_tsk` の `ER_ID` の条件（自分・他行程）は原文のまま。
8. **優先度（`chg_pri`）**: 枠ごとの `優先表` を使う。原文の `chg_pri(id, pri, opt)` は、`P_TASK` 指定なしだと**対象プロセス内の全タスク**の優先度を変え（戻り値はメインタスクの優先度）、`P_TASK` 指定ありだと `id` のタスク（`id = 0` は自タスク、`id > 0` は自プロセス内のタスクだけ。違えば `ER_ID`）だけを変える。今の実装（`kernel/proc/term.mkn` の `優先変更処理`）は `P_TASK` を扱うが、タスクは主 1 つの前提で「`id` が 0 か自分の識なら自分、それ以外は `ER_ID`」と判定している。これを、`P_TASK` なしは主とすべてのサブタスクの枠、`P_TASK` ありは同じ主の枠、に直す。範囲は対象が属するプロセスの現在の優先度グループ内（外は `ER_PPRI`）。
9. **メッセージ**: 信箱は行程単位（主の枠）。`rcv_msg` などで待つのが**サブタスクの場合**の扱いが原文に明記されていない。初期版では待てるのは**メインタスクだけ**とし、サブタスクが待とうとしたら**現行の実装の誤り（`ER_NOSPT` 相当）を返す**——これは適合から外れる点として互換表に記録する。後で待ち行列を枠単位にして直す。
10. **イベント・デバイス・ファイルのロック**: 持ち主は主（行程）。サブタスクが開いた柄・ロックは行程のもの（原文の「行程のリソース」と同じ）。
11. **統計（`get_inf`）**: 経過時間・使用時間は主の枠に合算する（サブタスク分を含める）。

## 5. 依存する他の作業

- `def_msg`・`ret_msg`・`ER_MINTR`・`WAIEVT` の完全な扱い: メッセージハンドラはメインタスクに割り込む仕組みなので、サブタスクの有無とは独立。`def_exc`/`ret_exc` で使う EL0 への同期例外の配送基盤（保存フレームの差し替え・復帰スタブ・入れ子禁止）を共有し、M7e で `def_msg`/`ret_msg` を実装した（`信手試` 25 項目）。
- `kernel/kernel.mkn` に手を入れる量が多い（`讀現在` の置き換え、`立程`・`終行程` の変更）ので、`def_exc`/`ret_exc` のマージ後に着手する。

## 6. 段階

| 段階 | 内容 | 試験 |
|---|---|---|
| S0 | `主行程(号)` を導入し、資源の添字を置き換える（挙動は変えない）。`行程表` に `主` の欄を足す（今は常に自分自身） | 既存の全件が通る（回帰） |
| S1 | `cre_tsk`（枠・民の棧・核棧・保存フレーム）、`ext_tsk`（サブタスクの終了）、`get_tid`。数の上限 | 生成したタスクが動き、`arg` を受け取り、終了で枠・頁が戻る（頁の空き数が元に戻る）。`ER_ADR`・`ER_PPRI`・`ER_LIMIT` |
| S2 | `ter_tsk`、メインタスク終了でサブタスクを終了、待ち状態の終了 | 待ち中のサブタスクを終了できる。主の終了で全員が消え、頁が戻る |
| S3 | `slp_tsk`・`wup_tsk`・`can_wup`・`dly_tsk` を主の枠で判定 | 2 タスク間の起床、`ER_ID`（自分・他行程）、起床要求の数 |
| S4 | `chg_pri` の対象の枠の判定（全タスク／1 タスク）、優先度（群の範囲・A 群の厳密な順序）、統計の合算 | 優先度が高いサブタスクが先に走る。`P_TASK` あり・なしで変わる範囲が違う。`ER_ID`・`ER_PPRI`。`get_inf` に合算 |
| S5 | 互換表・適合表・ABI 表の更新（漢令の番号を割り当てる） | 全件が通る |

## 7. 利用者側（`user/btron/proc.mkn`）

`cre_tsk(FP entry, W pri, W arg)` は関数の番地を取る必要がある。機械漢文に「関数の番地を取る」構文があるか、無ければ `取址` と同じ方法でコード域の番地を取る手段を S1 で確かめる（無ければ、サブタスクの入口は外部命令の `user_main` 内の記号を `外術` で番地に直して渡す）。

## 8. 決定事項（2026-10-18）

1. **`程限` は 8 のまま**。サブタスクは行程の枠を使うので、タスクの総数が 8 に収まる範囲で作れる（`cre_tsk` は空き枠が無ければ `ER_LIMIT`。行程あたりの上限は S1 で決める）。
2. **サブタスクは `rcv_msg` などメッセージ待ちができない**（初期版。互換表に非適合として記録する。待ち行列を枠単位にして直すのは後続）。
3. **`def_exc`／`ret_exc` と EL0 への同期例外の upcall が開通したので、S0 から進める**。ハンドラ表・退避フレーム・復帰スタブの配置と入れ子禁止の扱いは `kernel/proc/exc.mkn` と `docs/abi-aarch64.md` に従う。

## 9. 実装の記録（2026-10-23、S0〜S5 完了）

- **枠**: 副タスクは行程表の枠を 1 つ使う（案 A）。`程項幅` を 128 → 192 に広げ、`+128 偏主`（主の枠 + 1、0 = 主）、`+136 偏起`（起床要求数）、`+144 偏棧`（民スタック上端）、`+152 偏帰`（像ヘッダ +32 の終了スタブ）を足した。`程限` は 8 のまま。
- **資源の持ち主**: `主行程(号)`・`現主()` を導入し、柄・章・ファイル・利用者・ロック・メモリ・デバイス・イベント・時計・名前の表は主の枠で引く。`程台(号)` は主の頁表を返し、起動時の `設頁表` だけ `台基 + 番*台幅` を直接使う。待ち合わせ系（ランデブ・例外・メッセージハンドラ・同期の待ち表）は枠単位のまま。
- **民スタック**: 窓内 `0x406D8000`（頁 216〜231）を 4 頁 × 副上限 4 個で固定割当。作成時に 4 頁とも空いていることを確かめ、終了時にその 4 頁だけ返す。
- **起動**: `生行程像` が KBN1 ヘッダ +32 を読んで `偏帰` に保存する。`cre_tsk` は `[像基, 像基+像最大)` かつ 4 B 整列の入口だけを受け、保存フレームの `x0 = arg`・`x30 = 偏帰`・`ELR = entry`・`SP_EL0 = 棧頭` を作る。`crt0.S` は +32 に `__task_exit_stub`（`x8=186` の `svc`）を書き、副タスクが return すると `ext_tsk` になる。
- **漢令**: 185 `cre_tsk`、186 `ext_tsk`、187 `ter_tsk` を追加。74 `wup_tsk`・75 `can_wup` は同じ主の枠を対象にし、自タスク・他プロセス・無い ID は `ER_ID`、`can_wup(0)` は自分の要求数を返す。`slp_tsk` は有限待ちを `状眠時 = 10`、無期限を既存の `9` とし、`wup_tsk` は `x0=0`、時間切れは `覚醒` が `x0=誤時限`（`錯換` で `ER_NONE`）を書く。
- **`ext_tsk`／`ter_tsk`**: 副タスクは自分の枠だけを片付ける（主の柄・ファイル・共有資源は閉じない）。主の `ext_tsk` は先に同じ主の全副タスクを終えてから既存の `程終了` を通る。`ter_tsk` は同じ主の生きた副タスクだけを受け、それ以外は `ER_ID`。
- **`chg_pri`**: `P_TASK` なしは主と全副タスク（戻り値は主）、ありは同じ主の 1 枠（`id=0` は自タスク）。範囲は主の現在の優先度群で検査する。
- **`get_inf`**: 副タスクが走った刻は主の `utime` に合算する。
- **試験**: 外部命令 `副試`（`user/btron_task.mkn`、補助 `user/btron_task_aux.S`、19 項目）。生成・arg・`get_tid`・return、`ER_ADR`・`ER_PPRI`・`ER_LIMIT` と頁の返却、`ter_tsk` と頁、`ext_tsk`、`wup_tsk`/`can_wup`、時間切れ、`rcv_msg` の `ER_NOSPT`、`chg_pri` の範囲、`get_inf` の合算、主の終了、他プロセスへの `ER_ID`、群 B・C の配分比を確かめる。`make test` は 192 PASS（rc=0）。
- **既知の制限**: 副タスクはメッセージ待ち（`rcv_msg` ほか）ができない（`ER_NOSPT`）。排他セマフォを持ったまま終了した場合の解放は行わない。`dly_tsk` の待ち状態 2 は副タスクでもそのまま動くが、`slp_tsk` の時間切れだけ `状眠時` で区別する。

## 10. 群 B・C の配分比（2026-10-25）

- **重み**: 群 B は `192 - 優先度`、群 C は `256 - 優先度`（1〜64）。群 A は従来どおり優先度の厳密な順で、配分比を使わない。群 B は群 C より先に走る（群の選択は A → B → C）。
- **仮想時刻**: 枠ごとに配分表（`0x403E0D40`、8 B × `程限`）を持つ。実行可能な枠のうち仮想時刻が最小のものを選び、選ばれた枠の仮想時刻を `262144 / 重み` だけ進める。128 と 191（192 と 255）の実行頻度の比は 64:1 になる。
- **待機からの復帰**: `置状` で待機から実行可能へ戻るとき、同じ群の実行可能な枠の最小の仮想時刻へ合わせる（`配分就`）。長く眠った枠が仮想時刻を溜めて CPU を占有しない。
- **実装**: `kernel/kernel.mkn` の `次程` を、群の選択・群 A の厳密な順・群 B/C の仮想時刻の 3 段に分けた。`配分読`/`配分置`/`配分重`/`配分歩`/`配分就`/`配分進` を追加し、`kernel/proc/term.mkn` の `優初期化` で配分表を 0 埋めする。
- **試験**: `副試` の 2 項目。群 B は優先度 128 と 191 の副タスクを 650 回切り替えて 640 と 10、群 C は優先度 200 の子行程の中で 192 と 255 を走らせて 640 と 10 になることを確かめる。群 C の子は群 B の親より後にしか走らないので、親は `rcv_msg` で眠って場所を空ける。
