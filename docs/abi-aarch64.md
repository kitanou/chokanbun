# AArch64 ABI・ブート設計（草案）

## ターゲット
- AArch64 little-endian / ARMv8-A
- QEMU `virt`、初期は単一CPU
- 初期ブートはEL1で動く構成を目指す（実際の起動例外レベルを検出して必要なら遷移）
- カーネルとユーザー空間の境界はEL1/EL0

## ブート
1. QEMU virtの起動契約とデバイスツリーを確認する。
2. スタックとBSSを初期化する。（実装: `kernel/boot.S`）
3. UARTを初期化し、最初のログを出す。（実装: `kernel/kernel.mkn` の PL011 ドライバ）
4. 例外ベクタを設定する。（実装: `kernel/boot.S` が `VBAR_EL1` に `_vectors` を設定）
5. メモリ管理とタイマーを順次有効化する。（MMU: 実装済み。タイマー+GIC割込: 実装済み）

## 例外
- `-kernel` 起動は EL1（SP_EL1）で始まる。`VBAR_EL1` に 2 KiB 整列した
  ベクタ表を設定し、同期例外は `kernel/vectors.S` の共通入口でレジスタを
  保存してから機械漢文ハンドラ `exception_dispatch`（`kernel/kernel.mkn`）を
  呼ぶ。ハンドラは ESR_EL1 を復号して診断を出力し、復帰先 ELR_EL1 を返す。

## 割込（GICv2 + 汎用タイマー）
- QEMU `virt,gic-version=2`を前提とする。GIC ディストリビュータ `0x08000000`、
  CPU インタフェース `0x08010000`。
- EL1 物理タイマー（PPI 30）を `CNTP_TVAL_EL0`/`CNTP_CTL_EL0` で起動し、
  `CNTFRQ_EL0`（QEMU virt では 62.5 MHz）から周期を求める。
- IRQ はベクタ表の Current EL with SPx（+0x280）から `irq_handler`
  （`kernel/vectors.S`）に届く。`irq_handler` は x0–x30 と NZCV を保存して
  機械漢文ハンドラ `irq_dispatch`（`kernel/kernel.mkn`）を呼び、復帰時に
  すべて復元して `eret` する。
- 例外入口は `PSTATE.DAIF` の I ビットを立てるため、ハンドラ実行中は割込が
  入れ子にならない。`開割込`（`local_irq_enable`）で明示的に I を落とし、
  `待割込`（`wait_irq`）で `wfi` する。
- CPU インタフェースはセキュア状態からのアクセスとなるため、
  `GICC_CTLR.AckCtl`（bit 2）を設定して `GICC_IAR` で Group 1 の要因番号を
  取得する。要因番号は `GICC_EOIR` に書き戻して完了する。
- EL0 実行中のタイマー割込（プリエンプション）は下位EL IRQ ベクタ（オフセット
  `0x480`）の `lower_irq_handler`（`kernel/el0.S`）に入り、SVC と同じ 288 バイトの
  保存フレームを作って機械漢文の `割込切替`（`irq_switch`）を呼ぶ。`割込切替` は
  `GICC_IAR`/`GICC_EOIR` とタイマー再装填、刻数の加算を行い、`排程` で次の行程へ
  切り替えて復歸先フレームへのポインタを返す（0 なら EL1 で待機）。
- 民行程は既定で割込をマスクして走る（`SPSR_EL1` = `0x3C0`、EL0t・DAIF マスク）。
  非協調切替を有効にするには `開先取`（番7）を発行する。これは自分の保存フレームの
  `SPSR_EL1` の I ビットを落とし（`0x340`）、タイマーを起動する。
- 行程の状態（行程表の `偏状`）は 0=空（終了）・1=実行可能・2=待機。`待機`（番8）は自分の
  起床予定刻（`偏覚` = 現在刻 + 指定刻）を記録して状を 2 にし、`排程` で他の行程へ
  切り替える。`割込切替` はタイマー刻を進めた後に待機行程の起床判定（覚醒）を行い、
  予定刻に達した行程を実行可能（状=1）へ戻す。実行可能な行程が無ければ核は
  EL1 で待機する（既知の制限）。

## MMU
- 4 KiB グラニュール、`TTBR0_EL1`、`T0SZ=33`（2 GiB 領域）でレベル1 から
  探索する。**行程ごとに変換表を持ち**、核の写像は全行程で共通、民の窓だけが
  行程ごとに異なる（下記）。
- レベル1（行程ごと）:
  - 要素0: `0x00000000`–`0x3FFFFFFF` を Device-nGnRnE 1 GiB ブロック
    （PL011 UART、GIC。AP=00、EL1 のみ）
  - 要素1: `0x40000000`–`0x7FFFFFFF` を、その行程のレベル2 表への
    テーブル記述子。
- レベル2（行程ごと、2 MiB ブロック）:
  | 要素 | 仮想アドレス | 内容 | EL1 | EL0 |
  |---|---|---|---|---|
  | 0 | `0x40000000` | 漢極コード・rodata・民コード | RO+実行 | RO+実行 |
  | 1 | `0x40200000` | data・bss・核棧 | RW+実行 | 不可 |
  | 2 | `0x40400000` | 頁池・頁表・刻数 | RW+実行 | 不可 |
  | 3 | `0x40600000` | 民の窓（棧・データ） | — | — |
  要素0〜2 は全行程で同一。要素3 は全行程でその行程の**レベル3 表**への
  テーブル記述子である。
- レベル3（行程ごと、4 KiB ページ）: 民の窓 `0x40600000`–`0x407FFFFF` を
  512 枚の 4 KiB ページで覆う。窓の頁の編成 (BTRON3 1.5 メモリ管理
  [compat/btron3-spec-verification.md](compat/btron3-spec-verification.md) §6.5):

  | 頁 | 用途 |
  |---|---|
  | 0〜7 | 民の棧 (頭 `0x40608000` = 窓の先頭から 32 KiB) |
  | 8〜247 | ローカル塊域 (240 頁。`get_mbk` のローカル塊は昇順 first-fit で割当。物理頁は需要供給に委ねる) |
  | 248〜255 | 共有・システム塊域 (8 頁。共有・システム塊は連続物理頁を全行程に同一 VA・同一物理頁で写像し、降順 first-fit。`窓清` はこの域の頁を頁池へ返さない) |
  | 256〜510 | データ域 (デマンドページング) |
  | 511 | 引数頁 (`0x407FF000`。argv を `0x407FF008` に置く) |

  **デマンドページング**: 起動時に張るのは民の棧の
  先頭 2 ページだけで、残りは EL0 が触れた時に `漢令處理`（`svc_dispatch`）が
  下位EL データアボート（EC=36）を捕らえ、`頁取`（動的頁域 `頁元` 0x40800000
  のビットマップ割当）で物理ページを与えて同じ命令を再試行する。仮想アドレスは
  全行程で共通（民の棧の頭 `0x40608000`、データ `0x40700000`）だが物理ページが
  異なるため、行程間で互いの書き込みは見えない。ただし共有・システム塊域
  （頁 248〜255）は例外で、塊を取った物理ページが全行程の表に同じ VA で張られる。
- 変換表（1 行程あたり 12 KiB = レベル1 + レベル2 + レベル3）は機械漢文
  （`設頁表`）が構築し、システムレジスタ設定のみ `kernel/sysreg.S` に委譲する
  （`enable_mmu` で起動、`set_ttbr0` で切替）。
- 行程切替時は `排程`（機械漢文）が `設台`（`set_ttbr0`）を呼び、
  `TTBR0_EL1` を次の行程の表へ向けて TLB を無効化する。核の恒等写像は
  全行程の表に含まれるため、切替後も核はそのまま実行を続ける。
- EL0 から書き込めるブロックは EL1 では実行できない（AArch64 EL1&0 の
  段1規則）。そのため実行イメージ（要素0）と書き込み可能な窓（要素1・3）を
  別ブロックに分ける。要素0 を EL0 RO にとどめることで、民コードの実行と
  EL1 の実行を両立させる。
- 物理アドレスは当面 QEMU `virt` の固定配置（Devicetree 未解析）。民の窓の
  物理ページは動的頁域（`頁元` `0x40800000`〜`頁末` `0x41800000`、16 MiB = 4096 ページ。EL1 RW の
  2 MiB ブロック 8 個で全行程の表に恒等写像する）から切り出す。使用ビットマップ（`0x40421000`、64 語）で管理し、`頁取` は最も若い空きページを
  **ゼロ埋めして**返し（空きが無ければ 0）、`頁放` が返す（二重解放・範囲外・頁境界でない
  アドレスは 0 で拒否）。`頁残` は空きページ数。

## 漢令（syscall）ABI v0.1
- `svc #0` で EL0 から EL1 へ遷移する。下位EL同期ベクタ（オフセット `0x400`）
  の `lower_sync_handler`（`kernel/el0.S`）が 288 バイトの保存フレームを作る
  （`x0`–`x30`、NZCV、`ELR_EL1`、`SPSR_EL1`、`SP_EL0`）。`ESR_EL1` とフレームへの
  ポインタを `svc_dispatch`（`kernel/kernel.mkn`）に渡す。
- `svc_dispatch` は復歸先フレームへのポインタを返す。フレームは**行程ごとの核棧**
  （64 KiB、`核棧基` 0x40320000 から）上にあり、`el0.S` は返されたアドレスへ
  `SP_EL1`（EL1h の `sp`）を切り替えてから復歸する。これによりハンドラは別の行程の
  フレーム（と核棧）から復歸でき、コンテキスト切替を実現する。0 を返すと
  実行可能な行程が無いことを意味し、核は EL1 で待機する（`wfi`）。
- レジスタ規約:

  | `x8` | 漢令番号 |
  | `x0`–`x5` | 引数 |
  | `x0` | 戻り値（誤りは負の errno） |

- 引数検査: 漢令のポインタ引数は、EL0 から読める範囲

- `読込`（番10）は**書込系漢令**の最初の例で、UART 受信 FIFO（`UART_FR` の RXFE
  ビットで空きを判定し `UART_DR` を読む）から、今ある分だけを検証済みの民の窓
  バッファへ書く。殻（シェル）の入力経路になる。呼び出し側は改行まで繰り返し
  呼ぶ。書込先は窓内（書込可能）かつ `令長限` 以内でなければ `-EFAULT`。
  核は EL1 から民の頁へ書くため、対象頁は `給頁`（デマンドページング）で先に
  全て張ってから書く。
- **柄（ファイル記述子）**: **行程ごとの柄表**（8 本）から、**系統の開表**（32 項）を経由して実体を指す。
  柄 `0`=標準入力（コンソール）、`1`/`2`=標準出力/標準誤り（コンソール）は起動時に各行程へ与えられ、
  `3` 以降が開いた典籍。`讀入` の柄 `0` は `読込` と同じく UART から読み、`柄書` の柄 `1`/`2` は
  `書出` と同じくコンソールへ書く。これにより殻は「どれでも同じ柄」として入出力を扱える。
  - `開` は呼出側の行程の空き柄（3 以上で最小）を返す。**同じ典籍を 2 回開くと別の柄になり、位置も別々**に持つ。
  - `閉` は柄 3 以上だけ閉じられる（盤の柄 `0`/`1`/`2` は `-EBADF`）。行程が終わると（`終行程`）その柄はすべて閉じる。
  - 開表項は `{種, 対象, 位置, 参照数}`。種は 盤の入力・盤の出力・典籍。参照数は、複製（後続の `複寫柄`）で柄が同じ項を共有するための準備。
- **典籍（RAMFS/VFS）**: 起動時に数件のファイルを登録した読み書き可能な
  メモリ内ファイル。目録（名前・名前長・本文長・開数）は 0x403A0000 に、
  本文は 0x403B0000 に置く。柄表は行程表の各項（`偏柄`）、開表は 0x40313800。`開` は名前のバイト列を照合して
  開表項を作り柄を返し、`讀入`/`柄書` は開表項の位置から順に読み書きして位置を進める。
  目録の開数は、その典籍を指す開表項の数で、0 でなければ `削` は `-EBUSY`。
  核は EL1 から民の頁を書くため、`讀入` の宛先は `備宛`（窓内・`令長限` 以内を確認し
  `給頁` で先に張る）を通す。
- 機械漢文側からは薄いラッパ `奏令`（`kernel/el0.S` の `svc_call`、
  AAPCS64 で x0=番号, x1–x6=引数）を呼ぶ。
- 下位EL データアボート（EC=36）が民の窓 `0x40600000`–`0x407FFFFF` 内なら、
  `svc_dispatch` は未写像ページに `頁取` で物理ページを与え、`無效台` で TLB を
  無効化して同じ命令を再試行する（デマンドページング。`頁供 0x…` と診断出力）。
  頁で解決できないデータ異常と、SVC 以外の下位EL同期例外は、その行程が `def_exc` で
  ハンドラを定義していれば EL0 のハンドラへ配送する（§「利用者例外ハンドラ」）。
  ハンドラが無い場合と、ハンドラ実行中に起きた例外は、従来どおり `民異常 ESR=…` と
  診断して待機する。
- 行程終了（`終行程`）で実行可能な行程が尽きると、核は EL1 で待機する。

### 黄帝紀元の時刻（T1・T2 実装済み）

黄帝紀元の壁時計と単調時計は [design-time.md](design-time.md) で定義する。純粋な変換・書式化・
解析の利用者ライブラリ（T1）と、次の 3 つの新漢令（T2）は実装済み。
既存の 176 `時刻取`・178 `時刻設` は BTRON3 互換の STIME 用として残す。

| 番号 | 名前 | 引数 | 戻り値 |
|---:|---|---|---|
| 221 | `壁時取` | `x0` = `有符六四*`（8 B）, `x1` = `UW*`（フラグ。0 なら書かない） | 0／`-EFAULT` |
| 222 | `壁時設` | `x0` = `有符六四`（Unix 秒） | 0／`-EACCES`・`-EINVAL`（HE 1〜9999 の外） |
| 223 | `単調取` | `x0` = `無符六四*`（8 B） | 0／`-EFAULT` |

`壁時取` のフラグ bit 0 は `時計有効`（1 = 有効、0 = RTC 無し・時刻不明）。bit 1〜31 は予約で 0。

### 利用者例外ハンドラ（BTRON3 1.10 `def_exc`/`ret_exc`）

同期例外を EL0 のハンドラへ配送する。要因はインプリメント依存の 8 種。

| 要因 | 名前 | 主な ESR の EC |
|---:|---|---|
| 0 | `EXC_BRK` | 60（BRK）・48（ハードウェアのブレークポイント）・49（ソフトウェアのステップ） |
| 1 | `EXC_DATA_ABORT` | 36（下位EL データ異常）・37（同・同一 EL） |
| 2 | `EXC_INSTR_ABORT` | 32（下位EL 命令異常）・33（同・同一 EL） |
| 3 | `EXC_ALIGN` | 34（PC 整列）・38（SP 整列） |
| 4 | `EXC_UNDEF` | 0（未定義命令）・14（不正な実行状態） |
| 5 | `EXC_FP` | 44（浮動小数点） |
| 6 | （予約） | — |
| 7 | `EXC_OTHER` | 上のどれにも当たらない同期例外 |

- 漢令 181 `例外定義`（`def_exc`）は行程ごとのハンドラ表に `FP` を書く。`exchdr=0` で解除。
  同じ要因は後から定義したものが有効。要因が 0〜7 の外は `-EINVAL`、ハンドラが
  `像基`〜`像基+像最大`（128 KiB）と `典域頭`〜`典域末` の外、または 4 B 未整列は `-EFAULT`。
- 漢令 182 `例外復帰`（`ret_exc`）は、ハンドラ実行中でなければ `-EBADRQC`（ER_CTX）。
  `ret=0` は退避フレームを戻して例外位置から再開し、本漢令からは戻らない。
  `ret≠0` は退避を捨て、ハンドラの `ret_exc` 呼出し直後へ 0 を返して続行する。
- ハンドラは EL0 で `x0`=要因、`x1`=ESR、`x2`=例外の起きた命令アドレス、`x3`=FAR を受ける。
  `x30` は復帰スタブ（`exc_return_stub`。`ret_exc(0)` 相当）に向く。`ELR` はハンドラの入口。
- BRK は退避側の `ELR` だけ +4 し、ハンドラの `x2` には元の `ELR` を渡す。その他の要因は
  退避側 `ELR` をそのまま残す（`ret_exc(0)` は同じ命令を再実行する）。
- 例外文脈が有効な間はハンドラを入れ子にしない。`ret_exc(1)` は文脈を終えるので、その後に起きた同期例外は新しい例外として配送する。
- 表の配置は `0x403DD000`（ハンドラ表 8 行程 × 8 要因 × 8 B）、`0x403DE000`（退避フレーム
  8 行程 × 320 B）、`0x403DF000`（状態 8 行程 × 32 B。+0 実行中、+8 要因、+16 ESR、+24 元の ELR）。
- 起動時に `例外初期化` で全行程を空にし、`生行程像` は枠の再利用時に `例外清` で消す。
  子行程は親のハンドラを継がない。

## ABI方針
- 通常関数呼出しはAAPCS64に従う。
- 独自syscall ABIはSVCで定義し、番号レジスタ・引数・戻り値・エラー規約を別途固定する。
- 例外入口では保存対象レジスタとスタックアラインメントを厳密に規定する。
- デバイスアドレスを固定値で決め打ちせず、QEMU virtの仕様/DTBを参照する。
