# 暫定アセンブリ・C 依存の一覧と置換順序

[roadmap.md](roadmap.md) F1 の「暫定アセンブリ依存を一覧化し、置換順序を定める」の成果物。2026-10-26 時点の `main` を調べた。
置換は機械漢文の言語機能（下の「必要な言語機能」）が入った順に進める。機能が無いまま書き直さない。

リンカスクリプト（`kernel/kernel.lds`・`boot/boot.lds`）とビルド用シェル（`tools/*.sh`）は言語ではないので対象外。

## 2. 必要な言語機能

現在の言語には、関数のアドレスを取る式も、システムレジスタの読み書きも、インライン asm も無い
（[language-spec.md](language-spec.md) §6・§7・§13。`險` の中は生ポインタ・`讀揮發`/`寫揮發` だけ）。

| 記号 | 機能 | 解消するもの |
|---|---|---|
| L1 | システムレジスタの読み書き・命令の組込み（`mrs`/`msr`、`isb`/`dsb`、`tlbi`、`wfi`、`dc`/`ic`） | `sysreg.S` の全部、`boot.S` の `VBAR_EL1` |
| L2 | 関数のアドレスを値として取る式 | `*_addr` 系すべて（`aux.S` 3 本、`el0.S` の 3 件） |
| L3 | 組込みの `svc`/`brk`（固定レジスタ割付） | `svc_call`（核・民）、`exc_brk`、`trigger_exception` |
| L4 | `eret` と `ELR`/`SPSR`/`SP_EL0` の操作 | `enter_el0`、復帰スタブ |
| L5 | 関数の属性（前後奏を作らない `裸`、セクション指定、整列、`SP` 設定） | `_start`、ベクタ表、入口 |
| L6 | 全レジスタ退避・復帰（`x0`〜`x30`、`NZCV`）を機械漢文から書く手段 | `vectors.S`・`el0.S` の入口 |
| L7 | リンカ記号のアドレスを持つ静的データ | `crt0.S` の `KBN1` ヘッダ |

## 3. 置換順序

下に行くほど言語側の準備が多く、失敗したときの影響も大きい。各段階は `make test` の全件 PASS を保って 1 段ずつ入れる。

1. **段階 A: 今の言語で置けるもの。**
   - `exc_store`（`btron_exc_aux.S`）は `八置`（`險` の `寫揮發〈無符六四〉`）に置き換え済み。`例試` の 16 項目で確認した。
   - `boot/uart.c` は `kernel` の `核外輸出` と二重になっている。`uart`・`uart_mmio` 試験を機械漢文だけにするか、参照用として `docs/` へ退避して `boot/` を整理するかを決める（置換の対象は C）。
2. **段階 B: L2（関数アドレス）。** 言語に最小の式を足せば、`user/*_aux.S` のアドレス取得 13 件と `el0.S` の `*_addr` 3 件がなくなる。副作用が無く、検証は既存の `信手試`・`例試`・`副試` がそのまま使える。**最初に着手する言語機能はこれ。**
3. **段階 C: L1（システムレジスタ・バリア）。** `sysreg.S` の葉関数 13 本は単純で、MMU 有効化だけ命令の順序が厳しい（`isb` の位置）。タイマー・`DAIF`・`FAR_EL1`・TLB を先に、`enable_mmu`・`TTBR0` を最後に移す。
4. **段階 D: L3（`svc`/`brk`）。** `svc_call`（核と民）、`exc_brk`、`trigger_exception`。民の `crt0.S` から `svc_call` が消え、全像で共通のライブラリになる。
5. **段階 E: L5 + L1（起動）。** `kernel/boot.S` を機械漢文の裸関数へ。`.bss` 零化は `險` の `寫揮発` ループで書ける。スタックを使う前に `SP` を設定する必要があるので、L5 の `SP` 設定が先。
6. **段階 F: L4 + L6（例外入口・EL0 遷移）。** `vectors.S`・`el0.S` の入口と `enter_el0`。レジスタ退避の枠組みを決める最大の作業で、`kernel/proc/*.mkn` の `異常處理` との境界（[abi-aarch64.md](abi-aarch64.md) の「機械漢文から見える割込境界」）を設計し直す。
7. **段階 G: L7（漢像ヘッダ）。** `crt0.S` の `KBN1` ヘッダ。ヘッダの値はリンカが決める絶対アドレスなので、静的データにリンカ記号を置ける仕組みが要る。`_start` と副タスク終了スタブも同時に移す。`副試` の `__task_exit_stub` は裸関数（L5）。

段階 F が終われば `kernel/*.S` は残らず、G で `user/*.S` も消える。そのときリンカスクリプトとブート時の `VBAR` 設定だけが言語外に残る。

## 4. 現時点の判断と未決事項

- 段階 A の `exc_store` は置換済み。次の開発は段階 B(L2 の設計)から。
- L6（全レジスタ退避）は、組込みで足りるか、`裸` 関数に限った限定的な asm 文を許すかで設計が分かれる。language-spec §13 の「inline asm は対象外（非M0）」との関係を決めるまで段階 F は始めない。
- 置換のたびに、このファイルの表と [roadmap.md](roadmap.md) F1 を更新する。
