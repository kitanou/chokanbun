# 設計: 行程の生成・外部命令・パイプ（spawn / exec / wait / pipe / fork）

状態: **設計のみ（未実装）**。ロードマップ M4 の残り「init からの外部命令の起動」と M5 の前提にあたる。
関連: [roadmap.md](roadmap.md)、[abi-aarch64.md](abi-aarch64.md)、[posix-compat.md](posix-compat.md)、
[detailed-design-v0.2.md](detailed-design-v0.2.md)、[shell-commands.md](shell-commands.md)

## 1. 目的とスコープ

殻（甲行程）が、内蔵命令だけでなく**別の行程として外部命令を起動**し、終了を待ち、
パイプでつなげられるようにする。段階は `posix-compat.md` の方針に従い、
`spawn`（生行程）→ `wait` → `pipe`/柄の複製 → `exec` → `fork` の順にする
（`detailed-design-v0.2.md`: 「forkとexecは後期。初期は単純なspawnを優先」）。

対象外: シグナル、端末制御（ジョブ制御）、共有メモリ、複数 CPU、ディスク。POSIX 適合は主張しない。

## 2. 現状と制約（2026-10-17 時点）

| 項目 | 現状 | 本設計で問題になる点 |
|---|---|---|
| 行程数 | `程限`=2 の固定。行程は起動時に `立程` で全員作る | 動的な生成・終了後の再利用が無い |
| 行程の表 | `状表`・`覚表`・`程表` などの別々の配列 | 親子・終了コード・柄表を持てない |
| プログラム | 全行程が同じ `user_main`（`民務`）を実行。コードは漢極イメージ内（EL0 RO ブロック） | 別プログラムを読み込む経路が無い |
| 民の窓 | 2 MiB（`0x40600000`–`0x407FFFFF`）、行程ごとのレベル3表、デマンドページング | コード置き場の規約が無い |
| 物理ページ | `頁元`(0x40430000) からの**バンプ割当のみ**。解放なし | 行程が終わるたびに漏れる |
| 柄（FD） | 柄 `3+番号` は典籍の目録番号。位置と開状態は**目録に 1 つだけ** | 行程間で共有・複製できない |
| 待ち・起床 | `待機`（時刻）のみ | 子の終了・パイプを待てない |
| 漢令 | 1〜16 | `生行程` 以降が未定義 |

## 3. 設計方針

1. **行程表を 1 本の構造体配列に統合する**。状態・親・終了コード・柄表・頁表・核棧を行程ごとにまとめる。
2. **プログラムは「漢像」形式の平坦イメージ**として典籍（RAMFS）に置き、`生行程` が名前で読み込む。
3. **柄は「行程ごとの柄表 → 系統の開表 → 実体（コンソール/典籍/管）」の 3 段**にする。複製・継承・パイプはこれで統一的に扱える。
4. **物理ページに解放を導入する**（行程の生成・終了を繰り返せる前提）。
5. **核は非プリエンプティブのまま**（EL1 では IRQ をマスクしたまま動く）。ブロックする漢令は
   「状態を変えて `排程` へ」と「起床時に再試行」で実現する。
6. fork は**最後**。exec と先に作った生成経路を再利用し、まず全コピー方式で実装する。

## 4. 行程表

`程限` を 8 に拡大し、行程ごとに次を持つ（1 件 128 B 程度の想定）。

| 項目 | 型 | 内容 |
|---|---|---|
| `識` | u64 | 行程番号（pid）。1 始まりで単調増加、再利用しない |
| `状` | u64 | `空`/`可`（実行可能）/`眠`（時刻待ち）/`待子`/`待管`/`僵`（終了済み・未回収） |
| `親` | u64 | 親の `識`。親が先に終わったら init（`識`=1）へ付け替える |
| `碼` | u64 | 終了コード（`終行程` の引数） |
| `台` | u64 | レベル1 頁表の物理アドレス（行程ごとに 3 ページ） |
| `框` | u64 | 保存フレームへのポインタ（現行の `程表`） |
| `覚` | u64 | 起床予定刻（現行の `覚表`） |
| `待` | u64 | 待ち対象（`待子` なら回収したい pid、`待管` なら管の番号） |
| `柄表` | u8[8] | 柄表の各項目（§6）。1 行程あたり最大 8 本 |

- 行程の枠は `状`=`空` のものを線形探索して割り当てる（8 件なので十分）。
- `次程`（ラウンドロビン）は `状`=`可` だけを選ぶ。`眠`・`待子`・`待管`・`僵`・`空` は選ばない。
- 核棧は行程ごとに固定領域（現行 64 KiB → 16 KiB へ縮小する案。最大使用量の実測が必要。未決 §12）。

## 5. 行程の生成と終了

### 5.1 実行イメージ「漢像」

平坦バイナリに 32 バイトの頭部を付ける。

| オフセット | 内容 |
|---|---|
| 0 | 魔: ASCII `KBN1` |
| 4 | 入口の相対位置（コード先頭から） |
| 8 | コード長（バイト、4 KiB 単位に切り上げて配置） |
| 16 | 初期データ長 |
| 24 | bss 長 |

- 生成: 機械漢文のコマンドを `chokanbun` → LLVM IR → `llc` → `ld.lld`（専用リンカスクリプトで基底
  `0x40610000`）→ `llvm-objcopy -O binary` →頭部付与、の順に作る。`Makefile` に `命令` ターゲットを追加する想定。
- 配置: 起動時に漢極イメージへ埋め込み、`籍入` で典籍として登録する（`.incbin` でバイナリ配列を持つ）。
  ディスクが無い間はこれが唯一の入手経路。
- コード領域は上書き不可（EL0 RO+実行）、データ・棧・heap は RW+実行不可にする。**複写後に命令キャッシュを無効化**する
  （`dc cvau` → `ic ialluis` → `dsb`/`isb`）。QEMU では見えなくても実機では必須。

### 5.2 民の窓の配置 v2

| 仮想アドレス | 内容 | EL0 権限 |
|---|---|---|
| `0x40600000` | 棧（現行の位置を維持。下向き） | RW |
| `0x40610000`–`0x4061FFFF` | コード（最大 64 KiB） | RO+実行 |
| `0x40700000`– | 初期データ・bss・heap（デマンドページング、現行の `民資址`） | RW |
| `0x407FF000` | 引数ブロック（§5.3）。1 ページ | RO |

### 5.3 `生行程` の手順（漢令 17）

`生行程(名址, 名長, 引址, 引長)` → 子の `識`。

1. 名前を検査（窓内・長さ上限 16・`令長限`）し、典籍から漢像を探す。無ければ `-ENOENT`、魔が違えば `-ENOEXEC`。
2. 空き行程枠を探す。無ければ `-EAGAIN`。柄表の空きは不要（継承するだけ）。
3. 頁表 3 ページと棧 2 ページを頁池から取る（足りなければ `-ENOMEM`、取れた分は戻す）。
4. コードを複写し、データ・bss を初期化。引数文字列を `0x407FF000` に並べる（`argc`、各引数へのポインタ、文字列本体）。
5. 保存フレームを作る: `ELR`=入口、`SPSR`=EL0t、`SP_EL0`=棧頭、`x0`=argc、`x1`=argv。
6. 親の柄 0/1/2 を子へ**継承**（開表の参照数を増やす）。リダイレクト指定は §7 の `複寫柄` で子の生成前に親が差し替える。
7. `状`=`可`、`親`=呼出側 `識`。

### 5.4 終了と回収

- `終行程(碼)`（番2）: 柄をすべて閉じ（参照数を減らす）、窓の頁と頁表を頁池へ返し、`状`=`僵`、`碼` を保存。
  子を持っていれば全員の `親` を init に付け替える。親が `待子` で待っていれば起こす（§5.5）。
- `待行程(識, 状址)`（番18）: 引数 `識`=-1 は任意の子。終了済みの対象があれば `碼` を `状址` に書いて即返し、枠を `空` にする
  （回収）。無ければ `状`=`待子` にして `排程`。子が無ければ `-ECHILD`。
- 起床時の結果は、**起こす側が親の保存フレームの `x0`/`状址` に直接書く**（再実行しない）。

### 5.5 init（識=1）

起動時に核が作る唯一の行程。典籍 `初` の漢像を実行する。仕事は 2 つだけ:
殻（`殻`）を生成して待つ、孤児になった僵行程を回収し続ける。殻が終わったら init は終了せず、再度殻を起動する。

## 6. 柄表・開表・管

```text
行程.柄表[8]  ──→  系統開表[32]  ──→  実体
  (開表番号)        種 / 対象 / 位置 / 参照数
```

| 種 | 対象 | 備考 |
|---|---|---|
| 無 | — | 空き |
| 盤 | — | コンソール（読み: UART 受信、書き: UART 送信）。柄 0/1/2 の既定 |
| 籍 | 典籍の番号 | 位置は**開表側**が持つ（現行は目録側。ここを移す） |
| 管讀 / 管書 | 管の番号 | パイプの読み端 / 書き端 |

- 開表の項目は参照数を持ち、0 になったら実体の後始末（典籍なら何もしない、管なら端の数を減らす）。
- 現在の `開`/`閉`/`讀入`/`柄書` はこの 3 段に載せ替える。誤り番号（`-EBADF` など）と柄の数値規約（0/1/2 + 3 以降）は変えない。
- 開いた典籍の「現在位置は目録に 1 つ」という現状の仕様は破る必要がある（同じファイルを 2 行程が開ける）。
  これは ABI の互換破壊ではなく内部表現の変更で、既存テストが通ることを回帰条件にする。

### 6.1 パイプ（漢令 19 `造管`）

- 管 1 本 = 頁池から取る 1 ページ（4 KiB の輪状バッファ、読み位置・書き位置・読み端数・書き端数）。同時 8 本まで。
- `造管(対址)` は読み端の柄と書き端の柄を `対址[0]`/`対址[1]` に書く。
- 読み: データがあれば読む。空で書き端が残っていれば `待管` で眠り、起床後に**漢令を再試行**（`ELR -= 4`）。
  空で書き端が 0 本なら 0（EOF）を返す。
- 書き: 空きがあれば書く。満杯なら `待管` で眠って再試行。読み端が 0 本なら `-EPIPE`（シグナルは未対応のため誤りで返すのみ）。
- 管のどちらかの端が変化（書き・読み・閉じる）したら、その管を待つ行程を `可` に戻す。

### 6.2 `複寫柄`（漢令 20）

`複寫柄(旧, 新)`: 柄 `旧` の開表項目へ `新` を向ける（`新` が使用中なら先に閉じる）。殻がリダイレクトとパイプの接続に使う。

## 8. 殻の拡張

漢殻文法（Issue #8）のうち、本設計で扱う範囲:

| 構文 | 意味 | 実現 |
|---|---|---|
| `命令 引数…` | 内蔵になければ外部命令を `生行程` し、`待行程` で待つ | §5 |
| `甲 傳 乙` | 甲の標準出力を乙の標準入力へ（パイプ） | `造管` + `複寫柄` + 2 回 `生行程` |
| `命令 奏入 名` | 標準出力を典籍へ（`創` してから開いて柄 1 に複写） | `創` + `開` + `複寫柄` |

- 内蔵のまま残す: `終`（殻自身を終える）、`助`（命令一覧）。`響`・`讀`・`目`・`書` は外部命令へ移行できる
  （移行時に `助` の一覧を実在の命令から生成する）。
- 外部命令の最小セット（後続実装）: `讀`（柄 0 または名前から読んで柄 1 へ）、`目`（一覧）、`索`（一致行だけ通す）、`計`（バイト・行数）。

## 9. exec と fork（最終段）

- **exec（`換行程`）**: 自分の窓の頁と頁表を捨て、§5.3 の 3〜5 を自分の枠に対して行う。柄は引き継ぐ。
  生成経路の部品をそのまま使うため、新規の仕組みは少ない。
- **fork（`分行程`）**: 親の頁表を走査し、使用中のページを**全複製**する（初版は copy-on-write なし。窓は最大 2 MiB なので許容）。
  子の保存フレームは親の複製で `x0`=0 にする。柄表は全項目を複製し参照数を増やす。copy-on-write は、
  ページ単位の参照数と書き込みアボートの処理が要るため別段階とする。

## 10. メモリ配置の見直し

現行の固定配置は 2 行程前提で、8 行程にすると衝突する（例: 頁表 12 KiB × 8 = 96 KiB が `0x40412000` から
刻数（`0x40420000`）まで延びる）。次のように整理する案。数値は概案で、実装時にリンカスクリプトと突き合わせる。

| 領域 | 現行 | 案 |
|---|---|---|
| 行程表 | `0x40300000`（保存フレーム）ほか分散 | `0x40300000` に統合（128 B × 8）。保存フレームは核棧の上 |
| 系統開表・管表 | なし | `0x40310000`（開表 32 × 64 B、管表 8 × 64 B） |
| 核棧 | `0x40320000` に 64 KiB × 2 | 同位置に 16 KiB × 8（実測要） |
| 典籍の目録・本文 | `0x40340000` / `0x40350000`、現行 8 件 | 16 件に拡大（目録 1 KiB・本文 4 KiB） |
| 頁表 | `0x40412000` から行程ごとの固定領域 | **頁池から動的に確保**（固定領域を廃止） |
| 頁池 | `0x40430000` からバンプ（`0x405FFFFF` まで約 1.7 MiB） | `0x41000000`–`0x43FFFFFF`（48 MiB）を空き頁の**ビットマップ**で管理。EL1 RW の 2 MiB ブロックを追加で恒等写像 |

頁池の解放: 頁単位のビットマップ（1 ビット = 1 ページ）。確保は先頭から探索、解放はビットを戻す。
行程終了時に窓のレベル3表を走査して返す。

## 11. 段階とテスト

各段階は独立した PR にし、`make test` の QEMU ケースを足す。

| 段階 | 内容 | 受入条件（QEMU ログで確認） |
|---|---|---|
| P0 | 土台: 行程表の統合・`程限` 8・頁池の解放・柄表/開表への載せ替え | 既存テストが全て通る。頁を確保→解放→再確保で同じアドレスが返る |
| P1 | 漢像の生成と `生行程`/`終行程`/`待行程`、init | init が最小命令を生成し、終了コードを回収して表示する。生成・回収を 20 回繰り返しても頁が漏れない |
| P2 | 引数・柄の継承、殻が外部命令を起動 | 殻から外部命令 `響` を実行して出力が出る。無い命令は `殻不明` |
| P3 | `造管`/`複寫柄`、`傳`・`奏入` | `讀 史記 傳 計` で件数が出る。`奏入` で作った典籍を `讀` で読み戻せる。書き端が閉じて EOF になる |
| P4 | `換行程`、`分行程`（全複製） | 子で `x0`=0。fork した子が exec で別の命令になる。親子でデータが独立 |

回帰テストも併走させる: 既存の甲・乙の 2 行程テスト（プリエンプション・待機起床・境界検査）は P0 以降も維持する。

## 12. 未決事項と危険

- **核棧の大きさ**: 64 KiB → 16 KiB にしてよいか。`漢令處理` の最大呼び出し深さの実測が要る。
- **コンパイラ**: 別ブートされる漢像のリンクに必要な機能（基底アドレス指定、`.data`/`.bss` の扱い）が現在の `chokanbun` で足りるか未確認。
  ローカル変数の alloca をループ外へ集約する修正（PR #29）は済み。グローバル変数の扱いは要調査。
- **命令キャッシュ整合**: 実機では必須。QEMU の TCG では見逃しやすいので、手順をコードに必ず入れる。
- **孤児と init の死**: init が終了すると全体が止まる。init は終了せず再起動する設計とし、核は init の終了を検出したら停止ではなく panic にする。
- **時間**: `待機` と `待子`/`待管` の混在。起床は `割込切替` の覚醒処理に統合するか、各所で `可` に戻すかを実装時に決める。
- **POSIX との対応**: `生行程` は `posix_spawn`、`換行程`+`分行程` は `exec`+`fork`、`待行程` は `waitpid`、`造管` は `pipe`、`複寫柄` は `dup2`。
  シグナルを持たないため、`SIGPIPE`・`SIGCHLD` 相当は誤り番号で代替する。
