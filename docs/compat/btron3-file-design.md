## 2. BTRON3 のファイルモデル（要求の要約）

### 2.1 ファイルシステムと接続

- ファイルシステムはデバイス上の論理単位で、**ルートファイル（ID 0）**を持つ。名前（20 文字）、デバイス位置名（20 文字）、物理デバイス名（8 文字）を持つ。
- 使うには**接続**（`att_fls`）が要り、**接続名**（8 文字）が付く。パスが接続名で始まれば、そのファイルシステムのルートからの絶対指定になる。
- 管理情報（`FS_STATE`）: ブロックサイズ、ファイル数の上限（16 ビット ID に基づく）、言語、アクセス管理レベル（0〜2）、総ブロック数・空きブロック数、作成・更新時刻。

### 2.2 ファイル

- 種別は**通常ファイル**（レコード列）と**リンクファイル**（他のファイルを指す）。ファイル ID は 16 ビットで、ファイルシステム内で一意。
- 通常ファイルの**レコード**: 型（0=リンク、1〜31=データ）、サブ型（16 ビット）、大きさ、本体。番号は 0 から。末尾には**終端レコード**（実体の無い目印）があり、`rea_rec`/`wri_rec` などは終端レコードに対して `ER_ENDR` を返す。**現在レコード**があり、開くと先頭、空なら終端を指す。`ins_rec` は現在レコードの前に挿入、`apd_rec` は末尾に追加。
- 大きさの制限: レコードの最大、ファイルの最大、レコード数の最大は**原文に定めが無い**（超えたときは `ER_SZOVR`、同時にロックできる数や同時に開ける数を超えると `ER_LIMIT`、数値は未規定）。したがって §4.3 の値は実装依存の選択として記録する。
- リンクレコードは 52 バイトの固定長。**浮動リンク**（既定）は名前と作成時刻で対象を探し、**固定リンク**（`F_FIX`）はファイル ID に固定して参照数を数える。リンクの参照数は最大 255。
- ファイル名は最大 20 文字で、変更できる（`chg_fnm`）。名前は対象ファイルの側でなく、リンクの付随情報（`F_LINK` の `f_name`）に持ち、**同じファイルの中に同名のリンクが複数あってよい**（識別はファイル ID。パスでは「名前＋出現番号」で選ぶ、§2.3）。`fil_sts`/`ofl_sts` は成功時にファイルの参照数を返す。

### 2.3 パス名

- TC 文字列で最大 256 文字。区切りは `TC_FDLM`（0xFF21）、**名前と出現番号の区切り**は `TC_FSEP`（0xFF22。同名のリンクのうち何番目かを 0 始まりで選ぶ。省略すると 0）、自分（作業ファイル）を表す印は `TC_FOWN`（0xFF23）。
- 接続名で始まれば絶対、そうでなければ作業ファイルからの相対。行程ごとに作業ファイルを持つ（`chg_wrk`）。
- `get_lnk` の指定: `F_NORM`（作業ファイルから）、`F_BASED`（引数のリンクから）、`F_DIRECT`（リンクレコードそのものを得る）。

### 2.4 アクセス制御とロック

- 所有者名、グループ名（利用者あたり最大 4）、所有者・グループ・公開の各 R/W/E、利用者レベル 0〜15、属性（読取専用・削除不可・アプリ定義 2 ビット）、パスワード。
- **ビット配置**: 所有者のアクセス（`f_ownacc`、16 ビット）は下位 3 ビットが R・W・E。グループ（`f_grpacc`）と公開（`f_pubacc`）は、それぞれ**利用者レベルのしきい値**を R・W・E に 4 ビットずつ持つ（上位 4 ビットは未使用）。しきい値は 0〜15 で、**利用者レベルの数がしきい値以下の利用者**に許す。判定は、所有者ならその権限、グループの所属ならグループのしきい値、そうでなければ公開のしきい値。
- `get_dfm`/`set_dfm` の既定アクセスモードは `DA_MODE`（`f_ownacc`、`f_gacc[4]`＝グループごとのしきい値、`f_pubacc`）。定義の後半は原文が途切れていたため、フィールドの並びは**要確認**。
- **アクセス管理レベル**（ファイルシステム単位）: 0=アクセス管理をしない、1=一部だけ管理、2=すべてのファイルを管理。1 の「一部」の範囲は原文から確定できない（要確認）。
- パスワードは `opn_fil` で一致しないと開けない（`ER_PWD`）。形式・長さの上限・保存方法は原文に規定が無く、実装依存（§6）。
- オープンモード: 読み・書き・更新、排他、書込排他。レコード単位のロック（ロック・解除・試行・確認）。

### 2.6 構造体（フィールドは原文どおり、型は W=32 ビット、H/UH=16 ビット、TC=16 ビット）

`LINK`（fs_name[20]、f_id、atr1〜atr5）= 52 バイト。`F_LINK`（f_ctime、f_atype、f_name[20]、f_id、rf_ctime、fs_name[20]、fs_locat[20]）。`FS_STATE`、`F_STATE`（f_type、f_group[14]、f_grpacc、f_pubacc、f_nlink、f_index、f_size、f_nblk、f_nrec、f_ltime/atime/mtime/ctime）、`F_LOCATE`、`F_ATTACH`、`F_TIME`。`f_type` の上位 4 ビットが種別（0=リンク、1=通常）。

                                                       │ 漢令 128〜159（LINK・F_STATE を検査付きで複製）

- 録層は篇藏の**利用者**の 1 つ。篇の本文を直接解釈するのは録層だけで、篇藏は `録` の中身を知らない（D1・D2）。
- 開いたファイルの記述子（`fd`）は、既存の柄表 → 開表に載せる。開表の項目に**現在レコード番号とレコード内オフセット**を足す（現在の「位置」1 語は典籍用に残す）。

## 4. データモデル

### 4.1 `録` の篇の本文

- 先頭に**ファイル見出し**（128 バイト固定）、続いてレコードの列。見出しは `F_STATE` の元になる情報（種別、所有者名、グループ、アクセス、属性、アプリ型 `atype`、リンク数、時刻）を持つ。
- レコード = **レコード見出し**（8 バイト: 型 1、予約 1、サブ型 2、本体の大きさ 4）+ 本体（4 バイトの倍数に切り上げ）。リンクレコードは本体が 52 バイト固定の `LINK`、加えて `F_LINK` の付随情報（名前など）を本体に続けて持つ。
- レコード番号 → 位置は、見出しにある**レコード索引**（小さい間は全走査でよい）で引く。`see_rec`/`fnd_rec` は索引と線形走査。
- 篇藏上の 64 ビット篇ID と、BTRON3 の 16 ビットファイル ID は、録層の**ID 表**で対応づける。ファイル ID は **0 をルート**に予約し、**単調増加で割り当て、再利用は回り込んだときだけ**とする（原文は再利用規則を述べていない。要確認）。

### 4.2 リンクとパス解決

- 各ファイル名は、それを指すリンクレコードの付随情報に持つ。`get_lnk` は次の手順で決定的に解決する。
  1. 先頭が接続名か `TC_FOWN` か、いずれでもないかで起点（ルート／作業ファイル／相対）を決める。
  2. 起点の通常ファイルのレコードを先頭から走査し、型 0 のリンクレコードのうち、付随情報の名前が要素の名前部分と**完全一致**するものを数え、**出現番号**（`TC_FSEP` の後ろ。省略は 0）番目を選ぶ。足りなければ `ER_NOEXS`。
  3. 浮動リンクなら対象を（名前・作成時刻で）探して `LINK` の `f_id` を確定する。固定リンクならその `f_id` を使う。
  4. 末尾まで繰り返し、`F_DIRECT` ならリンクレコードを、それ以外は指す先のファイルへの `LINK` を返す。
- 区切りは内部でも TC のまま扱う。UTF-8 への変換は録層の外（篇藏との接点）でしか行わない。

### 4.3 容量（RAM のみの間）

| 項目 | 上限（案） | 備考 |
|---|---|---|
| ファイルシステム | 2 個 | `RAM`（利用者用）と `SYS`（埋め込み像用、読取専用） |
| ファイル／FS | 32 | 見出し表は核に固定 |
| レコード／ファイル | 32 | |
| 本文の合計／ファイル | 4 KiB（頁 1 枚から開始） | 頁池から取る。拡張は段階 B6 |
| リンク参照数 | 255 | 原文どおり |

上限は**原文が定めない値**（実装依存の選択）。段階ごとに引き上げ、引き上げは互換層から見えないようにする。超えたときは、ファイル・レコードの大きさは `ER_SZOVR`、ファイルやロックの数は `ER_LIMIT`、領域不足は `ER_NOSPC` を返す。

## 5. 記述子と排他

- `fd` は柄表の番号（既存の 3 以降）で、開表の種に `録` を足す。対象 = (ファイルシステム番号, ファイル ID)。
- オープンモードの衝突規則（排他・書込排他）は、開表の走査で判定する。原文で確認できたのは、`F_EXCL` が他のタスクの同時オープンを禁じ、`F_WEXCL` が他のタスクの書込・更新での同時オープンを禁じることまでで、組み合わせの表は図にあり本文に無い。**暫定の規則**（排他は誰とも同居しない／書込排他は他の書き手と同居しない／それ以外は同居。衝突は `ER_BUSY`）を実装し、要確認とする。同じタスクの二重オープンの扱いも原文に無く、同居を許す。
- `del_fil` は、開いている行程がある・作業ファイルとして使われている・削除禁止属性のとき失敗する（`ER_BUSY`/`ER_PERM`）。`force`=0 でリンクレコードを含むファイルは `ER_REC`。レコードのロックを他の記述子が持つと、読み書き・大きさ変更・削除は `ER_LOCK`、他の記述子が使っているレコードの削除は `ER_BUSY`。`F_LOCK` は解除まで待ち、`F_TSLOCK` は待たず、`F_CKLOCK` は確認のみ。
- レコードロックは (ファイル, レコード番号) と行程 ID の表で持つ。行程終了時に解放する（`同終了` と同じ場所で呼ぶ）。`ER_LOCK` は他行程が持つときに返す。

## 6. アクセス制御

- 所有者は作成した行程の `usr_name`、グループは同じく `grp_name1`、アクセスモードの既定は利用者ごとの既定（`get_dfm`/`set_dfm`）。判定は**開くときに 1 回**、利用者レベルとグループ所属で行う（レベル 0 は常に可）。
- アクセス管理レベル（`FS_STATE.fs_level`）が 0 のファイルシステムでは検査を空にする。2 では §2.4 の判定をすべてのファイルに行う。1 の「一部」は範囲を確定できないため、当面は 2 と同じ扱いにする（実装依存）。`RAM` ファイルシステムの既定は 2、`SYS`（読取専用）は 0。
- パスワード（`chg_fpw`/`opn_fil`）は、**原文に形式・保存方法の規定が無い**ので、平文を保存せず**ハッシュ（固定長）を保存**する実装依存の選択とし、方式は B4 で決めて記録する。

## 付記: B1 の実装上の選択

- 篇藏の F1（篇ID とメタデータ表）がまだ無いので、録層は**ファイル見出しを核の固定表に、本文を頁池の頁 1 枚に**置いている（D2 の暫定）。篇藏 F1 の実装後に、見出しと本文を型 `録` の篇へ移す。
- 起動時に RAM FS へ試験用のファイルとリンク（`docs`・`memo`×2・`ghost`・`deep`）を作る。B2 で `cre_fil` が入ったが、B1 の試験がこの初期ファイルに依存するため残している。試験を自前で作る形へ移した時点で削る。
- 浮動リンクは、指す ID のファイルが無いとき、作成時刻（`rf_ctime`）が同じファイルを探して付け直す。固定リンク（付随情報の旗 bit0）は探さない。
- 装置名・接続名は 8 文字まで読み、それ以上は読まない（TNULL が無くても 8 文字で止める）。`lst_fls` の個数が負（`F_GETDEV`・`F_GETNAM`）は意味が未確認のため `ER_PAR`。`det_fls` の取り出し指定は無視する。
- 録層の初期化は、核の頁池の自己試験の後（行程の投入の直前）に行う。初期化で頁を取るため、頁池の総数の検査より前に置くと検査が合わなくなる。

## 付記: B2 の実装上の選択

- **記述子は柄表に載せず、録層専用の開表（16 件）に置いた**（設計 D5 からの変更）。柄表・開表は典籍の読み書きと結びついており、`録` の項を足すと既存の `開`/`閉`/`讀入` の経路すべてに分岐が要る。B3（レコード操作）でレコード位置を持たせる際にも別表のほうが素直なので、B2 では分けた。記述子は `(世代 << 8) | (枠 + 1)` で、閉じた後に再利用されても値が変わり、古い記述子は `ER_FD` になる。他の行程の記述子も `ER_FD`。行程の終了時（`程終了型`）に全て閉じる。柄表との統合は B3 で再検討する。
- `cre_fil`/`cre_lnk` の `lnk` は**親ファイル**（リンクレコードを足す場所）と読んだ。`cre_fil` は成功すると `lnk` を新しいファイルの LINK で置き換え、`F_UPDATE` で開いた記述子を返す。原文の「lnk は固定リンクのとき対象」の記述は意味を確定できなかった（要確認）。
- `opt` は `F_FLOAT`(0)・`F_FIX`(1) だけ。`F_FILEID`(2)（ID を指定する）と、`A_MODE` が NULL でない場合は `ER_PAR`。理由: ID の渡し方と `A_MODE` の大きさが原文で確定できない。B4 でアクセス制御と一緒に対応する。
- 名前は 1〜20 文字で、`TC_FDLM`・`TC_FSEP`・`TC_FOWN` を含むと `ER_FNAME`（パスで引けなくなるため）。**同名は許す**（出現番号で選ぶ）。
- ファイル ID は FS ごとの「次の ID」から空きを探し、16 ビットで回り込む（0 は予約）。ファイルは FS あたり 32、親ファイルのレコードは 36 件（本文 4 KiB ÷ リンクレコード 112 B）。超えるとそれぞれ `ER_LIMIT`・`ER_SZOVR`。頁が取れなければ `ER_NOSPC`。
- `del_fil`: `org`（親）が与えられたら、その中の最初のリンクレコードを取り除く（無ければ `ER_NOEXS`）。**force=0 で、リンクレコードを含む、または他のリンクが残る場合は `ER_REC`**。force≠0 では、含んでいたリンクの先の参照数を減らして消す（他のリンクは宙に浮く）。戻り値は、その減算で参照数が 0 になったファイルの数。参照数が 0 になっても先は自動では消さない（孤児として残る。`org`=NULL の `del_fil` で消せる）。開いている、作業ファイルとして使われている、削除禁止属性（0x20）、ルートのときは拒む。
- `opn_fil`: モードは `F_READ`(4)・`F_WRITE`(2)・`F_UPDATE`(6)・`F_EXCL`(0x100)・`F_WEXCL`(0x200) の組み合わせだけ（読み書きのどちらも無い、または他のビットは `ER_PAR`）。衝突の判定は §5 の暫定規則どおり、**別の行程**との間だけで見る。同じ行程の二重オープンは許す。パスワードは B4 まで検査しない（アドレスだけ確かめる）。
- `fil_sts`/`ofl_sts`（**M2 で置換**: F_STATE は 96 B、F_LOCATE は 100 B。[spec-verification §6.1](btron3-spec-verification.md)）: `F_STATE` は自然な整列で 68 B（`f_type`@0 `f_group`@2 `f_grpacc`@30 `f_pubacc`@32 `f_nlink`@34 `f_index`@36 `f_size`@40 `f_nblk`@44 `f_nrec`@48 `f_ltime`@52 `f_atime`@56 `f_mtime`@60 `f_ctime`@64）。名前は、そのファイルを指す最初のリンクの名前を 20 文字（40 B）で書く（ルートは空）。`F_LOCATE` は書式が読めなかったので NULL のみ。
- `det_fls` は、その FS を開いている記述子があると `ER_BUSY`。

## 付記: B3 の実装上の選択

- **レコードは頁 1 枚（4 KiB）に詰める**（設計 §4 の暫定）。データレコードは見出し 8 B（型、副型、大きさ）+ 本体（4 の倍数に切り上げ）、リンクレコードは 112 B 固定。1 つのデータレコードは 4088 B まで。超えると `ER_SZOVR`（`ER_NODSK` に当たる errno が無いため）。
- 現在レコードは**記述子ごと**に持つ（開表の +48）。オープン時は 0（空なら終端）。終端レコードは番号 = レコード数。`see_rec` は終端までは移れる。
- 現在レコードの動き（原文が途切れていた部分）: `ins_rec` は挿入したレコードが現在レコードのまま（番号は変わらない）。`apd_rec` は番号を変えない。`del_rec` の後は次のレコード（無ければ終端）。`rea_rec`/`wri_rec`/`trc_rec` は変えない。
- **他の記述子の現在レコードとロックは、挿入・削除で番号がずれる分を直す**。試験 `録試` の「ロックは同じレコードに付いてくる」で確認した。
- ロックは**記述子ごとに 1 件**（開表の +56）。別のレコードを続けてロックすると `ER_LIMIT`。`F_LOCK` は**待たない**（`F_TSLOCK` と同じ。待ちの実装は核のブロック機構が要る）。`F_CKLOCK` は他の記述子のロックがあれば `ER_LOCK`、無ければ 0。ロックは記述子を閉じる・行程が終わると外れる。
- `fnd_rec` は `F_FWD`(0) と `F_NFWD`(1)（型マスクの否定）だけ。現在レコードも探索に含める。成功の戻り値は 0。`typemask`=0 は `ER_REC`。
- `rea_rec` の戻り値は現在レコードの型。リンクレコードは offset=0・size>=52 のとき LINK 全体を返す。`wri_rec` はリンクレコードの属性（LINK の +42〜+51）だけ書ける。データレコードは offset が大きさ以下で、`buf` が NULL なら領域の確保だけ（ゼロ詰め）。`units` は無視（漢令の引数が 6 個までのため、互換層で捨てる）。
- `ins_rec`/`apd_rec` のリンクは、先が存在し、FS が接続されていること（`ER_NOEXS`/`ER_NOFS`）、参照数が 255 未満（`ER_LIMIT`）。LINK に名前が無いので、リンクレコードの名前は先を指す最初のリンクの名前を写す。
- `xch_fil` は本文・レコード数を入れ替え、時刻は入れ替えない。両方が `F_UPDATE` で開かれている必要（原文の `ER_FD` の条件は「更新または排他モード」と読めたが、確定できず「書ける記述子」と解釈した）。他の記述子のロックがあれば `ER_LOCK`。別の FS は `ER_XFS`（RAM と書込可能な別 FS が無く、試験できない）。
- 漢令の帯を広げた: ファイルは 128〜175、イベント／デバイスは 192〜207 に移した（互換層の設計書）。
- errno の対応を追加: `-ENODATA`→`ER_ENDR`、`-ETXTBSY`→`ER_LOCK`、`-EXDEV`→`ER_XFS`（`user/btron/er.mkn`）。

## 付記: B4 の実装上の選択

- **アクセスの判定**（`録権`。M2 で、FS レベル 0 の近道の廃止・所有者の特例・隠し名を反映した。[spec-verification §6.1](btron3-spec-verification.md)）: FS のアクセス管理レベルが 0 なら常に許す。呼出側の利用者レベルが 0 なら許す。所有者名が一致すれば `f_ownacc`（下位 3 ビットの RWE）、そうでなくファイルのグループ名が呼出側のグループ 1〜4 のどれかと一致すれば `f_grpacc`、それ以外は `f_pubacc` で判定する。`f_grpacc`/`f_pubacc` は R=ビット 11〜8、W=7〜4、E=3〜0 に「許す最大の利用者レベル」を持ち、呼出側のレベルがそれ以下なら許す（原文の「4 ビットずつ」「0 が最高」の読み）。アクセス管理レベル 1 は 2 と同じに扱う。
- **適用箇所**: `opn_fil`（読みは R、書きは W）、`cre_fil`/`cre_lnk`（親への W）、`del_fil`（`org` があれば親の W、無ければファイル自身の W）。アクセスの誤りは、使用中（`ER_BUSY`）より先に返す。レコード操作・ロックは `opn_fil` で判定済みとして再検査しない。
- **所有者・グループ**: `cre_fil` が作ったファイルの所有者名は呼出側の利用者名、グループ名は `A_MODE.f_grpno`（1〜4 が呼出側のそのグループ）または既定モードのとき呼出側のグループ 1（空なら無し）。`chg_fmd`・`chg_fat`・`chg_fpw`・`chg_ftm` は所有者かレベル 0 だけ（`ER_ACCES`）。
- **（M2 で置換: 原文の並びは `f_ownacc; f_grpacc; f_pubacc; f_grpno`、`DA_MODE` は 16 B）`A_MODE` = {UH f_ownacc; UH f_grpno; UH f_grpacc; UH f_pubacc}（8 B）**、**`DA_MODE` = {UH f_ownacc; UH f_gacc[4]; UH f_pubacc}（12 B）**。原文では `f_ownacc` の先が欠落しており、`chg_fmd` の説明（所有者・グループ・公開・グループ番号）からの再構成（要確認）。`chg_fmd` では各欄の 0x8000（`F_NOCHG`）でその欄を変えない。`cre_fil` では 0x8000 を許さず `ER_PAR`。
- **既定のアクセスモード**は行程ごと（`P_USER` の予備 12 B、子へ継ぐ）。未設定なら (7, 0x0FFF×4, 0x0FFF) で、全員に全レベルで許す。そのため既定のままではアクセス制御は実質働かず、`chg_fmd` か `set_dfm` で絞る。
- **パスワード**: 20 文字まで。保存は 64 ビットのハッシュで、**暗号学的な強度は無い**（原文に形式の規定が無いための暫定）。`opn_fil` は、パスワードがあるファイルで未指定・不一致なら `ER_PWD`。レベル 0 でも免除しない。`chk_fil` は `F_PASWD` を足したときだけ照合する。21 文字以上の指定は `chg_fpw` で `ER_PAR`、照合では不一致（20 文字の前方一致でも通さない）。
- **`chk_fil(F_EXIST)` の戻り値**: ビット 0〜2 が呼出側に許される E・W・R、ビット 3 がパスワード有り、ビット 4〜7 が `f_type` の O（書込禁止）・P（削除禁止）・A・B。原文の欄の並びの読みで、確定していない。
- **`chg_fnm`**: ファイルを指す最初のリンクレコードの名前だけを替える（`fil_sts` が返す名前と同じ）。空・不正な名前は**原文どおり `ER_ACCES`**（`cre_fil` の `ER_FNAME` と違う）。削除禁止は `ER_PERM`、呼出側にそのファイルへの W が無ければ `ER_ACCES`。
- **`chg_ftm`**: `F_TIME` = {W f_ltime; W f_atime; W f_mtime}（12 B）。NULL は全て現在時刻、0 の欄は変えない。`f_ltime` は見出しの +168 に新設（作成時刻で初期化）。
- 漢令の番号は 163〜170（162 は `fnd_lnk` 用に空き）。`ER_PWD` ← `-ENOKEY` の対応を追加した。

## 付記: B5 の実装上の選択

- **像ファイル**: 起動時に、埋め込み漢像（像表）1 つにつき SYS FS（FS 番号 1、アクセス管理レベル 0）にファイル 1 つを作る。ファイル ID = 像番号 + 1、アプリ型は 0x4B42、見出しの +176 に 像番号 + 1 を持つ（0 なら通常のファイル）。名前はルートのリンクレコードに持つ。**本文は空**なので、レコード操作で像の中身は読めない（大きなファイルの本文は B6 の課題）。
- **名前の文字**（M5 で置換）: 漢像の名前は `tools/gen-images.sh` が **JIS X 0208 の 2 バイト符号**（原文のとおり。EUC-JP から 0x80 を引く）の TC[20] にして像表の名前の直後に置く。試験は JIS の値（録試 = 0x4F3F 0x3B6E）で引く。
- **SYS は起動時は未接続**。使うには `att_fls` で接続する（読取専用）。接続名は任意で、パスは `<接続名>/<漢像の名前>`。
- **`cre_prc`（漢令 70）**: `pri` は 0〜255 の検査だけでスケジューラへは反映しない（優先度の群が無い）。`msg` は NULL 可。型 0 のとき本体の NUL 区切りの文字列が `argv[1]` 以降になり、`argv[0]` は漢像の名前。型 0 以外はメッセージの配送が未実装で、引数なしになる。本体は 255 B まで。像ファイルでないファイルは `ER_REC`、実行（E）のアクセスが無ければ `ER_ACCES`、他の行程が `F_EXCL` で開いていれば `ER_BUSY`。子は親の利用者情報・作業ファイルを継ぎ、BTRON3 流（終了時に親へ `MS_EXIT`、枠を即解放）。
- 従来の漢令 64（`BTRON生行程`、典籍の名前と引数文字列）は、殻の起動経路と既存の試験の補助として残す。BTRON3 のアプリは `cre_prc` を使う。
