## 読む前の注意

- 要求は原文を独自に要約したもの。原文取得時に日本語が文字化けした箇所があり、**パラメータの細部・エラーコードの割当・一部の節は未確認**。各節の末尾に「要確認」を残した。適合判定の前に原文との突き合わせが必要。
- 本書は適合を主張しない。状態は「未実装」＝**BTRON3 の API として呼べるものが無い**ことを指す。機能の一部が別形式で既にある場合は「部分適合（機能のみ）」と書くが、API・ABI が違うので適合確認済みへ進む根拠にはならない。
- 既存実装の根拠: `docs/abi-aarch64.md`、`docs/design-process-exec.md`、`kernel/proc/`、`kernel/vfs/`、`kernel/kernel.mkn`。

## 1.1 プロセス／タスク管理（kernel/proc.html）

### 要求の要約
- 行程（プロセス）が管理単位で、行程は主タスク 1 個と 0 個以上の副タスクを持つ。行程・タスクは正の整数 ID を持つ。
- 起動時に初期行程が作られ根となる。親が終わると子は祖父へ付け替わる。
- 状態は 存在しない／実行可能／実行中／待ち。副タスクも主タスクと同じ遷移に従う。主タスクの終了で副タスクも強制終了、副タスクの終了では行程は終わらない。
- 優先度は 0（最高）〜255。0–127 は厳密な優先度順（同位は時分割）、128–191 と 192–255 は群内ラウンドロビンで優先度は配分比。低優先でも実行時間は保証される。優先度の変更は同じ群の中に限る。
- 利用者情報（`P_USER`）: 利用者名・グループ名 4 個・利用者レベル 0–15・ネットワーク利用者レベル 1–15。初期行程の値はシステムが設定。
- 生成（`cre_prc`）は、ファイルのリンク・優先度・初期メッセージを指定する。通常終了（`ext_prc`）は終了コードを親へ通知し、開いた資源を自動解放する（終了時削除指定のものを除く）。強制終了（`ter_prc`）は自分・親・指定行程を対象に、子孫ごとの終了も選べ、自分より高い利用者レベルの行程は終了できない。

### API 照合

**その他の差分**: 状態の名称・遷移は概ね対応（空・実行可能・待機・子待ち・終了済み未回収）するが、BTRON3 に「ゾンビ」はなく、終了通知はメッセージ。親の付け替えは設計済み（`design-process-exec.md` §4: init へ付け替え）で方向は一致するが「祖父へ」か「init へ」かの差は**要確認**。優先度群 A/B/C のスケジューラは未設計。
**G5 の選択（実装依存・解釈）と要確認**（`ter_prc`/`prc_sts`）:
- `ER_LEVEL` は「呼出側より**上位**（level の数が小さい）の行程は終了できない」と読んだ。原文は上位の向きを明記していない。
- MS_TERM を受け取るのは対象の親だけ。TERM_ALL では子孫に送らない。親・祖先を対象にして呼出側自身も終わるときは、呼出側にも送らない。
- 行程が終わると、生きている子は終わる行程の親へ付け替える（原文の一般規則どおり。親が無ければ孤児）。強制終了にも同じ規則を使う。
- `prc_sts` の名前の書き先は大きさの記載が無く、TNULL 1 文字だけを書く。優先度は優先表の値（既定は群 B の中央 128）を返す。
- 終了させられた行程の資源は、正常終了と同じ（柄・グローバル名・メッセージキュー・窓）。共有メモリ等は未対応。

**G4 の選択（実装依存・解釈）と要確認**:
- `chg_usr` は原文（直接確認後）で「システムプロセスでのみ実行可能」。**level 0 の行程をシステムプロセスとみなし**、それ以外は `ER_ACCES`（原文のエラー表に無いが、他の権限エラーと同じ）を返す。
- 起動時の利用者（root・level 0・net_level 1）の名前と net_level の値は原文に規定が無く、実装依存として選んだ。子は生成時に親の写しを受け取る（原文どおり）。
- 利用者名の末尾 2 文字の接尾部の意味、グループ名の検証は未実装（領域を写すだけ）。
- `set_tod` で `time` を渡したときは設定せず変換だけにする（原文の `ER_ACCES` の条件「time が NULL のとき」から読んだ）。年は 1985〜2100 のみ受け付ける。

**要確認**: `P_INFO` の項目、各 `ER_*` の発生条件、`slp_tsk` の時間単位、副タスクの最大数（`ER_LIMIT`）。

## 1.2 メッセージ管理（kernel/message.html）

### 要求の要約
- 行程ごとにメッセージキュー（FIFO）。宛先・送信元は行程 ID。メッセージは 型・本体サイズ・本体 から成る。型は 1–31、ビットマスクで複数選択可。
- 1=異常終了、2=正常終了、3=強制終了、4=タイムアウト、5=システムイベント、6–23=システム予約、24–31=アプリ用。
- 送信オプション `WAIT`/`NOWAIT`/`CONFM`、受信オプション `WAIT`/`NOWAIT`/`WAIEVT`/`CLR`/`NOCLR`/`CHECK`。
- ハンドラは型ごとに定義（再定義で置換）。定義済みの `MH_NONE`（無視）・`MH_BREAK`（待ちを中断して `ER_MINTR`）・`MH_TERM`（行程終了）。ハンドラは入れ子にならず、`ret_msg` で戻る。

| API | 要点 | 既存実装 | 状態 |
|---|---|---|---|
| `snd_msg` | 送信（`WAIT`/`NOWAIT`、宛先 pid / 0 / -1） | `user/btron/msg.mkn` → 漢令 信送 80（`kernel/proc/msg.mkn`）。8 件のキュー、満杯で WAIT は眠る。`CONFM` は `ER_PAR`（未対応） | 部分適合（`CONFM` 未実装） |
| `rcv_msg` | 受信（型マスク、`NOWAIT`/`NOCLR`/`CHECK`/`WAIEVT`） | 漢令 信受 81。最古の該当を返す。`CHECK`（2）は合う型が無くても別の型があれば先頭 8 バイトを返す。`WAIEVT`（4）は `WAIT` と同じに待つ（型マスク 0 可、`NOWAIT` と併用は `ER_PAR`） | 部分適合（`brk_msg` で待ちを解く `ER_NOME`・`ER_MINTR`・`CONFM` が未実装） |
| `clr_msg` | 消去 | 漢令 信消 82 | 実装済・未検証 |
| `req_tmg` / `can_tmg` | タイムアウトメッセージ | 漢令 83・84（`kernel/proc/msg.mkn` の時限表 16 件。刻 25 ms へ切り上げ、`覚醒` が `MS_TMOUT` を積む） | 実装済 |
| `def_msg` / `ret_msg` / `brk_msg` | ハンドラ定義・復帰・中断 | なし。EL0 への非同期上り呼びが必要 | 未実装 |
| `req_tmg` / `can_tmg` | タイムアウトメッセージ | 上の行（漢令 83・84） | 実装済 |
| `def_msg` / `ret_msg` / `brk_msg` | ハンドラ定義・復帰・中断 | なし。EL0 への非同期上り呼びの仕組み（シグナル相当）が必要 | 未実装 |

**方針メモ**: ハンドラは EL0 へ非同期に割り込む機構が要り、POSIX シグナルより先に必要になる。終了通知（型 1–3）が `cre_prc`/`ext_prc` の適合の前提なので、**1.1 の適合は 1.2 に依存する**。
**G3a の選択（実装依存・解釈）と要確認**:
- `rcv_msg` の成功時の戻り値は原文で「0 以上」としか確認できなかった。**0 を返す**ことにした（メッセージ長・型の読み方は未確定）。
- `WAIEVT`/`CHECK` の数値は確認できず、`CLR`=0・`NOCLR`=8（共有データ編）、`WAIT`=0・`NOWAIT`=1・`CONFM`=2 だけを扱う。
- `rcv_msg` の msgsz が 8 以上で本体より小さいときは、msgsz までを写す（原文の該当文が途切れていた）。msgsz が 8 未満・型マスクが 0 のときは `ER_PAR`。
- `clr_msg` は先頭から見て、型マスクに合うものを消し、消した型が最後マスクに含まれたら止める（`MM_NULL` は該当を全て、`MM_ALL` は最初の 1 件）。原文は断片的で**要確認**。
- 本体の大きさの範囲は 1〜32、キューの深さは 8（原文に容量の記載なし）。
- 型 6〜23（システム予約）への送信は禁止していない（原文に規定なし）。
- 子の終了通知は G3b で接続した。`MS_EXIT` のみ（`MS_ABORT`・`MS_TERM` は `ter_prc` と異常終了の実装後）。親のキューが満杯のときは通知を**捨てる**（原文は待つかを規定していない可能性があり**要確認**）。
- BTRON3 流の子は `待行程` で回収できない（`-ECHILD`）。同じ子に両方の流儀を使わせない。

## 1.3 同期通信管理（kernel/taskcomm.html）

要求: セマフォ（同期型 `SEM_SYNC`／排他型 `SEM_EXCL`）、イベントフラグ（AND/OR 待ち）、メッセージバッファ（バッファ 0 も可）、ランデブポート（呼出・受付・転送・返答）。待ち時間は `T_NOWAIT`/`T_FOREVER`/正の ms、満了は `ER_NONE`。生成は動的で ID は正の整数。

| API 群 | 既存実装 | 状態 |
|---|---|---|
| `cre_sem` `del_sem` `sig_sem` `wai_sem` | セマフォ（同期型・排他型、FIFO、時間切れ、DELEXIT） | `user/btron/sync.mkn` → 漢令 96〜99（`kernel/proc/sync.mkn`）。ID は 種・世代・枠を含む正の値。排他セマフォは持主の終了で自動的に次へ渡る。試験 `同試` | 実装済・未検証 |
| `cre_flg` `del_flg` `set_flg` `clr_flg` `wai_flg` | イベントフラグ（AND/OR 待ち、NOCLR） | 漢令 100〜104 | 実装済・未検証 |
| `cre_mbf` `del_mbf` `snd_mbf` `rcv_mbf` | メッセージバッファ（総量・最大・環状・待ち） | `user/btron/sync.mkn` → 漢令 105〜108（`kernel/proc/sync2.mkn`）。`bufsz`=0（直接渡し）は `ER_PAR`（未対応） | 部分適合（`bufsz`=0 未対応） |
| `cre_por` `del_por` `cal_por` `acp_por` `fwd_por` `rpl_rdv` | ランデブポート（呼出・受付・返答・転送） | 漢令 109〜111・115〜117。記録 8 件、呼出と返答は 128 B まで。試験 `緩試` | 実装済・未検証 |

**方針メモ**: 核は非プリエンプティブで、ブロックは「状態を変えて `排程` へ」「起床時に再試行」（`design-process-exec.md` §3）。この方式で待ち行列を載せられる。
**G6a の選択（実装依存・解釈）と要確認**（セマフォ・フラグ）:
- ID は `(種<<24) | (世代<<8) | (枠+1)` とした（原文は「正の整数」とだけ規定）。古い ID は世代の違いで `ER_NOEXS`、範囲外・種違いは `ER_ID`。
- 各 16 個まで（`ER_LIMIT`）。セマフォのカウント上限は 65535。待ちの順は FIFO（原文は順序を明記していない）。
- `wai_flg` が条件を満たしたとき、`NOCLR` でなければ**全ビットを 0 に戻す**（一部のビットだけ消すのかは原文で確認できず、**要確認**）。成功時の戻り値はそのときのパターンで、最上位ビットが立つと呼出側の W では負に見える。
- 時間は 25 ms 刻みへ切り上げる。タイマー割込を取れない（EL0 が IRQ 禁止の）間も、漢令の入口と空き待ちで GIC を確認して刻を進める。ただし、**他の行程が漢令を呼ばずに走り続けている間は時間切れが進まない**（先取りを有効にした行程が居る場合を除く）。
- `ER_MINTR`（ハンドラによる中断）は 1.2 のハンドラが無いので返らない。

**G5c の選択（実装依存・解釈）と要確認**（メッセージバッファ・ランデブ）:
- `rcv_mbf` の戻り値は原文が途切れていた。**受け取った大きさ**を返す（µITRON 系の慣例からの推測、**要確認**）。
- `bufsz`=0 の直接渡しは原文の該当文が途切れていたため未対応（`ER_PAR`）。総量は 512 B 以内、1 通の最大は 256 B 以内、各 4 個まで。
- 待たされた側は、空き・到着で起こされると関数をやり直す。そのため、**起こされるたびに時間切れの計測がやり直しになる**（時間切れが延びる方向にずれる）。
- ランデブの呼出側は、転送されても待ちの対象が元のポートのままなので、**転送先のポートを削除しても待ちは起こされない**（元のポートの削除では起こされる）。
- `cal_por` の `T_NOWAIT` は、すぐに受け付けられる保証が無いため `ER_NONE` を返し呼出を取り消す。
- 受付側が返答せずに終了すると、呼出側は待ち続ける（時間切れか削除まで）。

**要確認**: `rcv_mbf` の末尾（原文が途切れた）、`DELEXIT` の扱い、各オブジェクトの数の上限。

## 1.5 メモリ管理（kernel/memory.html）

- 共有・システム塊の戻りアドレスは**窓内の正アドレス**（頁 248〜255 = 0x406F8000〜0x407FFFFF）。原文の「負アドレス」は「原則（CPU 依存でこの限りでない）」なので、行程ごとの窓に共有域を置くこの実装では正アドレスとした。共有塊は全行程に同一 VA・同一物理頁で写像するため、共有の意味（全行程から可・同一内容）は保たれる。

## 1.7 イベント管理（kernel/event.html）

要求: キーボード・ポインティングデバイスの入力を、1 本のシステムキュー内の「イベント」として時系列に保持。型 0–15、優先順位、イベントマスク（外れたものは破棄）、自動キーリピート、キートップコードと文字コード、ポインタは画面座標（原点左上）・絶対/相対動作タイプ・感度（0〜15）・スキャン速度（0〜15）、32 ビット ms タイムスタンプ、ブザー。イベントの型は EV_NULL 0・BUTDWN 1・BUTUP 2・KEYDWN 3・KEYUP 4・AUTKEY 5・DEVICE 6・RSV 7・APPL1〜8（8〜15）。起動直後はキューが空でシステムイベントマスクが 0（イベントは捨てられる）。EV_NULL と EV_AUTKEY はキューに入らず取り出し時に生成される。優先度は APPL1〜4 が最高、次に BUTDWN/BUTUP/KEYDWN/KEYUP、AUTKEY、DEVICE/RSV、APPL5〜8、NULL。

**M7a の選択（実装依存・解釈）**:
- **仮想デバイス**: 実機が無いため、キーボード・ポインティングデバイス・ブザーは核内の状態（前端の模型）として持つ。よって `ER_NODEV`・`ER_BUSY`・`ER_ERDEV`・`ER_IO` は返さず、全 API が通常の引数検査だけで試験できる。`エラーコード` のうち実機に依存するものは原文どおり実装できない。
- **キー状態の更新**: 実ハードウェアの代わりに `put_evt` の `EV_KEYDWN`/`EV_KEYUP`（`EVDATA.key.keytop` の下位 8 ビット）でキー状態（256 ビット）と押頭を更新する。自動リピート（`EV_AUTKEY`）もこれを前提にする。`get_kmp` はこの状態を返す。
- **`EV_NULL`/`EV_AUTKEY` の合成**: `get_evt` の取出し時に、該当イベントが無ければ `EV_NULL` を現在値（時=現在、座=PD 位置、状=メタキー状態）で合成する。`EV_AUTKEY` は自動リピート対象キーが押されていて、かつ `t_mask` で選ばれる中に `EV_AUTKEY` より優先度の高いイベントが無く、押頭から `繰隔`（初回）または `繰間`（以降）以上経っていれば合成する。原文の「優先度の高いイベントが発生していない」は**取出しの対象（`t_mask`）の中で**と読む（実装依存の選択）。
- **`req_evt` の要表**: 行程ごと 1 枠（行程表と同じ 8 行程）。`put_evt` が要表に載っている行程へ `MS_SYS5`（型 10、本体 20 B の EVENT、送り手は呼出側の行程 ID）を送る。行程の終了時に解除する（`起終了`）。同じ行程が再要求すると上書きするため、`ER_LIMIT` は発生しない。
- **誤りの割当**: アドレス不正 → `ER_ADR`（−`EFAULT`）、引数不正 → `ER_PAR`（−`EINVAL`）、隊が満杯 → `ER_NOSPC`（−`ENOSPC`）。`get_evt` の `t_mask` 0 と `opt` 不正は `ER_PAR`、`put_evt` の型 0・5・16 以上と `opt` の余計ビットは `ER_PAR`。
- **イベントタイマー**: タイマー割込ごとに 1 刻（週期 = 周波数/40 で再装填）。よって 1 刻 = 25 ms。`get_etm` は `刻数×1000×週期÷周波数` で ms に直して返す。`las_evt` の最終発生時刻も ms で保持する（型ごと 16 項）。原文の「BUTDWN/BUTUP でポインタ移動もイベントと見なす」「KEYDWN/KEYUP でメタキー状態変化もイベントと見なす」は、実機の入力が無いため該当事象が起きない（原文どおりの対象は `put_evt` だけ）。
- **KeyTab**: 変換表の保存域を固定域に 4352 B 取る。よって `keymax×kctmax` は 2108 項まで（原文の最小保証 2048 項以上は満たす）。それより大きい表は `ER_PAR`。`get_ktb` は表を書いて 648 B を返す。
- **ブザーの種別**: `0xTTTTHHHH` の `TTTT≠0` かつ `HHHH<0`（メロディー）は番号 −1〜−100 だけを妥当とし、それ以外は `ER_PAR`。`TTTT=0` の `0x0000thhh`（t = 100 ms 単位 4 ビット、h = 10 Hz 単位 12 ビット）は常に妥当。`ctl_buz` は種別 `kind` の範囲だけを検査する（値の意味は実機に委ねる）。

**要確認**: 実機の入力（virtio-input 等）を繋いだときの、ドライバと `put_evt` の境界。`EV_DEVICE` の発生源。

**実装の選択（実機が無いための模型）**: 実機（ディスク・コンソール・印刷）を繋がないため、核内に 4 ユニットの模型デバイスを持ち、全 API を試験できるようにした。よって `ER_NODEV`/`ER_ERDEV`/`ER_IO` は返さない（復号できない誤りは試験できないため）。

| ユニット | 種別 | 支数 | 塊長 | 属性 | 特長 |
|---|---|---|---|---|---|
| `rda` | 塊（RAM ディスク） | 3 | 512 B | 0x11 | 書込可。板は核内の緩（支ごと 8 塊） |
| `rom` | 塊（ROM ディスク） | 1 | 512 B | 0x12 | 書禁（`wprt`=1） |
| `con` | 文字（仮想コンソール） | 2 | 1 | 0x8000 | 支ごと 32 B の路。空なら `ER_BUSY` |
| `prn` | 文字（印刷） | 1 | 1 | 0x8000 | 読否（`rea_dev` と `D_READ` オープンが `-`） |

- **論理デバイス名**: ユニット名（最大 8 B、NUL 終端）の**最長前綴り一致**で解決する。残りは支番（1〜3 桁、前 0 なし。1 文字の "0" は可）。支番が支数以上なら `ER_NOEXS`。
- **記述子**: 32 B（在・行程・単位・支番（255=ユニット全体）・開法・排他）。`dd` は記述子番号 + 1 で最大 32。排他（`D_EXCL`/`D_WEXCL`）は同じ扱いで、ユニット単位で重複を検査する。
- **データ入出力**: `size`<0 は `ER_PAR`。`start`<0 は属性データ（16 B、読のみ。`wri_dev` は `ER_PAR`）を指す。`size`=0 は `a_size` に容量・空きを返す。塊型は `size`×塊長 ≤ 4096 かつ `start`+`size` ≤ 塊数（越えれば `ER_PAR`）。文字型は `start`=0 のみ。`D_NOWAIT` でなくても待たない（データ終了通知が無いため、**文書化**）。
- **向きの検査**: `opn_dev` で読否（読で開けない → `ER_DEV`）と書禁（書で開けない → `ER_RONLY`）を検査する。`D_READ` オープンでの `wri_dev` と `D_WRITE` オープンでの `rea_dev` は `ER_DD`（原文の誤り一覧どおり）。
- **アクセスモード**: 登録時に R=W=F=15。`chg_dmd` は利用者レベル 0 のみで `mode` ≤ 0xFFF（`ER_ACCES`/`ER_PAR`）。
- **サスペンド**: 行程ごとに通常・強制の禁止数を器休址に持つ（上限 32767 → `ER_EMFILE`）。`D_CHECK` は通常・強制の数を返す。`D_SUSPEND` は通常なら通常・強制の両方が 0、`D_FORCE` 付きなら強制が 0 でなければ `ER_BUSY`。電源管理が無いので直ちに 0（復帰済み）を返す。行程終了で `器終了` がカウンタを解放し、開いたデバイスを閉じる。


**直接確認で判明**: 論理デバイス名 = ユニット名（種別 "hd"・"fd" など + ユニット "a"〜）+ サブユニット番号（先頭に 0 を付けない 0〜254 の最大 3 桁）で、全体で最大 8 文字。ユニット名の最後は数字でない。サブユニットが無ければユニット名がそのまま論理デバイス名。`error` は opn_dev でドライバが返す詳細エラー（NULL なら格納しない）。デバイスのアクセスモードは R=W=F=15 で登録され、変更は利用者レベル 0 だけ。ファイルシステムとして接続するには F（接続）のアクセス権が要る。

## 1.9 時計管理（kernel/clk.html）

要求: システム時刻は 1985-01-01 00:00 GMT からの 32 ビット秒数。時刻帯（`TIMEZONE`: GMT からのずれ・夏時間フラグ・夏時間補正）。ローカル時刻＝システム時刻−ずれ＋（夏時間時）補正。日時構造体 `DATE_TIM`（年は 1900 起点、曜日 0=日曜 など）。時刻の設定は利用者レベル 0 のみ。

|---|---|---|---|
| `get_tim` | 時刻と時刻帯の取得 | `user/btron/clk.mkn` → 漢令 時刻取 176（PL031 RTC）。時刻帯は設定手段が無く常に 0 | 実装済・未検証 |
