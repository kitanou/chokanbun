# 設計: BTRON3 互換層（EL0 ライブラリ → 既存の漢令）

状態: **設計のみ（未実装）**。親Issue: [#42](https://github.com/kitanou/chokanbun/issues/42)
関連: [btron3-os.md](btron3-os.md)（API 照合）、[abi-aarch64.md](../abi-aarch64.md)（漢令 ABI v0.1）、[design-process-exec.md](../design-process-exec.md)

## 1. 決定事項

| 項目 | 決定 |
|---|---|
| BTRON3 API の提供場所 | **EL0 の互換層ライブラリ**（`user/btron/`）。BTRON3 の関数名・引数・戻り値・`ER_*` を外部仕様として公開する |
| 核の ABI | 既存の漢令（`svc #0`、`x8`=番号）を**核の内部 ABI として維持**し、互換層から呼ぶ |
| 内部と外部の分離 | 互換層は漢令の薄いラッパに留めず、BTRON3 の意味論に必要な状態は**核側に新しい漢令を足して持たせる**（§4） |
| 適合の主張 | 互換層を通した観測可能な動作で判定する。漢令そのものは BTRON3 の適合対象にしない |

## 2. 構成

```
 BTRON3 アプリ（機械漢文）
        │  cre_prc / snd_msg / opn_fil …（BTRON3 の名称・規約）
 ┌──────▼───────────────────────────┐
 │ L2 互換層  user/btron/*.txt        │  引数変換、エラー変換、構造体の組立て、
 │                                   │  核に無い意味論（※核側に置くもの除く）
 ├──────────────────────────────────┤
 │ L1 民ライブラリ  user/lib.txt      │  奏令（svc 呼出し）と文字列補助（既存）
 ├──────────────────────────────────┤
 │ L0 漢令 ABI v0.1 → 拡張            │  svc #0。核の内部 ABI
 └──────────────────────────────────┘
```

- **公開シンボル**: `記號` による ASCII シンボル（`外術 … 記號「svc_call」` の既存の仕組み）で `cre_prc` のような名前を出す。機械漢文側の関数名は漢字（例: `生子行程`）のまま、`記號` で BTRON3 名を付ける。
- **ファイル配置**: 章ごとに分け、各プログラムは必要な章だけ `@取込` する。

  | ファイル | 内容 |
  |---|---|
  | `user/btron/er.txt` | `ER_*` 定数、漢令 errno → `ER_*` 変換 |
  | `user/btron/types.txt` | 基本データタイプ、`P_STATE` 等の構造体のオフセット定数 |
  | `user/btron/proc.txt` | 1.1 |
  | `user/btron/msg.txt` / `sync.txt` / `gname.txt` | 1.2 / 1.3 / 1.4 |
  | `user/btron/mem.txt` / `file.txt` / `evt.txt` / `dev.txt` / `clk.txt` / `sys.txt` | 1.5〜1.10 |

- **像の大きさの制約**: 漢像の最大は 64 KiB（`像最大`）で、静的取込みなので互換層全体を各プログラムに入れられない。章ごとの取込みで抑え、将来は未使用関数の除去を検討する。

## 3. 呼出し規約

| 観点 | 設計 |
|---|---|
| 引数・戻り値 | 互換層の公開関数は AAPCS64（`x0`–`x7`）。漢令へは `奏令(番, 引0…引5)` で渡す（最大 6 引数。それを超える API は構造体にまとめて渡す） |
| 戻り値の符号 | 成功は 0 または正値、失敗は負の `ER_*`。**数値は原文で確認してから固定する**（未確認）。変換は `er.txt` の 1 か所 |
| ポインタ引数 | 核は EL0 から読める範囲（民の窓）に収まるか検査する（既存）。長さの上限は現在 4 KiB（`令長限`） |
| 構造体引数 | `P_USER`、`MESSAGE`、`TIMEZONE`、`DATE_TIM` など。**核側の構造体複製検査が必要**（ロードマップ M4 の未完項目「漢令の構造体引数の複製検査」が前提になる） |
| 型の幅 | BTRON3 の基本データタイプ（共有データ編 第1章）の幅・符号を確認してから `types.txt` に固定する（未確認） |
| 待ち時間 | BTRON3 は ms 系、漢令は刻数。換算係数を `clk.txt` に置く。係数の取り方（`CNTFRQ` を核が公開するか固定値か）は要決定 |
| スレッド安全 | 互換層は状態を持たない関数を原則とする。状態は核（または行程ごとの民領域）に置く |

## 4. 実現方式の分類

BTRON3 の各 API を、互換層だけでできるか、核の拡張が要るかで 4 種に分ける。

| 種別 | 意味 | 例 |
|---|---|---|
| **A 写像のみ** | 既存の漢令に引数・戻り値を写すだけ | `get_tid`→`識別`、`dly_tsk`→`待機`/`譲渡`、`ext_prc`→`終行程` の一部、`mbk_sts`→`頁残` の一部 |
| **B 写像＋漢令の拡張** | 既存の漢令に引数や機能を足す | `cre_prc`（優先度・初期メッセージ）、`opn_fil`（モード）、`cls_fil` |
| **C 新しい漢令** | 核が新しい状態や待ち行列を持つ | メッセージ（1.2）、同期通信（1.3）、グローバル名（1.4）、`ter_prc`、`chg_pri`、時計（1.9） |
| **D 民側のみ** | 核を呼ばずに実装できる | `malloc` 系ライブラリ（ただし下に `get_mbk` が要る）、`DATE_TIM` 変換の純計算部分 |

### 4.1 新しい漢令の番号の割当

既存は 1〜31（19–20・22–23 は予約、31 は診断）。互換層向けに次の帯を**予約する**（番号は案。確定は実装時に `abi-aarch64.md` に記載する）。

| 帯 | 用途 |
|---|---|
| 64–79 | 行程・タスク（1.1） |
| 80–95 | メッセージ（1.2） |
| 96–111 | 同期通信（1.3） |
| 112–119 | グローバル名（1.4） |
| 120–127 | メモリ（1.5） |
| 128–159 | ファイル（1.6） |
| 160–175 | イベント／デバイス（1.7・1.8） |
| 176–191 | 時計／システム（1.9・1.10） |

BTRON3 の 1 API が 1 漢令に対応するとは限らない。核の都合で粒度を変えてよい（互換層が吸収する）。

### 4.2 設計上の要点（意味論のずれ）

1. **行程終了の通知**: BTRON3 は終了時に親へ**メッセージ**（正常／異常／強制）を送る。現状は `待行程` で回収する方式（ゾンビ状態あり）。
   - 方針: 核の行程表項に「BTRON 流」フラグを持たせ、このフラグの行程は終了時に親のキューへメッセージを積んで**枠を即解放**する（ゾンビを作らない）。
   - 従来の `生行程`/`待行程` は殻などのために残す（二つの流儀が併存する）。同じ子に両方を使うことは禁止し、混在時は `ER_PAR` 相当で拒否する。
   - 前提: メッセージ管理（1.2）が先。`cre_prc` の適合は 1.2 の実装後。
2. **ハンドラ（`def_msg`/`def_exc`）**: EL0 への非同期上り呼びが要る。核が EL0 の保存フレームに差し込む方式（ハンドラのエントリへ `ELR` を向け、復帰用のスタブへ戻す）を採る。`ret_msg`/`ret_exc` はこのスタブから呼ぶ漢令。入れ子禁止は核が保持する。
3. **ファイルのリンク（`LINK`）**: `cre_prc` や `opn_fil` は名前でなく `LINK` を取る。当面は互換層が「典籍名＋接続名」の構造体として `LINK` を表現し、`get_lnk` が典籍名へ解決する。ファイル ID・レコード構造は篇藏との分離設計（1.6）の後に拡張する。
4. **待ち時間の意味**: `T_NOWAIT`/`T_FOREVER`/正の ms を互換層が刻に換算して漢令へ渡す。タイムアウトの `ER_NONE` と中断の `ER_MINTR` は核が区別して返す。
5. **優先度**: 群 A（0–127、厳密）／B・C（128–255、配分）のスケジューラは核側の作業。それまでは優先度を保持だけして無視するか、`chg_pri` を `ER_PAR` で拒否するかを**段階ごとに選び、選択を適合表に記録**する。
6. **副タスク**: 当面は未対応とし、`cre_tsk` 系は `非適合／未対応` として理由を記録する。行程内の複数実行文脈は将来の別設計。
7. **利用者情報・レベル**: 行程表に利用者名・グループ・レベルを足す。初期行程の値は核が設定する。ファイルのアクセス判定（1.6）と時計設定の権限（1.9）に使う。

## 5. 段階計画

各段階は「実装・試験・適合表の更新」までを完了条件とする。

| 段階 | 内容 | 前提 | 完了条件 |
|---|---|---|---|
| G0 **（完了）** | `er.txt`/`types.txt` を原文確認のうえ確定。互換層のビルド経路（`@取込`、`記號` の公開）を `get_tid` 1 本で通す | なし | 試験 `識試`（`user/btron_gtid.txt`）が QEMU で通る。型の幅は確定。**`ER_*` の数値は規範に無く、実装依存の選択として記録**（`er.txt` 冒頭） |

> G0 で分かったこと: (1) ASCII 名の識別子は `「」` で囲む必要があり、定数参照も `「ER_PAR」` と書く。(2) `負`・`項`・`真` などは予約語で変数名に使えない。(3) `@取込` は最初のファイルのあるディレクトリが基準なので、`btron/*.txt` は `註 @取込 btron/er.txt` と書き、依存する `lib.txt` を先に取り込む。(4) 殻は終了コード 0 の外部命令の `殻碼` を出さない。
| G1 **（完了）** | 1.4 グローバル名（C 種）。漢令 112–114、名前は TC 配列の先頭 8 文字、表 16 件 | 構造体でなく文字列と整数のみ。引数検査は既存の窓検査 | `cre_nam`/`del_nam`/`get_nam` の正常系・各 `ER_*`・`DELEXIT` の試験 |
| G2 **（完了・範囲を調整）** | 構造体の複製検査の共通部品（漢令 複写出 177）と 1.9 時計の取得系 `get_tim`/`get_tod`（漢令 176）。`set_tim`/`set_tod` は利用者レベルが入る G4 まで保留 | G0 | 試験 `時試` 11 項目（暦・閏年・ER_ADR）が QEMU で通る |
| G3 | 1.2 メッセージ、`ext_prc`/`cre_prc` の BTRON 流 | G0・G2 | 終了コードがメッセージで親に届く。ゾンビが残らない。混在拒否の試験 |
| G4 | 1.1 の残り（`ter_prc`、`prc_sts`、利用者情報）、1.3 同期通信 | G3 | 各 API の試験。優先度の段階の選択を記録 |
| G5 | 1.5 メモリ、1.6 ファイル（篇藏との分離設計を先に完了） | G2 | 設計レビューの後に API 単位で試験 |
| G6 | 1.7/1.8/1.10 | virtio-input などの入力経路 | GUI 側（第2・3章）と同時に計画 |

## 6. 試験の方針

- 互換層の各関数ごとに、`tests/` に QEMU 上のプログラムを置き、`tests/run_tests.sh` から実行して出力を比較する（既存の流儀）。
- 試験項目は「正常系」「各 `ER_*` を返す条件」「境界値」を最低限とし、結果を `btron3-conformance.md` の根拠として記録する。
- 互換層だけでなく**核の拡張にも漢令単位の試験**を置く（互換層のバグと切り分けるため）。

## 7. 未決事項

- 互換層を **C ヘッダ**としても提供するか（BTRON3 アプリは C 向け）。C の処理系を入れるかは別判断。当面は機械漢文側の宣言だけを提供する。
- `ER_*` の数値、基本データタイプの幅、`T_FOREVER` 等の定数値の確認（原文）。
- 刻数→ms の換算係数の持ち方。
- 副タスクを将来サポートするか。
- 静的取込みによる像の大きさ。分割または動的リンクの要否。
