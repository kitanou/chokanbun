# BTRON3 OS 仕様編 第3章 3.1 ウィンドウマネージャ — 要求の整理（F7）

> 出典: BTRON3 仕様書 Ver. 3.20.00 第2編 第3章 3.1（`os_spec/shell/window.html`、51 関数）。更新: 2026-10-30。
> 状況: **第 1 段階と属性の読み書きを実装済**（`user/btron/wnd.mkn`、31 関数）。標準形状の図（border・fixed_win・reshape_win・frame_cont・active_process）は確認済。`EX_*` の数値は原文に無いので `er.mkn` の選択（`EX_WND`・`EX_WPRC` を追加）に従う。

## 1. 位置づけ

ウィンドウマネージャは**ウィンドウ枠（タイトル・スクロールバー・ハンドル）の表示と管理だけ**を行い、内部の表示は各アプリケーションが自分で描く。描画環境はウィンドウマネージャが用意する。隠れた部分のイメージは**保存しない**のが原則（再表示要求イベントで描き直す）。管理する画面は、最下部のシステムメッセージパネルを除いた部分（フルスクリーンでは全部）。

## 2. ウィンドウの種類・状態・前後関係

| 種類 | 役割 | 備考 |
|---|---|---|
| 通常（主） | アプリの中心となるウィンドウ | 親子関係の木を作る。入力受付状態になれるのは主ウィンドウだけ |
| 通常（従属） | 主ウィンドウの補助 | 常に主ウィンドウの前面。主が入力不可になると**不可視** |
| 前面 | フロントエンド用 | 常に最前面。全主ウィンドウに共有される従属ウィンドウ |
| パネル | ダイアローグのパネル | 枠は描かない（存在の管理だけ）。入力受付状態を横取りして占有。移動・変形不可 |
| 内部 | 描画環境をウィンドウとして扱う擬似ウィンドウ | 枠・領域管理・入力状態なし。使える関数は `wcls_wnd`・`wget_gid`・`wset_dat`・`wget_dat` だけ |

- 入力受付状態は主ウィンドウ間で 1 つだけ。新しく開いた主ウィンドウが入力受付状態になり、元のウィンドウは入力不可になって管理プロセスに `EV_INACT` が届く。
- 前後（最前面から）: 前面 → パネル（開いた順）→ 入力受付の従属 → 入力受付の主 → 入力不可の主。従属・前面どうしは、開いた・移動/変形したものが最前面になる。
- 親子: 主ウィンドウは親と「生成元」（親ウィンドウ内の相対矩形）を持つ。閉じると入力受付状態が親へ移り（親が無ければ直前の入力受付状態へ、さかのぼる）、子の親・生成元は閉じたものの親・生成元に付け替える。
- モード: 主ウィンドウは通常／全面（`wchg_wnd`）。全面中に移動・変形すると通常に戻る。フルスクリーンは別（`WA_SFULL`）。

## 3. 外観と属性

- 枠は右下に影のある境界線、最上部にタイトルバー（ピクトグラム＋タイトル）。変形可能なら四隅がハンドル、右・下（3 方向なら左）の枠にスクロールバー。入力受付状態は枠を灰色パターンで埋め、不可状態は白く。**具体的な形は図 47〜52（原文の図）**。
- 属性（`wopn_wnd` の `attr`、生成後は変えられない）: `WA_FRONT` 0x1・`WA_SUBW` 0x2・`WA_SIZE` 0x4・`WA_HHDL` 0x8・`WA_VHDL` 0x10・`WA_RBAR` 0x20・`WA_BBAR` 0x40・`WA_LBAR` 0x80・`WA_TITL` 0x100（1 でタイトルバー**無**）・`WA_BGDSP` 0x200・`WA_FULL` 0x400・`WA_SFULL` 0x800・座標指定 `WA_STD` 0／`WA_WORK` 0x1000／`WA_FRAME` 0x2000・`WA_FMOVE` 0x4000・`WA_NORMAL` 0x7C。
- 表示属性 `WDDISP`: frame（境界線幅/パターン番号）・tlbg・barpat・barbg・tlcol（`wopn_wnd` では「指定は意味を持たない」）。

## 4. データ・定数（3.1.3）

- イベント: `SEVENT`（切換）・`REVENT`（要求）・`GEVENT`（一般）・`WEVENT`（共用体、生イベント `EVENT` を含む）。型 `EV_SWITCH` 8・`EV_REQUEST` 9・`EV_MENU` 10・`EV_RSWITCH` 16・`EV_INACT` 17・`EV_MSG` 18・`EV_NOMSG` 19。
- 位置コード: `W_WORK` 0・`W_FRAM` 1・`W_PICT` 2・`W_TITL` 3・`W_LTHD`〜`W_RBHD` 4〜7・`W_RBAR` 8・`W_BBAR` 9・`W_LBAR` 10。コマンド `W_SWITCH` 128・`W_CLOSED` 129。
- 要求: `W_REDISP` 0・`W_PASTE` 1・`W_DELETE` 2・`W_FINISH` 3・`W_OPENED` 5、応答 `W_ACK` 0x40・`W_NAK` 0x80。
- 取得モード: `WAIT` 0・`NOWAIT` 1・`NOMSG` 0x10・`RAWEVT` 0x20・`DRGEVT` 0x30。`CLR` 0・`NOCLR` 8。`W_NORM` 0・`W_FULL` 1。`W_MOVE` 0・`W_MOVEC` 1・`W_HOLD` 2。
- `WDSTAT`: attr・parent・pid・r（絶対）・wr（作業領域、相対）・org。PD の操作: `W_PRESS` 0・`W_QPRESS` 1・`W_CLICK` 2・`W_DCLICK` 3。
- **`EX_*`（`EX_WID`・`EX_WND`・`EX_WPRC` など）の数値は 3.1 のページに無い**。別の章（拡張エラー）で確認が要る。

## 6. 実装の方針（案）

1. **状態の置き場**: 複数の行程が見る表が要る。共有画面の塊（2 MiB、画面は 307200 B）の後ろの部分（例: 先頭から 512 KiB 以降）に、ウィンドウ管理表（最大 16〜32 枚）を置けば、核の変更なしに行程間で共有できる（画面共有の第 1 段階の仕組みを使う）。排他は後の課題（今は行程が 1 つずつ動くと仮定）。
2. **枠の描画**: 標準形（境界線・影・タイトルバー・灰色パターンの枠）を `dp.mkn` の描画関数と `dpchr.mkn` の文字で描く。外観は図の確認後に決める。
3. **見える領域**: ウィンドウの矩形を前後関係の順に引き算して矩形の列にする（隠れた部分は描かない）。`wsta_dsp`〜`wend_dsp` はその列を描画環境のクリップとして渡す。
4. **イベント**: 1.7 のイベント（PD ボタン・キー）を、`wfnd_wnd` で位置コード（`W_WORK`・`W_TITL` など）に直して `WEVENT` で返す。
5. **試験**: screendump で枠の画素を調べる（`gpu_boot` と同じ方法）。

## 8. 第 1 段階の実装（`user/btron/wnd.mkn`、試験は `描試` の 9 項目）

- **関数**: `wopn_wnd`・`wcls_wnd`・`wmov_wnd`・`wswi_wnd`・`wget_sts`・`wset_tit`・`wget_tit`・`wfnd_wnd`・`wget_act`・`wget_gid`。
- **状態**: 共有画面の塊（漢令 234）の 0x80000 以降の表（16 枚、1 枚 256 B）。行程をまたいで見える。
- **形状**（図から）: 黒 2 ピクセルの境界線、右と下に 2 ピクセルの影、最上部のタイトルバー（8×8 のピクトグラムの箱とタイトル、下に作業領域の境界線）。作業領域は外枠から左右下 3・上 13（タイトル無しは 3）の内側。入力受付状態の枠は灰色、不可状態は白。`WA_STD` は `WA_FRAME` と同じ外枠座標として扱う（仮）。
- **動作**: 開くと入力受付状態になり最前面へ（従属・前面は入力受付を変えない）。入力受付でない主ウィンドウの移動は `EX_WND`。閉じると従属を連鎖して閉じ、子の親を付け替え、入力受付は親（なければ最前の主）へ移る。`CLR` は影を含む範囲を背景色で消す。`wfnd_wnd` は前後の順に探し、`W_WORK`・`W_PICT`・`W_TITL`・`W_FRAM` を返す（従属は入力受付の主のものだけ見える）。`wget_gid` は作業領域の左上を原点にした `SCREEN` の環境（行程ごとに 1 つ覚える）。
- **属性（第 2 弾、`描試` 5 項目）**: `wget_dat`・`wset_dat`（記録 +192）、`wget_bar`（スクロールバーは無いので 0）、`wget_wrk`・`wset_wrk`（作業領域の左上の相対座標を +216/+224 に保持し、描画環境のビットマップ境界・フレーム・表示長方形も移す。`wget_gid` も同じ原点で作る）、`wget_org`・`wset_org`（主ウィンドウだけ。親 +32、生成元 +208。親が 0 か自分なら無くす）、`wlst_wnd`（0 = 全て、負 = 行程、正 = 子。個数を返し、size を超える分は書かない）。
- **再表示（第 3 弾、`描試` 5 項目）**: `wchk_dsp`・`wsta_dsp`・`wend_dsp`・`wreq_dsp`。隠れたイメージを保存しない代わりに、開く・前面へ出す・動かす・閉じるとき、作業領域のうち描き直しが要る部分を窓ごとに 1 つの外接矩形として覚える（+232 領域・+240 状態・+248 再表示中に増えた領域）。動かす・閉じるときは、元の枠と影に重なる他の窓の作業領域が対象。`wsta_dsp` は相対座標の外接矩形と個数（0 か 1）を返し、再表示中の新たな要求は `wend_dsp` が 1 を返して次の再表示になる。`RLIST` の構造が未確認なので `rlst` には書かない。再表示要求イベントの送出（待ち受け）は未対応。
- **イベント（第 4 弾、`描試` 5 項目）**: `wget_evt`・`wugt_evt`・`wpas_evt`。管理するウィンドウを持つ行程が 1.7 の `get_evt` で取り出し、PD の押下・離しは位置にあるウィンドウの相対座標にして `data` を `cmd | wid << 16`（`SEVENT` の並び）にする。入力受付状態でない主ウィンドウで PD を押すと `EV_SWITCH` を返して状態を移す（`NOMSG`・`RAWEVT`・`DRGEVT` では移さず `EV_BUTDWN`）。`RAWEVT` は絶対座標のまま `wid` = 0。`wugt_evt` は 16 個まで戻せて、`WAIT`/`NOWAIT` のとき戻した順に先に出る。`WAIT` は待たずに繰り返し取りに行く。フロントエンドプロセス・`EV_MSG`・要求イベントの配送は未対応（`wpas_evt` は常に `EX_ADR`）。
- **変形とドラッグ（第 5 弾、`描試` 5 項目）**: `wrsz_wnd`・`wsta_drg`・`wend_drg`・`wget_drg`・`wmov_drg`・`wrsz_drg`。`wrsz_wnd` は外枠の絶対座標を受け（4 隅のどれかが現在と一致しないと `EX_PAR`、最小は外枠で 7 × 15）、描画環境のフレームを新しい大きさにし、相対座標が変わらないようビットマップ境界を作業領域の左上の移動だけ動かす。他の窓と自分に再表示領域を設定して 1 を返す。ドラッグ状態は管理表の頭（行程・対象・描画環境）で、二重開始は `EX_DRAG`。`wmov_drg`・`wrsz_drg` は契機のイベント（`EV_BUTDWN`・`EV_SWITCH`・`EV_RSWITCH`、位置コード 1・4〜7、`wrsz_drg` は 4〜7 だけ）を調べ、`BUTUP` までイベントを読んで（キーは捨てる）、離した位置との差で動かす・変形する（`limit` は最小・最大の大きさ）。影の描画・シフトでの拘束・システムメッセージパネルでの取り消し・ポインタ形状は未対応。
- **ハンドル（第 6 弾、`描試` 3 項目）**: 変形可（`WA_SIZE`・`WA_HHDL`・`WA_VHDL` が全て 1）の窓の枠の 4 隅（角から 10 ピクセル以内。タイトルバーの上は除く）を `wfnd_wnd`・`wget_evt` が `W_LTHD`〜`W_RBHD`（4〜7）で返し、枠の帯を横切る黒い印を描く。変形不可の窓の隅は `W_FRAM` のまま。
- **未対応**: 隠れたイメージの保存と再表示要求イベント（移動・削除のあと、重なっていた他ウィンドウの**作業領域は描き直されない**。枠は前後の順に描き直す）、描画のクリップ（重なった部分への描画を防がない）、ハンドルとスクロールバー、パネル・内部ウィンドウ、全面モード、再描画（`wsta_dsp` 以下）・ドラッグ・イベント（`wget_evt` 以下）、メニュー。
- **言語の注意**: `且`・`或` は短絡しないので、`且` の後ろで NULL や 0 番の記録を読む式は、`若` を入れ子にして守る（この実装で 2 度踏んだ）。
