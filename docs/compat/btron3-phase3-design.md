## B5・B6: パネルの中のパーツ（PARTS_ITEM）と標準パネル

### 今の作り

- パネル（`panel.mkn`）の項目は NULL_ITEM・TEXT_ITEM（と ACT_ITEM を重ねたボタン）だけ。PARTS_ITEM（7）は EX_PAR。
- パーツ（`parts.mkn`）はウィンドウに属し、表示は `wget_gid(wid)` の描画環境に描く（記録の +24 が所属ウィンドウ）。テキストボックス（TB）は `cact_par`・`cexe_par` でキー入力を受け、`ccut_txt`・`cins_txt` で中身を読み書きできる。
- 試験では `事置`（`BTRON事生`）で入力イベントを先に積んでおき、`pact_pnl` に処理させる（描試の `pact_pnl` の項目）。

### 決めること

1. **パネルに属するパーツ**: パーツの記録の所属を「パネル」も取れるようにする。所属が負なら `-(パネルの描画環境 gid)` とし、表示はその描画環境に直接描く（仮身の登録で描画環境を `-gid` で表すのと同じ形）。座標はパネルの描画環境の座標（パネルの左上が原点、`pget_gid` と同じ）。
2. **`pcre_pnl` の PARTS_ITEM**: 項目の ptr は PARTS（`ccre_par` の引数と同じ並び）を指す。パネルを作るときにパーツを作り、項目の desc にパーツ ID を入れる（`pget_itm` が返す）。`pdel_pnl` はパーツも消す。原文の「デフォールトスイッチより小さい番号の PARTS_ITEM は EX_PAR」も守る。
3. **`pact_pnl` とパーツ**: 原文の (1)〜(6) のとおり、最小番号のボックスを入力状態にし、パーツ上のイベントは `cact_par` に渡す。ボックスがタブ・入力終・改行で終わったら `cact_par` の値を返し、改行ではデフォールトスイッチを次の呼び出しで動かす（itemno は負）。
4. **標準パネル（実身／仮身マネージャが出すもの）**: 次の 3 つの形に分けて、`omgr` 側から使う。見た目（項目の配置・文言）は実装依存として A に記録する。
   - **名前入力パネル**: 見出し（TEXT_ITEM）・テキストボックス（PARTS_ITEM）・「確定」「取消」（ACT_ITEM）。保存先指定（`ocre_obj` の名前が空・NULL、`ocre_chd`）、名前変更（`ochg_nam` の NULL、`oexe_vmn` の Name）、新版作成（`onew_obj`）。取消は EX_PAR（原文の「取り消された」）。
   - **選択パネル**: 見出しと選択パーツ（SS）と「確定」「取消」。続柄変更（`ochg_rel` の index < 0、`oexe_vmn` の Relation）、ウィンドウ背景色変更（`achg_bgc`、マスク 0〜7 と色）。
   - **確認パネル**: 文言（TEXT_ITEM）と「確定」（と「取消」）。ディスク状態（`odsk_inf`）、デバイス接続（`oatt_vob` の取り消し 0）、エラー（`odel_obj` など）。
5. **パネルを出す行程**: パネルは呼び出した行程の画面に出す（パネルマネージャは共有画面に描く）。入力は呼び出した行程のイベントを使う。

### 試験

- 描試: PARTS_ITEM を持つパネルを作り、文字キーと改行を積んで `pact_pnl` を回し、テキストボックスの中身と itemno・戻り値を確かめる。
- 実試: `ochg_nam(vid, NULL)` の前に文字キーと「確定」の押下を積み、実身名が変わること。「取消」の押下なら EX_PAR で名前が変わらないこと。続柄・新版・保存先も同じ形で 1 つずつ。

### 順番

1. パネルに属するパーツ（`parts.mkn` の所属の拡張）→ 2. PARTS_ITEM（`pcre_pnl`・`pget_itm`・`pdel_pnl`）→ 3. `pact_pnl` のボックス入力 → 4. 名前入力パネル（`ochg_nam`・`oexe_vmn` の Name・`onew_obj`・`ocre_obj`・`ocre_chd`）→ 5. 選択パネル → 6. 確認パネル。各段で PR を分ける。

## B3: 開いた仮身の表示エリア（M_DISPREQ・M_TADREQ）

### 今の作り

- 描画環境の表（`DP表`、0x407F2000、16 件）は行程ごとの番地にあり、`DP環検` は他の行程の環境を 0 にする。
- 共有塊（`M_COMMON`）は全行程で同じ仮想アドレスに張られる（登録簿が使っている）。
- `oend_req` の結果は登録簿のヘッダを通して起動元へ返せる（`oput_dat` で使用済み）。起動メッセージは本体の先頭の語が型になる（M_DISPREQ は 0x11 = 17、M_TADREQ は 0x14 = 20）。

### 決めること

1. **共有描画環境**: ビットマップを共有塊に置いたメモリ描画環境を、行程をまたいで使えるようにする。描画環境の ID を 17〜32 に分け、その記録は共有画面の塊の表に置く（`DP環検` は 17 以上ならその表を見る）。作るのは `gopn_mem` に「共有」の印を足した内部関数（公開 API は変えない）。閉じるのは作った行程。
2. **`odsp_vob` の V_DISPALL**: 開いた仮身（表示エリアがある）なら、表示エリアの大きさの共有描画環境を作り、背景色で塗って、既定アプリを M_DISPREQ（gid・bgcol を含む）で起動する。`oend_req` を待ち（`oput_dat` と同じ待ち方）、終わったら共有環境の中身を仮身の表示エリアへ写す（`gcop_bmp`）。アプリが無い・失敗したときは V_DISP と同じ（背景色で塗る）。
3. **`otad_vob`**: 開いた仮身は M_TADREQ で既定アプリに TAD を作らせ（一時ファイル）、仮身セグメントのあとに図形として取り込む。エラーなら M_DISPREQ の画像を TAD の画像セグメントにする（原文の手順どおり）。
4. **アプリ側**: `objapp`（試験用アプリ）に M_DISPREQ を足す: `wopn_iwd(gid)` で内部ウィンドウを開き、表示エリアに決まった模様を描いて `oend_req`。

### 試験

- 実試: 開いた仮身（高さ > タイトル）を V_DISPALL で表示し、表示エリアに objapp の模様が写ること。アプリの無い仮身では背景色だけになること。

### 順番

1. 共有描画環境（`dp.mkn`）→ 2. `odsp_vob` の V_DISPALL と objapp → 3. `otad_vob` の M_TADREQ。

## 残りのその他

- **B4 の残り**: 5/6（虚身ウィンドウ）は、ウィンドウの生成元の仮身が虚身になったときにそのウィンドウへ送る（ウィンドウの記録に生成元の仮身 ID を持たせる）。16（デバイス仮身の挿入）は C6 のデバイス仮身と、17（新規実身への保存）・128（一時ファイルへの格納）はパネル（B5）とあわせる。
- **C4**: `apnl_men` の画面メニューは `msel_men` を使う。試験ではポインタの位置を決める仕組み（PD の位置を設定する核の呼び出し）が要るので、その有無を先に調べる。
- **C6**: デバイス番号から論理デバイス名を引く表（デバイス管理 1.8 の情報から作る）と、デバイス仮身（ファイルシステムの根を指す仮身）を `oprc_dev`・`ofmt_vob` で扱う。
