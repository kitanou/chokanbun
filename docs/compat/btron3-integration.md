## 1. 独自 ISA・機械漢文 CPU 構想との境界

### 1.1 三つの層

| 層 | 中身 | 何が決めるか | 適合の判定 |
|---|---|---|---|
| **B: BTRON3 の外部仕様** | 関数名・引数の意味・戻り値・`ER_*` の名前と発生条件、構造体の欄と並び、定数の値、メッセージの型と中身、TAD・TRON コード（`TC`）、実身／仮身の意味、画面の操作の意味 | BTRON3 仕様書 Ver.3.20.00 | **対象**。互換層（L2、`user/btron/`）を通して観測できる動作で判定する |
| **I: 原文が実装に任せる値** | `ER_*` の数値、`T_VER` の各欄（`cpu`=1 を AArch64 に割り当て）、`get_cnf` の項目名と値（`PGSZ`=4096 など）、メモリの番地の正負と配置、`F_SYSTEM` の写像先の番地、待ち時間の刻と ms の換算、実行プログラムレコード（種別 9）のサブタイプのうち原文に無い CPU 種別、画面デザイン（[btron3-phase3-gap.md](btron3-phase3-gap.md) の A） | この OS の選択。選んだ値は適合性マトリクスと各設計書に**実装依存として記録**する | 原文が任せる範囲に収まっているかを判定する（値そのものは問わない） |
| **K: 超漢文独自の部分** | 機械漢文の言語、漢令（`svc #0`・`x8`=番号・負の errno）、漢令の番号帯、核内表の番地（0x403Exxxx）、民の窓（0x40600000〜）、AArch64 の例外・MMU・頁表、篇藏、漢殻、POSIX サブセット、独自機械漢文 CPU（R1、Issue #26） | 超漢文の設計（[abi-aarch64.md](../abi-aarch64.md)、[language-spec.md](../language-spec.md)） | **対象外**。BTRON3 の規範として扱わない。変えても BTRON3 の適合には影響しない（B の動作が変わらない限り） |

規則:

1. **BTRON3 の適合は B だけで主張する。** 漢令・ISA・機械漢文の言語仕様を「BTRON3 準拠」とは書かない。逆に、BTRON3 の規範を ISA や漢令の仕様として書かない（`ER_*` を漢令の戻り値の規約にしない。漢令は負の errno を返し、互換層の `er.mkn` 1 か所で `ER_*` に変える）。
2. **I の値は 1 か所に置く。** 互換層の定数（`user/btron/types.mkn`・`er.mkn`・`sys.mkn`）か核の表に置き、試験はその定数で照合する。値を変えたら適合性マトリクスの注記も変える。
3. **独自 CPU（R1）への移植は K と I だけを差し替える。** B の動作は変えない。互換層の機械漢文ソース（L2）は ISA に依存しない形で書き、ISA に依存する部分（`奏令` による `svc`、レジスタの渡し方、番地の定数）は L1 の `user/lib.mkn` と核に閉じ込める。
4. **R1 が成熟するまで実行基盤を切り替えない**（[roadmap.md](../roadmap.md) R1）。BTRON3 の適合作業（Phase 5）は AArch64/QEMU virt の上で進め、独自 CPU の作業はその完了を条件にしない。

### 1.2 ISA が外部仕様に漏れる箇所

ISA に依存しないのが原則だが、次の箇所は CPU を変えると B から見える値が変わる。どれも原文が実装に任せる範囲（I）で、移植時に選び直して記録する。

| 箇所 | 今の選択（AArch64） | 移植時にすること |
|---|---|---|
| `T_VER.cpu`（`get_ver`） | 1 | 独自 CPU に別の値を割り当て、`sys.mkn` の `VER_*` を変える |
| 実行プログラムレコードのサブタイプ（種別 9。原文は TRONCHIP・68000・NS32000・x86・V シリーズの帯だけを定める） | 未使用（§2 の X2 で決める） | CPU ごとに原文の帯と重ならない値を割り当てる |
| `get_cnf` の `PGSZ` | 4096（AArch64 の 4 KiB 頁） | 新しい頁の大きさにする |
| ポインタの幅（`VP`・`FP` など） | 64 ビット。`W` は 32 ビットで、`W` を返す関数は x0 に符号拡張して返す（`types.mkn` 冒頭） | ポインタを含む構造体（`RLIST` の次ポインタ、`BMP` の `baseaddr` など）の並びが変わる。原文は 32 ビットの機械を前提に書かれているため、ポインタの欄の幅は実装依存として扱い、欄の順序は原文どおりにする |
| メモリの番地（`get_mbk` の正負、`F_SYSTEM` の写像先 0xFFFF8000_00000000 + 物理番地） | 正のローカル・共有番地、負のシステム空間 | 新しい番地空間に合わせる。試験 `録試` の `F_SYSTEM` の項目は上位 32 ビットが 0xFFFF8000 であることを見ているので、移植時に変える（実装依存の期待値） |
| 時間の単位（`get_inf` の stime、待ち時間） | 汎用タイマー（`CNTVCT`・`CNTFRQ`）から ms に換算 | 新しい計時の仕組みで ms を作る。BTRON3 から見える単位（ms）は変えない |

### 1.3 試験の置き場所

- 互換層の試験（`tests/run_tests.sh` の 17 種・750 項目）は BTRON3 の名前で互換層を呼ぶ。準備や照合のために `奏令` で漢令を直接呼ぶ箇所（篇藏の準備、行程の起動など）があるが、それは K の層の操作で、判定は互換層の戻り値で行う。
- 漢令単位の試験（核の拡張の切り分け用）は K の試験で、BTRON3 の適合の根拠にしない。
- 独自 CPU の適合試験（R1 の「機械漢文アセンブラと適合試験」）は ISA の適合を見るもので、BTRON3 の試験とは別に置く。同じ互換層の試験が独自 CPU の上でも通ることを、移植の完了条件にする。

### 2.2 残る衝突

各行の「移行手順」は、既存の利用者（漢殻・典籍・篇藏の像・POSIX の命令）を壊さない順に書く。

| # | BTRON3 の要求 | 既存の設計 | 決定 | 移行手順 | 確認 |
|---|---|---|---|---|---|
| X1 | 子の終了は親へのメッセージ（`MS_EXIT` など）で通知し、枠を残さない | `生行程`/`待行程` によるゾンビ方式（漢殻・POSIX の `wait` が使う） | **二つの流儀を併存させる**。BTRON 流で作った子（漢令 64・70）は終了時にメッセージを積んで枠を即解放し、`待行程` の対象にしない（`-ECHILD`）。同じ子に両方は使えない | (1) 済: 行程表項の BTRON 流フラグ。(2) 済: `cre_prc` で起動した子は `MS_EXIT`。(3) 今後: 新しいアプリは `cre_prc` だけを使う。漢殻と POSIX 命令は `生行程`/`待行程` のまま | `信試`・`強試`（終了通知と枠）、`待行程` の既存試験 |

### 2.3 漢令の番号帯について

[btron3-file-design.md](btron3-file-design.md) §8 と [btron3-compat-layer.md](btron3-compat-layer.md) §4.1 の番号帯は、実装前の案で、互いに食い違う。**確定した番号は [abi-aarch64.md](../abi-aarch64.md) の漢令表が正**で、この 2 つは履歴として残す。漢令の番号は K の層なので、BTRON3 の適合には関係しない。
