# 起動仕様（起動方式・EL・メモリ配置・DTB の受け渡し・制御移譲）

[roadmap.md](roadmap.md) F9 の「起動方式、EL、メモリ配置、DTB受け渡し、制御移譲の仕様を固定」。現在の実装（QEMU `virt`、`-kernel` に ELF を渡す）を仕様として固定し、将来の独立したブートローダーが満たすべき契約を決める。実機は当面対象外（[roadmap.md](roadmap.md) F8）。

## 1. 起動方式

- ブートローダー（今は QEMU の `-kernel`）は、核の ELF（`tests/output/kernel.elf`）の各セグメントを `p_paddr` の物理アドレスへ置き、`e_entry`（`_start`）へ分岐する。核は自分でディスクから読み込まない。
- 核の ELF は物理 0x40000000 から始まる 1 つのイメージで、`.text.boot`（`_start`）が先頭にある。

## 2. 入口の契約（`_start` に入る時点）

| 項目 | 内容 |
|---|---|
| CPU | 1 つ（ブートプロセッサ）。他の CPU は起こさない（QEMU は `-smp 1`） |
| 例外レベル | **EL1 または EL2**。EL2 なら `降位()` で EL1（AArch64）へ降りる。EL3・EL0 は未対応で、`wfe` で止まる |
| MMU・キャッシュ | MMU は切、命令・データキャッシュは不問（核が `SCTLR_EL1` で設定する） |
| 割込 | DAIF は全マスク（降位後も `SPSR_EL2 = 0x3c5` で全マスク） |
| x0 | **DTB の物理アドレス**（FDT。先頭 4 バイトが 0xD00DFEED のビッグエンディアン）。QEMU の `-kernel` ELF では物理 0 番地 |
| x1〜x3 | 未定義（使わない） |
| スタック | 無い。核が `_stack_top` を SP に設定する |

## 3. EL2 から EL1 への降下（`降位`）

型付き機械命令 `降位()` が、`CurrentEL` が 1 なら何もせず、2 なら次の順に EL1 へ `eret` する（`x0` は壊さない。作業は `x16`）。

1. `HCR_EL2.RW = 1`（EL1 は AArch64）
2. `CNTHCTL_EL2 = 3`・`CNTVOFF_EL2 = 0`（EL1 から物理・仮想タイマーを使える）
3. `SPSR_EL2 = 0x3c5`（EL1h、DAIF マスク）、`ELR_EL2` = 直後の命令
4. `eret`

`CurrentEL` が 1・2 のどちらでもなければ `wfe` の無限ループで止まる。QEMU では `-machine virt,virtualization=on` で EL2 開始を試験できる（`樹 EL 0x…1` が出る）。

## 4. メモリ配置（QEMU virt）

| 範囲 | 内容 |
|---|---|
| 0x00000000–0x3FFFFFFF | デバイス（MMIO。EL1 のみ。最初の 1 GiB を Device 塊で恒等写像）。DTB（QEMU では 0 番地） |
| 0x40000000–0x401FFFFF | 核のコード・rodata（EL1 RO+X、EL0 RO+X＝漢像のコードも同じ塊）。入口と例外ベクタ（2 KiB 整列） |
| 0x40200000–0x403FFFFF | データ・`.bss`・行程の核棧・核の固定表（EL1 RW のみ） |
| 0x40400000–0x405FFFFF | 篇・標・索の表、機器表（0x40420100）、頁池のビットマップ（0x40421000）（EL1 RW） |
| 0x40600000–0x407FFFFF | 民の窓（仮想。行程ごとに別の物理頁。EL0） |
| 0x40800000–RAM の終わり | 動的頁域（頁池）。大きさは RAM に追従（上限 64 MiB、下限 16 MiB、2 MiB 単位） |

RAM は基底 0x40000000・24 MiB 以上でなければならない。満たさなければ `核恐慌 記憶不足` で止まる。

## 5. DTB の受け渡しと核の出力

- 核は MMU を切ったまま DTB を読む（物理 0 番地は MMU 後には写像されないので、`早起動` が読み終える）。
- 読み取り結果は機器表（物理 0x40420100）に置く。RAM の基底と大きさ、UART・GICD・GICC・RTC・virtio-mmio の基底、タイマーの割込 ID、virtio-mmio の枠の数と間隔、頁池の大きさ。形式は `kernel/proc/fdt.mkn` の冒頭を参照。
- DTB が無い・壊れている・想定外の形（`#address-cells`/`#size-cells` が 2 でない、機器の欠落、番地が最初の 1 GiB の外）なら、QEMU virt の固定値を使い `樹 有効` を 0 にして起動する。

## 6. 制御の移譲

`_start`（`降位` → `棧置` → 呼出 `早起動`）→ `早起動`（`.bss` を零、DTB を機器表へ、VBAR_EL1 を設定）→ `核主`（MMU 有効化、各表の初期化、殻行程の起動）。`核主` は戻らない。殻行程（init 兼）が終わると `核恐慌 init終了` で止まる。

## 7. 独立したブートローダー（設計・未実装）

核とは別のローダーを置く場合の契約は、§2 の入口の契約そのものである。ローダーは、(1) EL を揃えて（§3）、(2) 核のイメージを ELF の `p_paddr` に置き、(3) x0 に DTB の物理アドレスを入れ、(4) 核の `e_entry` へ分岐する。ローダー自身は核の領域（0x40000000〜0x41FFFFFF）と DTB を壊さない高位（例: RAM の末尾近く）に置く。ディスクから核を読む場合は virtio-blk の読み出しだけを持つ小さなドライバが要る（`kernel/proc/blk.mkn` が元になる）。これは未実装。
