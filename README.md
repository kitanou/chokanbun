# 超漢文 OS — ChoKanbun OS

**機械漢文でカーネル内部まで記述する ARM64 ネイティブ OS。**

> 世界安寧

## 目的
- AArch64 (ARMv8-A) を対象とする独立した研究用OSを開発する。
- カーネル、システムコール、メモリ管理、プロセス管理、ドライバ、ユーザーランドを機械漢文で記述する。
- 機械漢文を独立したシステムプログラミング言語として定義し、LLVM IR経由でARM64機械語へコンパイルする。
- POSIX互換性は段階的に実装する。

## 開発方針
- 最初の実行環境: QEMU `virt` / AArch64。
- 最初の到達点: 機械漢文で記述したベアメタルプログラムがUARTへ「世界安寧」を出力する。
- ブート初期化などは当面最小限のAArch64アセンブリを許容し、後に低水準機械漢文構文へ移行する。
- コンパイラのブートストラップ実装には既存言語を許容する。カーネル本体は機械漢文を原則とする。
- `machine-kanbun` とは独立して仕様・実装・Issueを管理する。

## ビルドとテスト

```sh
make          # コンパイラ (chokanbun) をビルド
make test     # 全テストを実行 (IR生成 → AArch64オブジェクト → ELFリンク → QEMU)
make run      # 漢極カーネル (kernel/) をQEMU上で実行
make clean
```

LLVM ツールは既定で `/opt/homebrew/opt/llvm/bin` と `/opt/homebrew/opt/lld/bin`
を参照する。`LLVM_BIN` / `LLD_BIN` で上書きできる。

`make test` は `tests/run_tests.sh` を呼び出し、以下を検証する:

1. `hello` — 機械漢文 → LLVM IR → AArch64オブジェクト（逆アセンブル確認）
2. `uart` — `取址`/`長度` と `外術曰` 呼び出し → ELF リンク（C 版 UART スタブと結合）
3. `uart_mmio` — **機械漢文のみで記述した PL011 ドライバ**（`險`/`項`/`讀揮發`/`寫揮發`）→ ELF リンク
4. `kernel` — `kernel/` の漢極（例外ベクタ・例外ハンドラ・MMU・物理ページ割当・GIC/タイマー・EL0/SVC 境界）→ ELF リンク（`_vectors` の 2KiB 整列も検証）
5. `type_error` — 型不一致の診断（`E00xx`）が出ること
6. `qemu` — QEMU `virt` 上で機械漢文ドライバが PL011 に **世界安寧** を出力すること
7. `kernel qemu` — QEMU `virt,gic-version=2` 上で漢極が **超漢文起動**・**異常捕獲（BRK 診断）**・**記憶管理有効（MMU）**・**物理ページ割当**・**タイマー割込（GICv2）**・**EL0 行程の漢令呼出・協調切替・行程ごとのアドレス空間・境界検査・タイマー横取り（プリエンプション）** を出力すること

## 開発状況
Phase 0 完了。機械漢文コンパイラがビルド・テスト可能で、
QEMU `virt` / AArch64 上で機械漢文ソース由来のコードが UART に「世界安寧」を
出力する。さらに M2 の一部として、PL011 UART ドライバを機械漢文の
volatile MMIO・生ポインタ添字で記述できる（`tests/uart_mmio.txt`）。

M2 のカーネル基盤として `kernel/` を新設した。漢極本体（`kernel/kernel.txt`）は
機械漢文で記述し、PL011 出力、例外ハンドラ（`brk #0` を捕捉して ESR を復号し
`eret` で継続）、物理ページ割当、レベル1/レベル2 変換表の構築による恒等写像
MMU 有効化、GICv2 の設定と EL1 物理タイマー割込の処理（`GICC_IAR` で要因番号を
取得し、`GICC_EOIR` で完了して `eret` で復帰）を行う。

M3 として EL0 行程、SVC（漢令 ABI v0.1）、複数行程の協調スケジューラ、行程ごとの
アドレス空間を実装した。EL0 で走る民行程（`民務`）が `svc #0` で漢令を発行し、
漢極の `漢令處理` が処理して復歸する。漢令は番号 `x8`・引数 `x0`–`x5`・戻り値 `x0`
（`docs/abi-aarch64.md`）。保存フレーム（`x0`–`x30`・NZCV・`ELR_EL1`・`SPSR_EL1`・
`SP_EL0`）を行程表に持つことで、`譲渡`（番5）と `終行程`（番2）で次の行程へ
協調的に切り替える（ラウンドロビン）。MMU は行程ごとのレベル1/レベル2 表を持ち、
2MiB ブロック単位で EL0/EL1 権限を分ける。核の写像は全行程で共通、民の窓
（仮想 `0x40600000`）だけが行程ごとの物理 2MiB へ写るため、同一の仮想アドレスへの
書き込みが行程間で見えない（切替時に `設台`/`set_ttbr0` で `TTBR0_EL1` を切替）。
漢令のポインタ引数は `漢令處理` が EL0 可読範囲に収まるか検査し、核専用ブロックを
指す範囲は `-EFAULT`、未知の漢令番号は `-ENOSYS` で拒否する。民行程は既定で割込を
マスクして走り、`開先取`（番7）で自分の割込を解禁しタイマーを起動すると、EL0 で
受けたタイマー割込が下位EL IRQ ベクタから `割込切替`（`irq_switch`）に入り、
`排程` を呼んで SVC と同じ枠組みで非協調的に切り替える（`譲渡` なしで横取りされ、
甲が回転中に乙が走り、甲が復歸する）。暫定 AArch64 アセンブリは
スタック設定（`kernel/boot.S`）、例外ベクタ表と
レジスタ保存（`kernel/vectors.S`）、システムレジスタ操作（`kernel/sysreg.S`）、
EL0 遷移と SVC 境界・下位EL IRQ 入口（`kernel/el0.S`）に限定する。`boot/uart.c` の C 版ドライバは
`外術曰` 連携の後方互換・参照用として残している。旧起動スタブ `boot/boot.S` は
Phase 0 の参照用。デマンドページング、行程ごとの核棧、VFS は未実装。
